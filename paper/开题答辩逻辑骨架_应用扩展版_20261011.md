# 毕业开题逻辑骨架：密集目标视频实例分割中的候选竞争、质量校准与时空一致性

日期：2026-10-11

## 一、开题题目与总体判断

### 题目采用

**密集目标视频实例分割中的候选竞争、质量校准与时空一致性研究：从单帧失败机制到个体级跟踪**

副标题：

**密集目标的候选竞争、掩码可恢复性与跨帧身份保持**

### 总科学问题

在密集、接触、遮挡的养殖场视频中，如何让系统同时做到：

1. 单帧上把相邻个体分开；
2. 遮挡和局部可见时保持实例身份；
3. 跨帧输出稳定掩码和连续轨迹；
4. 最终支持计数、占用率、活动轨迹和行为分析。

### 三模块不是三个并列算法，而是三个系统层级

1. **模块一：密集场景数据与失败机制基准**  
   解决“密集场景到底哪里失败、不同数据域是否同一种失败”。
2. **模块二：密集特化的空间实例分割与候选竞争修正**  
   解决“单帧如何减少碎片、合并、邻居误报和 mask 读出失败”。
3. **模块三：视频级时空一致性与养殖应用系统**  
   解决“单帧结果如何跨帧连成稳定个体，并变成可用的监测指标”。

完整链条：

**跨数据集问题基准 → 单帧密集特化分割 → 跨帧身份与应用指标**

## 二、为什么把当前 YOLO-seg 工作放在中间层

当前 YOLO-seg 实验不是毕业课题的全部，而是模块二的机制基础：

- 已经建立 raw 候选、类别分数、Top-K/NMS、最终输出的身份追踪；
- 已证明固定 prototype 下部分 Mask fail 存在有限可恢复系数；
- 已排除多条简单的系数蒸馏、外挂修正和当前信赖域路线；
- 已有选择性 mask 读出校准的历史方法原型；
- 但尚未形成视频轨迹、跨帧身份和养殖应用闭环。

因此开题不要把标题写成“YOLO26-seg 系数优化”，而要把 YOLO-seg 作为**密集场景空间分割引擎和机制实验平台**。

## 三、应用场景要具体到系统输出

最终应用对象采用：

**密集目标视频监测**

系统输入：

- 固定摄像头或移动摄像头连续视频；
- 密集、接触、局部遮挡、光照变化和视角变化目标。

系统输出：

- 每帧猪个体 mask；
- 每个个体的稳定 track ID；
- 个体轨迹、停留区域和可见面积；
- 场景总数与分区占用率；
- 遮挡前后身份恢复；
- 后续事件统计接口。

开题不直接承诺“已经完成行为识别”。行为分类需要独立行为标签；当前可先把它定义成视频实例分割系统的应用出口。

| 层级 | 已有方法能做什么 | 密集视频仍缺什么 |

### 第 6 页：模块一——失败本体分类

统一五类失败：

1. 候选池无合格 mask；
2. 有好框但无好 mask；
3. 有好 mask 但类别或分数不够；
4. 完整候选与局部候选竞争；
5. 最终输出阶段发生丢失、重复或身份冲突。

当前 COCO 机制基准：

- 36,335 GT、30,828,840 raw；
- 同一 raw 同时 Box75+Mask75：23,805；
- 好框但无好 mask：6,688；
- 好 mask 但无好框：487；
- 好框和好 mask 分属不同 raw：531；
- 框和 mask 均无达标候选：4,824。

密集场景旧基准：

- 196 个残余 O 类；
- SPLIT_TYPE 50 个；
- 多预测联合 IoU 中位数增益 0.084，coverage 中位数增益 0.143；
- 这些是描述性诊断，不是全体密集实例的机制结论。

### 第 7 页：模块一——候选生命周期与视频入口

把单帧结果与视频问题接上：

GT identity
  ↓
raw candidate identity
  ↓
final prediction identity
  ↓
frame-level track identity
  ↓
application identity

重点说明：

- 单帧 candidate 丢失会造成 track fragmentation；
- mask 碎片化会造成 IoU 下降和错误关联；
- 邻居误报会造成 ID switch；
- 只看 frame AP 不能解释视频轨迹质量。

模块一输出：

- 跨数据集失败 taxonomy；
- candidate-to-prediction 映射；
- 可用于 tracker 的 mask quality、uncertainty、support 和 neighbor-conflict 特征。

### 第 8 页：模块二——密集特化的空间实例分割

研究问题：

> 在接触和遮挡场景中，如何把完整实例、局部实例、邻居和背景的竞争变成可控的空间修正？

模块二的三个子问题：

1. 候选形成：是否生成了完整实例候选；
2. 候选竞争：完整候选与局部候选如何排序和保留；
3. mask 读出：固定 prototype 下 coefficient 是否能恢复实例边界。

应用目标：

- 降低 merge；
- 降低 fragmentation；
- 减少邻居误报；
- 保持自身覆盖率；
- 为 tracker 输出更稳定的 mask 和置信度。

图：密集猪群中“完整候选—局部候选—邻居候选”的关系图。

### 第 9 页：模块二——当前 YOLO-seg 机制成果

固定 prototype 诊断：

- Mask fail 的定义完备复导可恢复率：4,843/6,456 = 75.02%；
- 原面板记录值：4,263/6,459 = 66.00%，并列披露；
- small/medium/large：72.5% / 72.7% / 91.7%；
- oracle 目标蒸入原生系数分支后，held-out cosine 为 −0.0348 / −0.0324；
- 信赖域 projection retention 0.302，低于随机同规模 0.588。

唯一结论：

**固定 prototype 中存在修复空间，但原生系数预测无法稳定迁移；下一步必须改变表示或监督接口。**

页脚：

GT-oracle 是机制诊断，不是视频部署结果。

### 第 10 页：模块二——密集特化方法路线

把方法设计成三层，而不是一个 gate：

1. **候选竞争层**  
   建模完整候选、局部候选和邻居候选关系；输出 candidate ownership/conflict。
2. **空间读出层**  
   根据 candidate mask quality、coverage、purity 和 support 选择性修正 mask。
3. **低层表示层**  
   对仍不可恢复的实例，引入局部 feature residual 或 prototype residual。

已有 RCMC 读出校准可放在空间读出层作为原型：

- m 模型 43.38→43.94；
- s 模型 39.42→39.90；
- 但该结果来自 4,500 图旧协议，不能与当前 5k 机制线混表。

当前 A/C/F/R smoke 对应低层表示层：

- A native；
- C native coefficient capacity；
- F local feature coefficient residual；
- R local prototype residual。

20k 正式训练前不填 AP。

### 第 11 页：模块三——视频级时空一致性

研究问题：

> 单帧密集分割结果如何跨帧维持同一实例的 mask、位置和身份？

系统结构：

frame t
  ↓
spatial masks + candidate quality + neighbor conflict
  ↓
motion/appearance/mask association
  ↓
temporal memory
  ↓
frame t+1 mask refinement and ID recovery

三类时序机制：

1. **身份关联**：bbox、mask IoU、外观和邻居关系联合匹配；
2. **时序掩码修正**：用前后帧高置信 mask 约束当前帧；
3. **遮挡恢复**：短时间不可见时保留 track memory，重新出现后恢复 ID。

注意：

- 当前仓库没有视频 track ID 的正式 Run；
- 因此这一页写方法框架和待验证问题，不写视频效果数字。

### 第 12 页：模块三——视频评价指标

视频模块不能只报 Mask AP，必须新增：

| 层级 | 指标 |
|---|---|
| 单帧质量 | Mask AP、AP75、Mask IoU、coverage、purity |
| 轨迹质量 | HOTA、IDF1、MOTA、ID switches |
| 时序稳定 | track fragmentation、短轨迹比例、temporal mask IoU、warp consistency |
| 密集专项 | merge/split 率、遮挡前后 ID 恢复率、邻居交换率 |
| 应用输出 | 计数 MAE、占用率误差、轨迹连续率；行为事件指标需另有标签 |
| 工程代价 | FPS、端到端延迟、显存、跨帧缓存大小 |

最小视频验证动作：

**冻结一套带 track ID 的短视频确认集，跑原生 YOLO-seg + ByteTrack/BoT-SORT 基线，先测 HOTA、IDF1、ID switch、fragmentation 和 temporal mask IoU。**

这一步是视频模块的唯一阻塞变量消除动作。

### 第 13 页：模块三——视频方法对照

固定四臂：

- V0：原生单帧 YOLO-seg + 基线 tracker；
- V1：加入模块二的密集特化空间修正；
- V2：V1 + mask-aware association；
- V3：V2 + temporal memory / occlusion recovery。

对照原则：

- 所有方法使用相同视频、相同 detector 输出预算和相同 tracker 基线；
- 单帧 AP 与视频轨迹指标分开报告；
- 不允许通过调低 confidence 牺牲 precision 换取虚假的轨迹连续；
- 记录新增缓存、延迟和掉帧。

### 第 14 页：跨数据集与跨场景验证

验证顺序：

1. COCO：验证机制和空间修正；
2. 现有动物密集目标数据：验证跨数据域单帧能力；
3. 外部连续视频确认集：验证轨迹与应用指标；
4. 第二类密集目标数据域：验证方法是否依赖首个验证域。

跨架构验证暂不作为第一阶段硬门槛。先把 YOLO-seg 体系跑通，再补第二架构。

### 第 15 页：完整研究计划与门槛

阶段一：模块一

- 冻结三数据集协议；
- 统一 raw→final→track 身份；
- 完成失败 taxonomy 和密集专项切片。

阶段二：模块二

- 完成 candidate competition、readout calibration、A/C/F/R 20k；
- 以正常 AP、Mask75 修复/损伤、密集专项指标和成本决定是否保留。

阶段三：模块三

- 建立视频 track ID 确认集；
- V0–V3 成对比较；
- 通过轨迹门槛后再做计数/占用率/行为接口。

模块二放行门槛：

- R−A ≥ 0.3 AP 点且 bootstrap 下界 > 0；
- R−F ≥ 0.1 AP 点且 bootstrap 下界 > 0；
- baseline-success 损伤率上界 ≤ 1%。

模块三放行门槛：

- HOTA、IDF1 和 fragmentation 至少有一项达到预注册改善；
- ID switch 不增加超过护栏；
- temporal mask IoU 不低于单帧修正基线；
- 端到端 FPS 达到应用设备预算。

### 第 16 页：毕业论文贡献与推翻条件

预期贡献固定为三条：

1. 建立跨数据集、跨阶段的密集实例分割失败账本；
2. 证明固定 prototype 下存在可恢复 mask 空间，并把候选竞争、读出和表示可达性区分开；
3. 构建面向视频的密集特化分割—跟踪—应用闭环，验证空间修正能否转化为时空收益。

推翻条件固定为：

- 若模块二在 20k 和独立数据上未超过普通基线，停止当前空间修正扩展；
- 若模块三只提升单帧 AP、不提升 HOTA/IDF1 或反而增加 ID switch，停止把该修正用于视频；
- 若模块三无法建立可靠 track ID 确认集，论文暂时收口为“密集场景单帧机制与校准”，不虚构视频结论。

## 六、答辩主回答

如果问“为什么从 YOLO-seg 做到视频”：

> 单帧实例分割是视频系统的空间底座。密集目标中的 mask 合并、碎片和邻居竞争会直接造成 ID switch 和轨迹中断，所以先用 YOLO-seg 把空间失败机制拆开，再把 mask quality、候选竞争和不确定性传给 tracker，最后验证是否改善时空指标。

如果问“视频是不是另起炉灶”：

> 不是。模块一建立候选与失败身份，模块二修正单帧空间结果，模块三复用这些身份、mask quality 和邻居关系做跨帧关联；三模块共享同一实例身份账本。

如果问“目前视频结果在哪里”：

> 目前未知，阻塞在带 track ID 的视频确认集和基线 tracker Run；最小动作是冻结短视频确认集，完成原生 YOLO-seg 加 ByteTrack 或 BoT-SORT 的 HOTA、IDF1、ID switch、fragmentation 和 temporal mask IoU 基线。

如果问“第三模块失败怎么办”：
