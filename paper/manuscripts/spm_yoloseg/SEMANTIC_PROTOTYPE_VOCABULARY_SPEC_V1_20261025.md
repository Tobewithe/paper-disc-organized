# 语义明确、多条目激活的对象原型词表：规格V1

2026-10-25。用户进一步明确：词表中的每个向量对应可辨认的对象或模式，覆盖不同姿态的猪体部位、完整身体、遮挡和边界；一次可以调用多个条目，激活必须与输入相关，例如站立猪应优先匹配站立整体。

**规格状态：设计草案，尚未实现、未冻结数值训练合同、未启动本版训练。** 本文细化先前[内容审查](PROTOTYPE_MEMORY_CONTENT_REVIEW_20261025.md)与[编码解码审查](PART_WHOLE_AUTOENCODER_REVIEW_20261025.md)中未明确的词条语义和匹配要求。它不追改V17/V18/V19已冻结协议、Run或科学结论。

## 1. 本次目标定义

建立一个带明确语义身份的可学习向量词表。一个条目对应一个声明清楚的对象/概念模式，能够独立检索、显示和核验。输入先编码成相应类型的查询，再调用多个相容条目，保留每项的编号、含义、权重、位置和当前实例归属，供后续整体组合与掩码推断使用。

用户提出的“完全解耦”在本规格中落实为：**语义身份明确、对无关变化保持适当稳定、可独立调用、与其他条目的作用可区分。** 部位、姿态、整体和遮挡存在真实联系，不要求它们在数据分布上互相统计独立。向量正交、不同编号、不同解码图或标签名称，本身都不能证明语义专一；高维向量仍可能携带未声明信息，需要用可追溯匹配与受控变化检验。

## 2. 词条类型与含义示例

下表是目标语义示例，不是当前已训练条目，也不是已冻结的完整部位/姿态清单。

| 类型 | 示例条目 | 语义职责 |
|---|---|---|
| 整体 | 站立猪整体、腹卧猪整体、侧卧猪整体 | 一种明确姿态/形态的完整对象模式及其允许变化 |
| 部位 | 站立前肢、侧卧前肢、某视角鼻部或耳部 | 有定位依据的局部部位及声明清楚的姿态/观察条件 |
| 遮挡关系 | 猪遮挡猪、栏杆遮挡躯干的条件模式 | 两侧区域及前后关系，区分实际可见部分与整体假设 |
| 边界关系 | 猪体—地面轮廓、猪体—邻猪接触边界 | 边界两侧角色、连续性、局部配置与上下文关系 |
| 拒绝/其他 | 不受当前对象词表支持的输入 | 允许背景、严重模糊和不明确输入不强行调用猪体概念 |

每条保存候选字段：`token_id / type / semantic_label / part_id / pose_condition / view_condition / relation_roles / variant_id / embedding / canonical_reference / evidence_sources / supported_conditions`。维数与预设容量见2.1，字段实现尚待工程设计；容量是本版设计起点，不是实测最优值。

同一宽泛部位可以具有多个有区分依据的观察变体，并通过共同的部位身份关联。光照、随机噪声和场景背景主要作为观察条件变化，不为每一种随机组合枚举一个永久词条。

### 2.1 首版容量：512条，每条128维

**本版选定总容量512，四类分库，嵌入维数统一为128；用户已确认作为初版预设，后续再优化。** 这是用于准备数据、接口与语义清单的工程预设，尚未成为启动训练的冻结合同；目前没有证明512优于其他容量的本项目实验。

| 词表 | 预设容量 | 分配依据与内容 |
|---|---:|---|
| 部位 | 256 | 以现有8组粗部位为起点，每组预留32条，覆盖有依据的姿态、观察方向与局部形态模式；部位需要承担细粒度定位，分配最大容量 |
| 整体 | 128 | 站立、腹卧、左侧卧、右侧卧4个主姿态组各预留32条，表达各组内的身体配置、可辨形态和观察变体 |
| 遮挡关系 | 64 | 表达目标与邻猪、栏杆及经训练来源核实的设施等遮挡关系，保留前后顺序、受影响部位与可见性配置 |
| 边界关系 | 64 | 表达猪体与背景、邻猪、遮挡物的局部边界模式，记录两侧归属、方向、曲率及细窄结构等属性 |
| **总计** | **512** | **四类词条分别检索，身份及调用位置保留到读出阶段** |

128维是每个词条的特征长度，512是词条数量，两者职责不同。词表矩阵共65,536个标量，FP32约256KiB，仅计算嵌入本身，不包括查询编码器、解码器、元数据或优化器状态。单条128维向量通过带类型的规范解码器与参考条件展示其内容，不直接将128个数解释为可见部位图。

**容量分配与已有标签的边界：**

- 现有[V5资产定义](OBJECT_PROTOTYPE_DESIGN_V5_20261023.md)的8组是头、颈、前躯干、后躯干和四条腿。鼻、左右耳和尾目前没有本规格要求的独立监督；要启用相应细部词条，先补可追溯标签，并在256条部位预算内重新分配，必要时另版扩容。头与鼻等父子部位可有层级关系，不伪装成互斥分区。
- 既有[V0姿态配置](../../../experiments/spm_object_prototype_20261023/CONFIG_V0.json)使用standing、walking、feeding、prone、lateral_left、lateral_right。walking、feeding是行为/配置属性，可能与站立同时成立，不能直接当作与站立互斥的三个姿态真值。新清单以实际几何/核实标签确定主姿态，行走和低头采食等作为组内配置；未覆盖的过渡状态保留未知，不硬塞标签。旧Run的六种配置及判定不改。
- “每组32条”是容量预算，不能仅给同一部位Mask监督就声称获得32种已解耦语义。每个启用条目还须绑定可辨的条件/形态模式、规范参考和多个来源样本，区分依据要登记；若没有足够依据，槽位保留未启用，不用随机背景、颜色或噪声凑满。局部确实不能区分整体姿态时，允许条目的支持条件覆盖多个姿态，由实例上下文约束匹配。
- 各类共享128维长度，不表示四类距离或权重天然可比较。按类型建立查询和排序监督；拒绝匹配通过独立置信/拒绝机制处理，不额外算作第513个对象词条，也不强迫背景分到512条中。

首轮容量保持上述512上限。是否扩到更大词表，以训练来源与独立开发对象上的语义覆盖、组内检索、词条重复及未被表达的形态模式共同判断：只有现有相关词条已被正确使用、仍有明确不同模式被挤在一起，才有扩容依据。若再次集中调用少量相同条目，先检查语义绑定、训练覆盖和查询分配；增加空槽位不能作为解决办法。扩容或重分配在下一版合同登记，不运行后改当前Run。

## 3. 查询、排序与多条激活

1. **按当前实例查询。** 当前检测及空间支持确定查询对象；一张图中站立猪和卧猪分别具有自己的查询与状态。同一原型可以被多个实例分别调用。
2. **按语义类型比较。** 整体证据查询整体词条，部位证据查询部位词条，双侧/邻域证据查询边界及遮挡关系；最终融合时保留各自身份。一次调用多条不是让它们在一个全局softmax里争抢唯一名额。
3. **在可比较候选内要求正确排序。** 对姿态可辨、标注为站立的实例，站立整体应高于腹卧、侧卧等不相容整体；前肢局部应优先匹配相容的前肢条目。可以由多个相容变体共同表达当前对象。
4. **整体与部位相互校验。** 同一实例的整体姿态约束部位配置；部位位置、方向和形态共同支持相容整体。鼻部局部未必含有足够身体姿态证据，不强迫每个局部都独立猜出整体姿态。
5. **边界/遮挡按当前关系判断。** “猪遮挡猪”必须结合目标、邻居及相对位置；单个纹理块不能被事后命名为确定的前后关系。
6. **输出置信度与不确定性。** 证据不足时保留候选或拒绝匹配；不能通过强制选择站立标签制造看似正确的激活。

站立整体在整体姿态组中最高，是用户要求的具体正确性目标。鼻部或清晰边界可能在各自组中获得更高置信度；异类组的原始余弦值或softmax权重没有天然可比性，需要分别监督和校准。

**首版稀疏调用预设：** 每个实例的整体查询Top-2；每个可见部位查询Top-2；每个边界局部查询和遮挡关系局部查询分别Top-2。整体和部位需要结合预测的相容条件排序；推理不能使用GT姿态筛候选。8组部位都可辨时，整体与部位合计最多先调用18个条目引用，边界/遮挡另按实际局部数量调用；跨位置可重复引用同一词条，引用数不等于不同词条数。遮挡部位可由上下文提出假设，但需与直接可见匹配及其置信度分别记录。证据不足可以少选或拒绝；姿态有歧义时保留不确定性，不把强制选满当作正确。最终计算预算与数值验收仍需在正式Run前冻结。

## 4. 训练应直接约束什么

| 约束 | 正向要求 | 必须考虑的反例 |
|---|---|---|
| 词条语义绑定 | 部位、整体姿态、边界/遮挡关系由合法标签及样本对应建立 | 只给条目取名称，训练却只优化重建，不检查语义 |
| 组内排序 | 相容词条比同组不相容候选得分高 | 模型依靠地面、光照或渲染来源判断姿态 |
| 跨观察对应 | 同一语义在不同外观/光照下仍匹配相容条目；几何变化按已知对应处理 | 把同一身体点的姿态变化错误压成完全相同图像表示 |
| 单条目规范解码 | 在声明清楚的参考条件下能展示对应部位、整体或关系模式 | 解码器或未声明输入代替词条完成了全部工作 |
| 部位—整体关系 | 来自同一实例的相容部位支持整体，并被整体布局约束 | 将甲的头和乙的腿组合成一头猪 |
| 拒绝与置信度 | 背景或不确定输入获得低相关性或拒绝 | 每个输入都被强制分到某个猪体概念 |

这些是训练目标的职责，不是已定损失函数、权重或超参数。可采用概念监督、匹配/排序约束、对应和规范重建共同实现；多项监督同时改变时，只能先评价完整方案，不能声称某一项的独立因果效应。

合成资产可提供可追溯部位ID、姿态、实例ID、深度和前后顺序；其中部位名称来自资产/人工定义，不宣称是自主发现。真实标注缺少相关属性时，保留未知或另作人工核验，不将猜测当真值。光照、材质、高频成像与遮挡的变化范围沿用真实训练来源指导的要求。

**2026-10-25用户进一步确定的数据与任务训练范围：** 密集主样本要求同画面至少15头实际拥挤互遮，身体与不同部位交错；原型预训练时即通过实例解码器联合学习检测和实例分割。具体数据配额、遮挡群验收、同实例框/Mask监督及无GT推理路径见[密集数据与任务预训练规格V1](DENSE_TASK_PRETRAINING_SPEC_V1_20261025.md)。512条容量预设不变，语义/规范内容与直接任务监督共同保留；该规格尚未实现或启动训练。

## 5. 怎样验收“输入匹配正确”

- **单词条语义证据卡：** 语义声明、多个训练来源依据、未参与构库样本的实际命中、真实作用区域、规范解码与易混淆反例。
- **排序正确性：** 在有合法姿态/部位标注的对象上，记录组内Top-1、相容词条召回、错姿态激活和混淆；完整来源分组报告，不只挑成功示例。
- **多词条相容性：** 记录一次实际调用的条目及空间/实例归属，检查它们能否共同解释同一个对象；激活数不作为对象计数。
- **专一性与观察稳定性：** 换背景/光照时保持适当的语义匹配，换姿态时整体与部位条件按预测改变；检查未声明信息是否主导作用。
- **关系语义：** 边界匹配与两侧实例/遮挡角色一起核验，完整形状和可见Mask分别评价。
- **正常任务效用：** 最后仍在无GT推理输入、同配置原生基线上报告框、Mask、原成功损伤及代价；概念正确率不替代正常分割收益。

数值门槛、统计对象与允许不确定的范围须在正式Run前冻结。本次只把“站立应优先匹配站立”明确成监督与验收目标；尚无实测正确率，也不能承诺任意真实输入100%正确。

## 6. 与当前原型实现及文献的关系

当前V17空间字典已有查询、Top-k与加权重建，但没有为全部自由条目建立本规格要求的逐条语义身份、属性匹配与同类型排序验收。V18/V19继承的相关内容和旧结果保留，不因本次重新定义目标而改判。

本规格细化了前一轮“部位—整体原型”的功能要求，采用多词条、带身份的调用记录；是否在某一级加权组合，以及如何保留语义来源，需要与实际解码方式一起确定，不将合并成单向量作为词表的定义。

可借鉴的一手研究：

- [ProtoPNet，NeurIPS 2019](https://proceedings.neurips.cc/paper/2019/file/adf7ee2dcf142b0e11888e72b43fcb75-Paper.pdf)：有训练样本依据的类内原型匹配与类间区别，支持语义绑定的方向，不证明每条仅携带一种信息。
- [Concept Bottleneck Models，ICML 2020](https://proceedings.mlr.press/v119/koh20a.html)：使用训练时给出的高层概念约束中间预测，支持直接监督声明的概念。
- [Concept Embedding Models，NeurIPS 2022](https://proceedings.neurips.cc/paper_files/paper/2022/hash/867c06823281e506e8059f5c13a57f75-Abstract-Conference.html)：高维概念表示可具有可解释职责；其分类和概念干预结果不直接支持本任务的密集分割。
- [Addressing Leakage in Concept Bottleneck Models，NeurIPS 2022](https://proceedings.neurips.cc/paper_files/paper/2022/hash/944ecf65a46feb578a43abfd5cddd960-Abstract-Conference.html)：概念预测仍可能携带影响语义和干预的额外信息，支持独立检查语义，而不是仅凭标签声明“完全解耦”。

本轮补充来源主要核对原始论文摘要/作者发布页及ProtoPNet既有方法阅读，不宣称完成上述概念模型的逐页全文审读，也不将它们包装为本规格已成立的证据。
