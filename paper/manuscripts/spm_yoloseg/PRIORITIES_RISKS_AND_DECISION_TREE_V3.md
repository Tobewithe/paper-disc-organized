## 0. 首要裁决：先识别信息瓶颈，再投入合成与原型

> **当前唯一优先行动仍是 P0 只读审计**：核实真实训练可见实例 Mask、场景/视频分组、模型 checkpoint/Neck 输出/评估版本，并形成最小真实接触边界账本。满足 P0 后，**首个建议的可区分实验是冻结 YOLO P3/P4 特征的接触边界可读性 probe**。这将决定原型的内容设计，但**probe 高分不等于原型会提升 Mask AP，probe 低分也不能数学证明特征中不存在边界信息**。其训练需要另行冻结授权。

核心问题不再泛称「利用真实+合成原型提升实例分割」，细化为：

1. 在真实**同类不同实例**接触处，冻结 YOLO26-Seg Neck P3/P4 是否包含可被有限监督头读取的邻猪分离线索？其信息是否比像素强度梯度/普通前景背景边界有额外价值？
2. 这种线索是否在视角、照明和视频压缩变化下不稳定？**外观知识**（纹理、光照）、**几何知识**（同类实例接触/方向）哪类更值得固化为原型？
3. 真实训练域条件合成与真实高频统计能否改善该不稳定性？相同几何/Mask/训练预算下，是否比普通随机合成和高频扰动有效？
4. 在上述条件下，冻结跨图原型库检索能否**独立地**优于相近容量的无记忆分支与额外训练，而非仅提升平均 AP？

这四个问题是**判别顺序**，并非要求已全部解决才能书写设计，也不预设假说成立。

## 1. 优先级：按「对论文成败的影响 × 可证伪性 × 投入成本」排序

| 事项 | 优先级 | 真正难点 | 最小可行证据 | 不该立即投入的内容 |
|---|---|---|---|---|
| **真实数据分组与 Mask / 错例账本** | P0，前置刚需 | 同视频帧泄漏、漏标与遮挡/接触概念混杂 | train/dev/test 簇与哈希、可见 Mask QA、接触/小目标分母、原生 checkpoint parity | 未统计即先生成上万张 |

| **共享原型发现和语义解释** | 科研核心，第二轮 | 域特定纹理捷径、频繁模式掩盖接触 token、K/簇坍缩、跨域不对齐 | real/syn token 检索覆盖、原型近邻 exemplar 和来源统计、边界 token 命中率 | 仅优化 K 或展示好看的聚类热图 |

**精力规划建议（非 GPU 配额或验证事实）**：跨域原型+同类接触表征约 40%；几何/标注可靠的合成约 25%；高频/真实成像域适配约 20%；YOLO 工程/评价约 15%。每项的正式训练资源需从低成本判别结果重新规划。

## 2. 为什么「前景 vs 背景」原型不足以支撑同类实例分割机制

原前景/背景二分库只需要区分 \`pig\` 与 \`background\`。在猪-猪接触边，两侧同为 \`pig\`，两位置很可能检索到相同的外观中心。此时原型记忆能否分离实例，取决于**是否存在可稳定查询的局部几何/边界/上下文线索**，以及融合器是否使用它，而非取决于原型数量。

需在设计中区分**用于标注/评估的位置类型**与**自动发现的原型语义**：
- A：猪体内部，远离任一可见边界；
- B：猪与背景接壤，可见实例/背景边界；
- C：猪与另一头猪接壤，两个不同可见实例 ID 的边界；
- D：不可靠/三叉边界/孔洞/严重模糊，进入 ignore 或单独统计。

这 **不是**事前硬编码「头/腿/背/接触」四组可训练语义原型；最初只用它们衡量 frozen feature 是否包含信息。若 C 原型支持率极低，可以考虑**按位置困难程度重采 token**，或（需另立预算/监督对照）加入空间几何关系，而不是事后将簇强行命名「接触原型」。

## 3. 三项相互独立的研究贡献候选与否决逻辑

### H1：真实条件 Blender 几何补充真实的困难样本
预测：相同渲染预算、相机/密度分层信息及模型预算下，真实 train 条件场景在真实开发集，尤其密集接触子集，比物理合理但无条件的 Blender 随机采样稳定改善。

- **反证/替代**：收益可能来自接触样本比例较高。需要报告密集/接触 bin 条件分布，并增设匹配难例比例的随机化对照。
- **失败出口**：优先修正合成可见标签/姿态/密度覆盖；如果 QA 合格且无额外效用，不将场景约束作为主创新。

### H2：类别条件真实频率统计补足合成域外观
预测：V3（train-real 条件高频）优于同几何 V2（普通强高频扰动）；若 V3 包含相机模拟，追加 HF-only vs camera-only vs combined 才能归因 HF 本身。

- **高风险**：最终 640 入网时细皮纹可能被 PSF、视频压缩和下采样淹没；仅看 patch PSD 收敛不能代替真实检测收益。
- **失败出口**：若 V2 与 V3 同效或 V3 跨相机损伤，转用更廉价 V2/物理相机管线，不强行保留「真实高频」论文核心。

### H3：局部原型记忆提供可重复的跨域接触边界信息
预测：在同样真实/合成图、原生 Mask 监督与训练步数的 B* 上，FSPM 相比等容量无记忆 G 和 B* continued 有用，且破坏原型 key-value 对应/空间匹配会定向损伤真实接触子集。

- **不充分证据**：P3 probe 能读出 C 线索、聚类有可解释 patch、或者 F 比 B* 好，单独都不构成 H3 证明。
- **失败出口**：若 probe 指出难以稳定读取 C 线索，优先比较更高分辨率特征/明确局部几何 cue 的表示，暂停大容量记忆；若 F≈G 或置换无效，停止宣称「冻结记忆独立增益」。

## 4. 分阶段判别路线及变更点

**S0（仍属 P0 的诊断准备）：** 数据来源与权限、真实 train/dev/test 分簇、可见 Mask 质量、模型代码/权重/输入/原生分割输出 audit；生成**真实错误账本**：密集程度、GT 级别猪-猪 contact pair、像素局部边界类型、实例尺度、固定预测身份漏检/黏连/分裂。不能把 synthetic amodal 遮挡比例当作真实可见 Mask 的固有属性。

**S1（P0 通过后，首个建议实验）：** 在同一 frozen pretrained checkpoint 上，针对真实 train 标注做 P3/P4 boundary linear/MLP probe，检验 C 与 B/内部的区分，按视频/猪栏 held-out dev 验证。若已有合法 real-only/B* checkpoint，可作为独立配对组补查，不能把不同权重混成同一组。详细合同见 [CONTACT_BOUNDARY_PROBE_DRAFT](../../../experiments/spm_yoloseg_20261021/CONTACT_BOUNDARY_PROBE_DRAFT.md)。

**S2（几何/标注 smoke，并行于 S1 的只读或小规模资产 QA）：** Blender 64–128 场景，核穿模/站立/接触/原生 RLE 可见 Mask 和 amodal；相机投影与真实 train 约束对齐。没过标签 QA 不做纹理增强大规模渲染。

**S3（合成域与频率适配）：** 训练域 patch bank，先 100–200 matched-scene 的 V0、V2、V3 QA，再建议 600 个不同场景的短程原生 YOLO 比较；每组见到**相同几何、相同 RGB 数量、相同 optimizer steps**。若缺少真实训练授权先只做 QA。

**S4（原型可行性）：** 选已验证 B*（允许退回最简单方案），冻结 Backbone/Neck，先测试跨域 P3/P4 对齐、边界 C token 命中/跨 camera 稳定，再动态发现 K 和冻结原型。若边界 C 的可读性明显更好于内部 token，优先调 **困难 token 采样**；若 probe 没有线索则考虑另外的尺度或几何提示机制。

**S5（P3 注入与机制归因）：** zero-alpha/梯度 smoke → B* continued vs G vs FSPM → 置乱/替换 key-value/空间位置的同 checkpoint 干预 → 全量/困难子集 Mask AP 和 FPS 成本；P4 扩展仅在 P3 的真实独立效用被证实后规划。

## 5. 明确风险排序与投入红线

**风险 1（科学根因）：** 真实猪-猪接触本质是同类实例边界，外观记忆可能无法提供独立的实例归属线索。决策必须由 S1/S4 检验而不是预设。  
**风险 2（域差）：** 合成纹理可极像真实，却由于 pose、尺度、接触几何、相机链错误产生负迁移。应先验证 S2，再投入频率逼真化。  
**风险 3（效率与归因）：** 冻结中心库 + Top-k/门控新增延迟，效果可能完全由普通残差或额外训练获得。必须有 G 和同 checkpoint 干预。  
**风险 4（数据可信度）：** 真实可见 Mask 漏标和同一视频泄漏会同时污染 contact probe、真实频谱 bank、原型与最终评价。P0 为刚性前置。  
**风险 5（方法过度复杂）：** 若无阶段性正面证据，不叠加 ViT/扩散真实化、多尺度大库、复杂 domain adversarial、额外 loss 或先训练大量 Blender。

## 6. 工程验收与运行规则

- V3 是**问题/顺序修订**，不是替换现有 V2 算法定义/先前设计记录，未变更 \`study.json\` 中 \`not_started\` 状态、运行许可与旧线总控。
- 启动 S1 或 S3 检测模型正式训练前需冻结：split SHA、model/code/checkpoint SHA、设备/预算/optimizer steps、具体标签/采样定义、预测差异与 CI、正/负/信息不足退出条件。
- **唯一现行动作：** 先 P0 只读审计与真实接触边界账本；P0 满足后首个优先的、需另获训练授权的科学实验是 S1 frozen P3/P4 boundary probe，而不是立刻生成 3,000 张或训练完整原型库。
