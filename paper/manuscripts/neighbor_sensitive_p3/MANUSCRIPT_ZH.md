# 可恢复但未实现：原型式实例分割的掩码质量差距

> 中文镜像稿：与 `main.tex`（投稿稿，Pattern Recognition Letters）逐节同步，数字与披露完全一致。
> 本文件用于内部评审与讨论；**投稿使用英文稿**。作者信息未填。

**摘要**　定位正确的实例仍可能通不过严格的掩码判据。我们追问：这类掩码失败在冻结表示内是否可恢复；若可恢复，原生模型为何没有恢复它们。在完整 COCO val2017 上，我们先跨原始候选几何、类别 argmax 条件与输出保留三层，记账掩码质量的损失位置；随后证明：在项目已记录的有限 oracle 定义下（本文重新推导并独立核验），**严格 argmax 条件掩码失败的 75.0% 存在一个系数修正，可在原型库冻结时达到 Mask75**（原面板部分记录的解码约定下为 66.0%，见第 4.2 节，两值均报告）。七项受控比较排除了通常的解释：oracle 目标监督不会通过原生系数分支迁移到 held-out 候选；受约束功能投影所保留的 oracle 增益低于随机支持对照。瓶颈因此定位在“系数如何被实现”，而非“信息是否存在”。全部读数为单冻结检查点上的诊断，不作任何精度声明。

**关键词**　实例分割 · 错误诊断 · 原型系数 · 掩码质量 · 冻结模型分析

---

## 1. 引言

现代原型式实例分割器用共享原型库加逐实例系数解码掩码 [YOLACT]。候选可以定位良好却仍通不过严格掩码判据。标准聚合精度不说明质量损失的位置，观察到多余前景也不说明它由哪个上游阶段产生。我们把问题分成层：原始候选池里是否存在该能力，语义条件是否保住了它，输出阶段又保留了什么 [TIDE]。

我们的问题更锋利。在类别 argmax 正确且 Box75 正确的实例中，多大比例的掩码失败可以只在冻结原型空间内改变系数向量来修复；若比例很大，原生模型为何没有实现它？我们发现严格总体中 **75.0% 在此意义下可恢复**（原面板记录约定下为 66.0%）。前半是可恢复性事实，后半是排除问题。两者都回答，且答案改变“修复应当作用在哪”。

本文的主张是一种有用的否定：可恢复比例很大，而我们检验的七个候选机制没有一个解释这个差距。朝 oracle 方向的短预算监督不迁移到 held-out 候选；对同一 oracle 方向的受约束功能投影极好地保护了可靠区域，却只保留约三分之一的可得增益，且低于随机支持对照。没有任何一项检验产出可部署方法；每一项都是移除一种解释的受控比较。

## 2. 相关工作

原型—系数解码是既有范式 [YOLACT]；检测与分割的错误分析工具是既有的 [TIDE]；边界细化与质量打分是既有的 [PointRend, BPR, Mask Scoring R-CNN, Mask Transfiner]；实例间的归属与竞争也已被建模 [BCNet]。因此我们不宣称任何结构新颖性。本文的新意在于组合：一个严格的 argmax 条件失败总体、全验证集上的冻结原型可恢复性测量、以及一条共同定位差距的受控排除链。

## 3. 记账：掩码质量损失在哪里

### 3.1 四种评价单位

一个原始候选由图像、分支、金字塔层级、网格位置与输入形状唯一标识。对每个普通 GT 依次问三件事：(i) 是否存在任一原始位置同时达到 Box75 与 Mask75；(ii) 是否存在**预测类别 argmax 与 GT 类相同**的原始位置做到；(iii) 正常输出是否保留了这个好候选。各单位回答不同问题，从不互换。由此得到下文使用的总体：argmax 正确、Box75 正确，但整个 argmax 正确候选集中不存在 Mask75 的实例。

## 4. 冻结原型空间内的可恢复性

### 4.1 Oracle 定义

固定原型库、候选系数、预测框与解码路径。对每个实例，在输入网格的 **GT 框区域**上解

```
Δc*_λ = argmin_Δc  (1/A) Σ_u BCE( p_uᵀ(c0+Δc), y_u ) + (λ/2)‖Δc‖² ,   c* = c0 + Δc*_λ
```

λ 事先固定；式 (1) 是项目已记录的有限 oracle 约定，构造上依赖 GT。当某个 argmax 正确 raw 的 c\* 经官方解码达到 Mask75 时，该实例为**可恢复**。

### 4.2 结果

我们用式 (1) 重新推导了整个面板：letterbox 几何、GT 栅格与解码路径均从保留的逐图记录重建，并以“换初始化独立重解 + 精确重聚合 + 身份交叉核对”核验。**复导份额为 6,456 个实例中的 4,843 个（75.0%）**；表 2 按 GT 尺寸分层，并与原面板记录值并列报告。原面板的求解器不在保留记录内，其解码与 ROI 约定仅部分有记录，因此两个值都报告，任一单独数值都不作为任何主张的唯一基础。3 个 GT（0.05%）的 GT 框在解码网格上退化，记为跳过。差异集中于小实例，与 0.75 判据附近的阈值边界约定效应一致，而非 oracle 族别不同。

一个独立面板复测了同一结构 [B4]。原记录中不可恢复的剩余部分分为“固定原型/解码受限”与“支撑不可行”两类（2,169 与 27），且该记录有 309 行候选存的是支撑上界而非求解值；这些记账事实不改变任一可恢复计数。位置选择不是解释：对拥有多个 argmax 正确 raw 的实例，oracle 最大值相对逐实例中位数平均只高 **1.293 点**（4,504 个多 raw 实例上为 1.854）。无论用哪个约定，可恢复份额都是严格总体的绝对多数，而下文没有任何拟合机制实现它。

## 5. 原生模型为何没有实现它

七项比较各移除一种解释。表 3 汇总，以下逐项给出边界。

**监督量。** 朝 oracle logit 变化加入空间 logit 教师会降低训练目标但不改变输出：相对同预算对照，图片 macro IoU 为 +0.013 点，目标组区间跨零，无额外 Mask75 跨越。

**归属读出与求解器。** 从冻结 neck 特征读取像素归属不胜过同容量对照；外部空间证据经固定求解器回投仍低于原生模型。

**共享末层。** 在冻结特征上重新拟合共享仿射末层回收诊断目标差距的 46.8%；冻结后施加于正常图像，图片 macro Mask IoU 有 +0.055 的自举为正改善，集中于 P4/P5。剩余逐实例 oracle 差距不是任何共享映射能回收的。

**事后全局修正。** 冻结的全局修正器改善图片 macro IoU 0.092 点，CI [+0.022,+0.167]，无可靠 Mask75 变化。

**Oracle 目标蒸馏。** 只微调系数头朝 oracle 派生目标不迁移：held-out 候选上，目标臂与同预算纯 BCE 对照都**逆着** oracle 方向移动（余弦 −0.03；P5 与大目标上 −0.12），修复增益在有/无 oracle 目标时完全相同，且两者都损伤约 7% 的原本正确实例。

**受约束功能投影。** 把 oracle 修正投影到信赖域子空间（按当前掩码不确定性取证据像素、按 margin 取保护像素）可把保护区 logit 改动压到 oracle 自身改动的 6%，但只保留 30% 的 oracle IoU 增益（门槛 80%），且低于同基数随机支持对照（59%）。

**解读。** 差距既不是信息可用性（可恢复份额很大），也不是上述七种机制中的任何一种。它位于实现阶段：原生系数头的函数类（按训练所得）不选择可恢复方向。

## 6. 这一差距对修正类方法的意义

两个独立的边界结果框定修正能买到什么。对已正确定位的预测去除误报像素，在 GT 辅助理想修复下掩码 AP 提高 10.999 点 [A5]；失败率随 GT 前景占比强烈变化（最低与最高占比组间 62.4% vs 10.5% [A6]），这是对象选择信号而非机制。解码级置换不能弥补差距 [A7]。结合第 5 节（表 3），任何修正类方法的价值被定位为：它能删除像素，但不能提供原生头未能实现的系数方向。

## 7. 限制

单检查点、单架构家族；COCO val2017 图像在开发中被反复使用，无结果是盲测；oracle 量为 GT 辅助诊断而非方法性能；候选—GT 关联是诊断性的，不是 COCO 匹配；不作精度声明。可恢复性测量的确切目标与投影审计的 margin 已在项目记录中冻结并如引。跨模型泛化性未检验。

## 8. 结论

原型式分割器中的掩码质量失败，很大一部分在其自身冻结表示内可恢复，而原生预测没有实现它们。本文的排除链把问题从“是否存在信息”转向“系数必须如何被实现”，并为下一次方法尝试给出了具体目标与一组必须胜过的受控比较。
