# 毕业开题汇报逻辑骨架（2026-10-11）

## 一、开题采用的唯一主线

**题目采用：面向实例分割的掩码失效可恢复性诊断、选择性读出校准与表示适配研究。**

总科学问题：

> 现有实例分割模型的掩码失败，究竟发生在候选生成、候选保留还是固定原型下的系数读出？其中有多少失败在现有表示空间内可恢复，如何把可恢复性转化为不损伤已正确实例的可学习修正？

三模块必须按下面顺序讲：

1. **模块一：失效记账与候选生命周期分解**  
   确定失败发生在哪一层，建立 raw 候选、类别/分数、Top-K/NMS、最终输出的统一身份账本。
2. **模块二：固定原型下的可恢复性与机制定位**  
   在模块一锁定的失败对象上，判断固定 prototype 与候选是否已经包含更好掩码，并用受控对照排除位置、监督、solver、共享末层和外挂修正等解释。
3. **模块三：可学习修正与表示适配**  
   先验证选择性读出校准，再验证局部特征/原型残差能否把可恢复空间迁移到原图。方法必须通过 2 万图充分训练、独立数据和正常 COCO 评价。

逻辑关系：

问题在哪一层 → 固定表示中有没有修复空间、为什么原生没实现 → 怎样在可控代价下学会修正并验证泛化

页标题：

**实例分割掩码失效的可恢复性诊断与选择性校准**

- 研究对象：YOLO26m-seg / COCO 实例分割。

### 第 2 页：为什么不能只看一个 Mask AP

Mask AP 只告诉最终任务表现，不能告诉失败来自 raw 候选、类别分数、Top-K、NMS 还是 mask 读出。需要三视图：

raw 几何视图 → 正常输出视图 → 训练分配视图。

图画成：

GT annotation_id
  ↓
完整 raw 候选（bbox / coefficient / prototype / class score）
  ↓
类别、conf、Top-K、NMS、maxDets
  ↓
最终 prediction_id / COCOeval

页脚写：raw/oracle 诊断不等于正常输出召回，也不等于 COCO AP。

### 第 5 页：模块一——从 raw 失败到最终输出失败的漏斗

正常输出 Mask75 失败的 13,568 个 GT 中：

- 11,512（84.85%）是 raw 池本身没有 Mask75；
- 1,797 有好 mask，但正确类别分数不够；
- 153 未进入 top-300；
- 103 被 maxDets 排除；
- 3 个是配对竞争。

结论句：

**主瓶颈首先是 raw mask 候选能力，其次才是类别/保留；因此后续不能只做 score re-ranking。**

图：13,568 起点的横向漏斗图。

模块一输出：

- 失败对象清单；
- raw candidate 与 final prediction 的身份映射；
- 后续 oracle 和训练方法的固定评价队列。

### 第 6 页：模块二——固定 prototype 下是否存在可恢复空间

研究问题：

对 raw Mask fail，固定 prototype、固定候选框，只改变 coefficient，能否达到 Mask75？

示意：

P（固定 prototype） + c0（原生 coefficient） → z0 → mask0

P + c*（GT 辅助有限 oracle） → z* → mask*

c* 只在分析阶段求解，推理时不存在。

核心结果：

- 复导定义完备值：4,843 / 6,456 = 75.02% 可恢复；
- 原面板记录值：4,263 / 6,459 = 66.00%，两值并列披露；
- 复导分层：small 72.5%、medium 72.7%、large 91.7%；
- 同 GT 多 raw 的 oracle 最大值与中位数平均只差 1.293pp，位置选择不是主要解释。

图：

1. prototype → coefficient → mask 示意；
2. small/medium/large 可恢复率柱状图；
3. native / oracle mask overlay 对比。

来源：

- experiments/coefficient_recoverability_rederive_20261010/REPORT.md
- paper/manuscripts/neighbor_sensitive_p3/EVIDENCE_MAP_MECHANISM_20261009.md B1–B3

页脚写：75.02% 是固定 P、GT 辅助、有限 oracle 的诊断可恢复率，不是方法修复率、COCO recall 或 AP 增益。

### 第 7 页：模块二——独立面板确认“可恢复，但原生未实现”

独立 197 图、1,375 个候选面板：

- oracle Mask75：81.38%；
- 原生失败 663 个中，oracle 可修复到 Mask75 的比例：61.99%；
- oracle Δc 平均范数：4.19；
- 普通/动作系数微调 Δc 仅约 0.9。

图：native → ordinary BCE fine-tune → oracle 的箭头或箱线图。

只保留两个结论：

1. 固定原型空间确实存在可恢复方向；
2. 普通原生系数头没有把该方向迁移出来。

不要写“模型已经学会，只是没有激活”，这只是待检验解释。

来源：experiments/coefficient_oracle_alignment_20261009/REPORT.md

### 第 8 页：模块二——机制排除链

用“竞争解释—最小对照—决定”矩阵：

| 竞争解释 | 证据 | 决定 |
|---|---|---|
| 只是位置选错 | oracle max–median 仅 1.293pp | 不足以解释主差距 |
| 只是监督量不足 | spatial teacher 约 +0.013pp，目标组 CI 跨零 | 关闭该解释 |
| 只是 ownership/solver | 外部空间投影为负 | 关闭该配置 |
| 共享末层完全不可达 | 固定特征共享仿射回收 46.8% 诊断差距；冻结实掩码 IoU +0.0548 | 存在可达结构，但不是 COCO AP 方法 |
| oracle 蒸进原生系数头即可 | held-out cosine B −0.0348、C −0.0324；C−B=0 | 当前预算/参数化关闭 |
| 信赖域投影能保留大部分 oracle | retention 0.302，低于随机同规模 0.588 | 当前构造停止 |

页脚写：不是“所有方法都无效”，而是把下一步从外挂修正/直接蒸馏转向表示层与可学习性。

### 第 9 页：模块三——已有选择性读出校准作为方法原型

这一页把 RCMC 放成“已完成的方法原型/强对照”，不要和模块二的 5k 机制数字混成同一 Run。

方法逻辑：

1. 先试修正一次 mask；
2. 预测这次修正的 ΔIoU/净收益；
3. 只接受预测收益为正的修正；
4. 拒绝时保留原 mask。

已有 4,500 图研究稿结果：

- YOLO26m：Mask AP 43.38 → 43.94；
- YOLO26s：39.42 → 39.90；
- m 误伤 576 → 445；
- s 误伤 556 → 389；
- 相对固定平滑额外约 +0.11 / +0.10 AP；
- 响应门控延迟 57.37 ms，固定平滑 35.60 ms。

图：

- paper/manuscripts/mask_boundary_calibration/figures/method.png
- 同目录 repair_damage.png
- 同目录 development_examples.png

页脚写：该结果是 4,500 图、一次拟合、验证集曾参与探索的历史研究稿；不称为全新盲测，也不替代当前 5,000 图机制线。

### 第 10 页：模块三——从读出校准到表示适配

真正的毕业任务：

> 当固定 prototype 中的可恢复方向无法通过原生 coefficient head 稳定迁移时，增加局部特征或 prototype 表示，能否提升原图可学习性？

四臂设计：

- A：原生模型；
- C：native coefficient capacity；
- F：局部 feature → coefficient residual；
- R：局部 prototype → coefficient residual。

当前状态：

- experiments/representation_reachability_20261010/REPORT.md 仅完成 G0 smoke；
- A/C/F/R 的前向、梯度、冻结边界通过；
- 没有 COCO AP、没有正式 20k 结果，不能放在“已有结果”栏。

图：四臂结构图，A/C 表示系数能力，F/R 表示局部表示，输出统一回到原生 decoder。

### 第 11 页：模块三的实验设计与判定门槛

训练要求：

- 至少 20,000 张代表性训练图；
- 单 seed 先做筛查，有正效应再补多 seed；
- 另留独立未参与研发的数据做确认；
- 报告完整 COCO AP、AP75/APsmall、Box AP、Mask75 修复/损伤、coverage/purity、延迟/显存。

预注册主门槛：

- R−A ≥ 0.3 AP 点且 bootstrap 下界 > 0；
- R−F ≥ 0.1 AP 点且 bootstrap 下界 > 0；
- AP75/APsmall 不同时下降超过 0.1；
- baseline-success 损伤率上界 ≤ 1%；
- 外部 PigLife/Faro 不同时为负。

图：门槛卡片或放行—停止决策树。

必须明确：

- 20k 之前的 smoke/小样本只证明工程可执行；
- oracle 只用于诊断和训练期标签构造；
- 不能把任一单次配置的负结果扩展成“方法整体无效”。

## 四、答辩时的主回答口径

被问“你的创新到底是什么”时回答：

> 创新不定义为再加一个 loss 或再加一个 gate，而是把实例分割失败拆成候选能力、候选保留和系数读出三个层次，先用固定 prototype 的可恢复性实验量化“可恢复但未实现”的差距，再把这个差距转成选择性读出校准和表示适配的可证伪方法问题。

被问“75.02% 是不是你方法的提升”时回答：

> 不是。75.02% 是固定 prototype、GT 辅助有限 oracle 下的诊断可恢复率，用来证明问题存在修复空间；方法效果只接受正常 COCO 输出、修复—损伤和成本三项共同验证。

被问“为什么不继续调 oracle 蒸馏或 TriFlow”时回答：

> 当前配置已达到预登记停止条件：oracle 蒸入原生分支没有超过普通微调，信赖域只保留 30.2% oracle 增益，TriFlow 在 20k 阶段未过 AP 门槛。下一步因此转向表示适配，而不是继续在同一系数读出上堆复杂度。

被问“第三模块是不是还没做完”时回答：

> 是。第三模块作为开题后的验证任务，工程 smoke 已通过，科学结果尚未知；它有固定四臂、20k 训练规模和明确放行/停止门槛，开题不把未知写成已完成结果。
