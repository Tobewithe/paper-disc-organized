# 01_研究定位

各位老师好，本次汇报的题目是“面向密集场景的目标检测与实例分割方法及系统研究”。论文关注密集场景中的个体级感知：当前画面能否准确区分个体和像素区域，以及这些结果能否支撑连续的视频分析。

围绕这一需求，拟开展候选判别与选择性掩码修正两项方法研究，并在通用系统中接入视频跟踪和身份状态管理。猪只群体监测作为应用案例，方法和系统接口面向通用密集实例问题。下面按照应用背景、现有能力、关键难点、研究内容和系统验证展开。
---

# 02_应用需求

应用中的困难可以沿着“场景条件、输出错误、业务后果”三步说明。首先，个体被局部遮挡时，仍然可见的区域可能只产生低分预测，或者在相邻帧中间歇漏检。这会造成可见数量的统计偏差，也可能使原有轨迹断开。

其次，相邻个体接触时，检测框可能分别覆盖目标，但分割区域仍可能粘连，或者把邻居的像素分配给当前个体。这样即使计数基本正确，个体面积和区域分析仍可能失真。第三，当外观相似的个体交叉或遮挡后重现时，当前画面可以再次检出两个目标，却可能把它们接到错误的历史轨迹上，或者重新分配身份，导致停留时间和连续行为记录断裂。

因此，连续个体分析需要同时检验帧内观测、区域质量和跨帧身份。这里的图是失效机制示意，不是本项目已经获得的实验结果。对完全不可见的个体，可见计数减少本身并不构成漏检；系统中的预测存量需要采用另一种明确的统计口径。
---

# 03_技术现状

现有技术已经具备较强的检测、分割和视频跟踪能力。YOLO26m-seg 可以统一输出类别、框和实例掩码。官方在 COCO val2017、640 输入条件下发布的 Box AP 为 52.5，Mask AP 为 44.1。这些是通用帧内评价指标，并不包含连续身份的评价。

视频跟踪方面，ByteTrack 将低分检测框用于关联，以恢复其中的真实目标；OC-SORT 针对遮挡期间运动预测误差积累，利用观测信息进行纠偏。SAM 3 进一步支持概念驱动的多实例检测、分割和跟踪。已有方法已经解决了一部分低分漏检、短时遮挡和实例传播问题。

本课题需要进一步检验的是：这些能力在密集接触、相似外观和较长遮挡的具体场景中，能否持续输出正确个体及其身份。单帧 AP 不评价跨帧关联，所以框和掩码的总体精度，不能单独证明身份连续性。后续将用独立的跟踪指标及遮挡事件评价回答这一问题。
---

# 04_遮挡后身份恢复

遮挡后的身份恢复可以分为三个阶段。遮挡前，系统已经积累了个体的位置、外观和历史轨迹。个体完全不可见时，没有新的可靠观测，系统只能暂时保留轨迹并预测可能位置。重新可见后，检测器提供的是当前目标，还需要将它与遮挡前的身份重新对应。

因此，再次检出与原身份续接是两个不同条件。时间越长，运动预测可能越不准确；姿态变化会改变外观；多个相似个体在遮挡区域内交叉后，又可能产生相近的关联候选。这些因素共同增加了错误续接和重新编号的风险。若图像信息本身不足以区分身份，评价标注也需要预先规定歧义事件的处理方式。

OC-SORT 和 DanceTrack 分别揭示了遮挡运动误差、相似外观与复杂运动的困难。SAM2Long 针对长视频中的错误记忆传播进行改进，也说明错误或缺失的分割结果可能影响后续帧。本课题将把遮挡后能否正确接回原身份作为系统验证问题，同时记录误连、新建身份和持续未检出，明确恢复能力的适用范围。
---

# 05_工程部署约束

工程部署还需要处理准确性、响应速度与资源之间的取舍。第一是输出确认。连续观察若干帧后再激活新轨迹，可以减少短暂虚假目标，但会增加首次确认的等待时间。因此，需要同时记录虚假轨迹数量和首次确认时延。

第二是轨迹保留。目标丢失后保留更久，可以提供更长的重关联窗口，但会增加计算与存储开销；长时间遮挡带来的外观变化，仍可能使重新匹配失败。NVIDIA 的部署文档明确讨论了这些约束。因此，保留时间需要通过正确续接、误连和资源消耗共同评价。

第三是完整处理链的容量。检测、分割、关联和结果输出共同消耗时间，多路视频及更多目标会增加资源需求。吞吐量与端到端时延需要分别测量，同时观察掉帧、并发容量和连续运行稳定性。

系统还要区分当前已观测个体与丢失期间的预测轨迹，避免把预测当作观测。前述背景说明，论文中的精度改进需要经过跟踪接口和完整系统评价，才能明确其实际应用收益。
---

# 06_实例选择研究现状

可靠的连续分析首先需要可靠的帧内观测。针对密集目标的实例选择，已有研究形成了多种解决思路。Adaptive NMS 根据局部密度调整抑制阈值，缓解拥挤场景中相邻行人的误抑制。CrowdDet 允许一个候选区域预测多个实例，并通过集合损失和 Set NMS 处理高重叠目标。DDQ 则从密集查询中保留有区分度的查询，兼顾候选召回与查询冗余控制。

这些工作表明，密集检测已经从局部抑制规则扩展到集合预测与查询去冗余。相应地，本课题的研究问题需要落实到更具体的候选歧义：完整目标候选、同一目标的局部片段和相邻真实个体可能同时出现在预测集合中，它们之间的重叠关系并不能直接对应实例身份。

因此，拟研究的重点是联合分析候选的可见完整性及相互关系，在限定候选范围内改进实例判别与集合选择。
---

# 07_实例身份歧义

第一项关键难点是实例对应歧义与检出完整性。左侧示意的是两个相邻真实实例，虽然它们的预测区域重叠较高，但都应当保留。若仅采用较强的重叠抑制，就可能删除其中一个真实实例。右侧示意的是同一个目标的两个局部片段，它们的重叠程度较低，却可能造成同一实例重复检出。

这两种情况提出了相反的选择要求：既需要保留高重叠的邻接实例，也需要识别低重叠的局部重复。单个候选的分类分数和几何重叠度难以充分表达这种差别。

因此，候选是否覆盖了较完整的可见区域，以及它与邻接候选之间是否存在包含、互补或竞争关系，都是拟研究的信息来源。研究目标是在固定候选预算下减少筛选造成的遗漏和重复，改善已有候选的选择质量。对于候选集合中没有形成有效预测的目标，则需要与选择阶段的错误分别分析。
---

# 08_修正研究现状

第二项研究内容建立在掩码质量估计和边界精细化的已有进展上。Mask Scoring R-CNN 预测掩码 IoU，将质量信息纳入实例评分。Boundary Patch Refinement 利用预测边界附近的高分辨率图像块进行局部细化。Mask Transfiner 以四叉树组织边界区域，重点处理检测出的易错节点。

这些方法分别解决当前质量评估、局部精细化和选择性计算问题。本课题进一步关注具体修正操作的收益。当前掩码质量较低，并不意味着某一种修正一定能够改善它；同样，发现局部存在错误，也不直接等于能够确定修正后的质量变化。

因此，拟将原掩码状态、操作引起的变化和邻接实例信息共同用于收益预测，以决定某个实例是否采用候选修正。后续通过特征消融，分析操作响应和邻接信息各自提供的作用。
---

# 09_修复与误伤

第二项关键难点是接触边界的像素归属和修正风险。页面展示了同类边界收紧操作的两种结果。如果去除的区域属于误分配的邻接实例像素，修正能够减少错误。如果去除的区域属于当前目标自身的真实细节，则会使原本正确的区域发生退化。

这说明修正操作的效果取决于具体实例的状态，而不能仅凭统一的几何规则判断。实际推理阶段没有真实标注，邻接实例的预测也可能包含误差，因此利用邻接关系时，还需要分析该信息是否有助于判断修正收益。

本课题拟以实例为单位预测修正前后的质量变化，在提高总体分割精度的同时，控制正确区域的损失。评价中将同时关注修复数量和退化数量，以分析精度变化背后的收益与代价。
---

# 10_总体研究框架

基于上述问题，论文拟以实例选择和区域优化作为两项方法研究，并通过系统集成检验其应用价值。基础模型首先产生候选集合，研究内容一进行实例判别与集合选择，研究内容二对保留实例进行选择性掩码修正。系统再按各模块的实际输入接口开展身份关联、区域统计和结果展示。

第一项内容主要改善实例集合，减少筛选造成的遗漏与重复。第二项内容主要改善像素区域，提高分割精度并控制正确区域的退化。两项方法分别开展特征消融，再比较单模块与组合结果。

视频跟踪与重关联由既有跟踪方法接入，重点检验当前帧的观测变化如何影响连续身份，以及系统在遮挡和持续运行中的实际表现。身份恢复能力还依赖跟踪器的关联机制和观测信息，不能仅由帧内方法的精度变化推断。
---

# 11_候选判别与冗余控制

研究内容一是关系辅助的候选判别与冗余控制。输入为预先限定的预测候选，拟从候选质量和候选关系两个方面提取信息。其中，质量表征关注可见区域的完整性，关系表征关注候选之间的重叠、包含、互补以及与相邻预测的关联。

基于这些信息，拟构建实例判别与集合选择机制，输出代表不同可见个体的预测集合。研究重点是区分相邻真实实例与同一目标的重复或局部片段，在限定候选预算内兼顾召回和冗余控制。

验证时，分别比较质量特征、关系特征及联合策略，保持输入候选和计算预算一致。除总体检测分割指标外，还将关注密集子集中的实例遗漏和重复检出，以判断方法是否改善了预期的实例选择问题。
---

# 12_修正收益预测

研究内容二是邻接关系辅助的掩码修正收益预测。对于已经保留的实例，先从原掩码生成候选修正，再估计该操作带来的质量变化，据此决定采用修正结果或保留原结果。

收益预测拟使用三类信息。原掩码状态描述实例当前的区域特征，操作响应描述修正引起的面积和边界变化，邻接实例关系则提供周边预测与接触区域的信息。训练阶段可以依据标注计算修正前后的质量变化，形成监督信号；推理阶段使用图像与模型预测完成决策。

该方向可以继承现有选择性修正原型，重点研究邻接信息对收益预测的补充作用。评价时固定检测集合及框、类别、分数等条件，通过特征消融比较总体分割精度、修复数量和退化数量，从而区分区域修正本身与实例选择带来的影响。
---

# 13_从输出到统计

方法改进需要沿实际的数据接口验证。第一条路径中，候选判别可能改变保留的实例集合、框或分数。这些结果作为固定跟踪器的输入，再评价身份是否更加连续。标准 ByteTrack 使用检测框和分数进行关联，因此应保持跟踪器及其参数一致，以分离前端观测变化的影响。

第二条路径中，掩码修正改变的是像素区域，首先对应个体可见面积和前景占用等统计量。评价占用时，对感兴趣区域内的掩码求并集，避免重叠像素重复计入。像素在相邻实例之间重新归属时，个体区域可能变化，而前景并集可能保持不变，因此需要分别评价。

如果框、分数和检测集合均不变，仅改变掩码，就不能直接改变标准 ByteTrack 的关联。若后续选择消费掩码的关联方式，也需要单独说明接口并进行消融。

评价包含三个层次：帧内采用检测分割 AP 和区域误差；跨帧采用 HOTA 及其关联分量 AssA、IDF1 和身份切换；遮挡事件另外统计正确续接、误连和未恢复。事件的开始、重现判定、恢复窗口与分母需在实验前确定。
---

# 14_通用系统

通用系统拟由五个模块组成。输入适配支持图像和视频，统一记录时间戳、类别和统计区域。检测分割模块通过模型接口输出框、分数和掩码，并保存逐帧结果。空间优化模块接入候选判别和选择性掩码修正，支持单独启用和组合对照。

身份关联模块接入既有跟踪器，管理轨迹丢失、重关联及身份新建。输出分析模块展示轨迹和区域结果，生成计数、面积统计以及可追溯的记录与报表。图像任务可以直接使用空间输出，视频任务增加身份关联。

系统会明确区分三种状态：当前已观测时更新轨迹和可见统计；短时丢失时保留预测状态；目标重现时记录成功续接或新建身份。由此将可见数量、预测状态和身份变化分开保存，同时记录处理时延。

通用性主要体现在模型接口、类别、统计区域与跟踪配置可调整。不同场景中的实际精度和身份恢复能力，则通过独立数据评价。

# 15_猪只应用案例

应用验证以猪只群体监测为例。密集聚集、外观相似和频繁遮挡，使这一场景能够具体检验实例区分、接触边界与遮挡后的身份连续性。

数据方面，已有动物静态图像可以用于帧内方法验证。视频研究还需要补充连续序列、跨帧身份以及遮挡、重现和可见性标注；现有图像实验不能直接替代这些标注。开发与评价按视频分组，避免相邻帧分散到不同集合；存在身份歧义的事件需要预先定义处理规则。

方法对照固定跟踪器及关联参数，比较基础模型、两个独立模块及组合方案，并按目标密度和遮挡时长分层。评价同时覆盖检测分割、区域统计、身份连续性和遮挡后续接，记录正确恢复的同时，也统计误连、新建身份或持续漏检。完整系统再测试端到端时延、掉帧与连续运行稳定性。

预期形成两项空间方法和可配置的通用感知分析系统。猪只承担应用验证，跨类别与跨场景的有效性仍需要独立数据支持。以上是本次研究方案汇报，请各位老师批评指正。

# 16_实验复用清单

现有工作可以复用四类基础。实例诊断实验提供分层评价与候选追踪流程，用于新模型的实例对应分析。RCMC 修正原型提供修正规则、收益模型和对照实现，后续补充密集子集与邻接特征消融。动物静态数据提供数据清单及推理评估基础，视频身份与遮挡事件标注仍需新增。推理和导出组件可以接入统一系统，继续完成跟踪、界面和系统测试。

已有候选排序方案未达到预设评价要求，保留其结果和诊断流程，有助于明确后续设计应解决的问题。历史实验支持研究基础与实现可复用，不能作为新关系方法或视频恢复效果已经成立的证据。

# 17_RCMC历史证据

这里列出选择性掩码修正原型的前期开发性结果。评价包含 COCO val2017 中的 4,500 幅图像和 32,831 个非 crowd 标注，在相同条件下比较基线、固定平滑和选择性响应门控。

YOLO26m-seg 的 Mask AP 分别为 43.38、43.83 和 43.94，YOLO26s-seg 分别为 39.42、39.80 和 39.90。从实例变化看，相比固定平滑，选择性门控减少了修复数量，同时也减少了退化数量，两个模型的净修复数量均有所增加。这说明选择性处理原型具备进一步研究的基础，也提示需要同时分析修复与退化。

这些结果来自一次门控拟合，评价数据曾参与早期开发，AP 尚未估计置信区间。因此，后续还需要在密集子集、邻接信息消融和独立应用数据上验证，确定新研究方案的有效范围。

# 18_实施与验证顺序

研究拟按四个阶段推进。第一阶段明确视频序列、跨帧身份、遮挡事件和独立评价分组，同时固定模型、候选预算与评价定义。第二阶段分别完成候选关系对照和修正收益预测的特征消融。第三阶段接入固定跟踪器，在相同条件下比较基线、两个模块和组合，分析空间质量与身份关联的不同变化。

第四阶段开展应用验证，测试端到端时延、掉帧和连续运行稳定性。近期的单个优先事项是确定视频标注与评价口径，随后接入基础推理和跟踪流程。后续结果将沿同一套身份定义、数据分组与接口进行比较。
