# 01_研究定位

老师好，我这次汇报的毕业论文定位是“面向密集场景的目标检测与实例分割方法及系统研究”。核心需求是看清每个可见个体，再把输出用于数量和区域分析。密集场景里，实例是否分别检出，以及每个实例的像素是否分准，是两个相互衔接的问题。

论文准备围绕这两个问题设置方法方向，最后形成通用检测分割分析系统。猪只群体监测利用已有数据作为应用案例，方法和接口按通用问题设计，跨场景效果通过实验验证。今天主要说明业界已有能力、尚存的具体困难，以及准备怎样攻克；实验细节放在备用页。

---

# 02_应用需求

先从应用究竟需要什么说起。用户往往不仅关心图像中有没有某一类目标，更关心当前看到了多少个个体，以及每个个体占据哪些区域。左侧是抽象示意，不是实际检测结果。漏掉一个实例会少计，把一个实例输出两次会多计；把邻居像素分到当前个体上，或者丢掉自身的一部分，则会影响个体区域分析。

如果进一步统计一个指定区域的前景占比，应当使用目标掩码的并集，避免重叠部分被重复计算。动物群体、人员和车辆场景的对象不同，但这些输出要求相通。因此，论文关注实例对应关系和区域质量都可核对的输出。这里的数量是当前可见实例数量，不推断完全遮挡的实际总数。

# 03_技术现状

目前通用检测分割已经有很强的基础能力。单个模型可以给出类别、位置和实例掩码。以官方发布的 YOLO26m-seg 为参考，六百四十输入的 COCO Box AP 为五十二点五，Mask AP 为四十四点一；这两个数是发布指标，不是本地复现结论，也不能据此推断本地验证已经对齐。

检测已经发展到一对一的端到端输出，可以免去最终 NMS。SAM 3 进一步支持通过文本概念或示例图像寻找多个实例，并支持检测、分割和视频跟踪。因此，本课题应在这些能力之上，检查密集位置的相邻个体是否分别保留，以及接触区域是否归属正确。前者属于实例对应问题，后者属于区域质量问题。

官方参考可在 https://docs.ultralytics.com/tasks/segment 和 https://docs.ultralytics.com/models/yolo26 核对；SAM 3 论文为 https://arxiv.org/abs/2511.16719 。不同模型的任务和指标条件不同，本页不构成跨模型性能排名。

# 04_实例选择研究现状

针对密集检测，已有研究首先改进抑制规则。Adaptive NMS 根据局部密度调整阈值，缓解相邻行人的误抑制。CrowdDet 通过一个 proposal 表达多个实例，配合集合损失和 Set NMS 处理高重叠目标。DDQ 进一步从密集查询中选择有区分度的查询，兼顾召回和查询冗余。这几项工作分别说明，密度适应、集合预测和候选区分都已有研究基础。

近期的 TQS 预印本也研究固定候选上的关系建模与集合选择，但其跨域稳定性并不一致。因此，本课题的切口需要更具体：当完整候选、同一目标的局部片段，以及相邻真实个体共同存在时，如何判断应该保留哪些预测。单纯提出“加入关系”还不够，需要证明所用信息和决策方式带来的新增作用。

本页来源为 Adaptive NMS：https://openaccess.thecvf.com/content_CVPR_2019/html/Liu_Adaptive_NMS_Refining_Pedestrian_Detection_in_a_Crowd_CVPR_2019_paper.html ；CrowdDet：https://openaccess.thecvf.com/content_CVPR_2020/html/Chu_Detection_in_Crowded_Scenes_One_Proposal_Multiple_Predictions_CVPR_2020_paper.html ；DDQ：https://arxiv.org/abs/2303.12776 ；TQS：https://arxiv.org/abs/2608.11607 ，后者按二零二六年预印本定位。

# 05_实例身份歧义

第一类难点可以用两个相反的例子说明。左侧两个预测高度重叠，但它们可能对应两个相邻、互相遮挡的真实个体；如果抑制过强，就会删掉一个本来应该保留的目标。右侧两个预测重叠很少，却可能只是同一个目标的两个互补片段，单纯按重叠去重就可能将它们都保留下来。

所以，重叠程度和单个分类分数都不能直接回答实例身份问题。拟研究的办法是结合候选的可见完整性和相互关系，在固定候选范围与计算预算下，选择一组对应不同可见个体的预测。这里的作用范围很明确：只有候选池里已经存在有效预测，选择才有机会减少筛选造成的损失；它不能凭空生成原本没有的候选。

图是机制示意。历史候选追踪与竞争案例可追溯到原汇报稿附录 E8、E9；这些案例是问题动机，不是新选择方法已经有效的证据。

# 06_修正研究现状

即使实例选对了，掩码仍然可能不够准确。关于掩码改善，已有研究也很充分。Mask Scoring R-CNN 估计 Mask IoU，用于校准质量分数；BPR 在预测边界附近提取高分辨率图像块进行细化；Mask Transfiner 使用四叉树，把处理重点放在检测出的易错节点上。

这说明质量感知、局部边界细化和选择性计算都已经具备方法基础。本课题把问题进一步收紧为：对于某一个实例，一次具体修正是否值得采用。当前质量差，不意味着某种操作一定能够修好；知道哪里可能出错，也不直接等于知道这次修改的净收益。我们准备把原状态、修正响应以及邻居预测用于这个判断，并通过对照检验新增信息的作用，而不把任务区分本身当成创新结论。

论文来源分别为 https://openaccess.thecvf.com/content_CVPR_2019/html/Huang_Mask_Scoring_R-CNN_CVPR_2019_paper.html 、https://openaccess.thecvf.com/content/CVPR2021/html/Tang_Look_Closer_To_Segment_Better_Boundary_Patch_Refinement_for_Instance_CVPR_2021_paper.html 和 https://arxiv.org/abs/2111.13673 。

# 07_修复与误伤

第二类困难在于，类似的修正动作可能带来相反结果。左侧把一块原本属于邻居的前景删掉，能够减少错误；右侧如果删掉的是当前目标自身的细小区域，就会破坏原本正确的输出。页面只表达这个机制，没有编造前后 IoU，也不代表某个实际样例经过新方法后已经改善。

部署时没有真实标注告诉我们每一块像素属于谁，邻居预测本身也可能有错。统一平滑或统一收紧，无法预先保证每个实例都获益。因此，需要根据原掩码与修正后的变化判断采用与否，并同时报告总体质量、修复数量和误伤数量。只有平均指标而没有成功保护分析，会漏掉一部分重要代价。

历史空间诊断提供了局部错误减少但总体质量没有改善的记录，来源为原汇报稿 E2。这支持同时考虑修复与误伤，并不构成对某个部件的因果证明。

# 08_总体研究框架

到这里，论文可以归结为两个层次的决策。第一层决定保留哪些预测，使输出尽可能对应不同的可见个体；第二层固定已经选定的实例，判断一次区域修正是否值得采用。基础模型产生候选，实例选择形成保留集合，掩码修正改善区域，系统再将结果转化为统计和展示。

这两个方向各自有清楚的输入和输出。一个改变实例集合，主要关联遗漏和重复；另一个处理区域，主要关联像素归属和成功保护。它们分别评价，再检查组合效果，避免把一项方法的变化归到另一项上。失败诊断、候选追踪和分层评价作为研究基础，为这两个方向提供证据，不单独列作攻克方向。

---

# 09_候选判别与冗余控制

第一个攻克方向是密集实例的候选判别与冗余控制。输入是在预先限定范围内保留下来的预测候选。准备使用的信息包括候选的可见区域完整性，以及候选之间的重叠、包含、互补和邻接关系，再结合候选质量判断哪些预测应该保留。

它需要面对的核心矛盾仍然是：相邻真实个体要分别保留，同一目标的局部候选又不能被重复解释。评价时固定候选范围和处理预算，沿基础模型实际使用的输出流程比较，保留候选与最终检测的身份对应。研究目标是减少选择造成的遗漏和冗余，是否能同时做到，需要实验回答。

已有追踪工具和候选竞争案例可以直接作为基础，但新判别方案还没有有效性结论。历史候选排序的 Gate 未通过，不能把它改写成新方法成果，也不能只换阈值追求阳性结果。

---

# 10_修正收益预测

第二个攻克方向是邻接关系辅助的掩码修正收益预测。先对一个已选实例生成候选修正，再根据原掩码状态、修正引起的变化以及邻居预测，判断采用修正，还是保留原结果。决策对象是一项具体操作的收益，而不是只给当前掩码打一个质量分。

例如，同样删除一块区域，发生在邻居接触处和发生在独立细节处，可能意味着不同风险。训练时可以用标注生成收益监督，推理时只使用图像和模型预测。单独评价该方向时固定框、类别、分数和检测集合，不将计数变化或漏检恢复归因于掩码修正。

已有 RCMC 选择性修正原型可复用，毕业论文新增的是邻接信息及相应收益判断的研究，额外增益仍待验证。后续需要同时观察总体质量和原成功实例的退化。

---

# 11_从输出到统计

把两项方法放回应用需求，就可以说明它们为什么有用。实例选择改变最终保留哪些预测，因此关联可见数量中的漏计和多计。掩码修正改变每个已保留实例的像素区域，因此主要关联个体区域是否准确。区域占用则使用指定区域内所有目标掩码的并集。

这三者需要分开理解。如果像素只是在两个邻接实例之间重新归属，个体区域会改变，但整体前景占比可能保持不变。系统应当保留前后结果，让用户能够追溯每项数量或区域变化来自哪一步，而不能笼统地把所有统计改善都归功于同一个模块。

目前已有候选追踪、分层评价工具、RCMC 修正原型和动物案例数据，可以作为实施基础。详细数值放在备用页，正文重点是把方法与应用信息连接起来。

# 12_通用系统

系统围绕前面的链路组织。输入可以是单张图片、批量图片或视频；已适配模型通过统一格式提供框、类别、分数和实例掩码，再进入候选选择与选择性修正。系统支持基线、两个单独模块以及组合模式，保留中间输出，最后叠加显示框和掩码，计算数量与占用，并保存处理结果和统计报表。

通用性首先通过工程接口实现：模型可以适配，类别名称可以配置，统计区域也可以调整。方法跨类别和跨场景的性能则必须另行检验，不能由界面可配置直接推出。

现有推理、解码和导出组件可以复用，统一界面、模型管理、视频任务和系统测试属于拟实现工作。这一页是系统设计方案，已有离线脚本并不意味着完整平台已经完成。

# 13_猪只应用案例

最后用已有数据基础比较好的猪只群体监测说明完整使用流程。用户选择猪只模型和输入数据，查看处理前后的实例结果，设置统计区域，再保存结果与逐帧统计记录。页面展示的是界面设计示意，不是已经运行的截图，也没有虚构处理速度或统计曲线。

应用验证主要检查功能是否正确、数量与区域统计是否准确、端到端延迟以及连续任务稳定性。计数只针对可见实例，区域占用是图像区域内的可见前景比例；逐帧曲线不默认具有跨帧身份保持或去重计数能力。

论文最终形成的主线是：方法回答保留哪些实例、是否修正区域，系统把这些输出变成用户可检查、可比较、可导出的结果。猪只是其中一种配置，研究对象保持为通用的密集检测与实例分割问题。

# 14_实验复用清单

现有基础主要分成四类。诊断与候选追踪可以复用分层评价和身份追踪实现，但新模型下的对应关系仍需重新核验。RCMC 可以复用修正规则、收益模型和历史对照，新增工作是密集子集分析、邻居信息消融和独立确认。动物案例可以复用清单与评估流程，但需要处理重复组问题，再验证新方法效果。推理与导出组件可以接入系统，统一接口、界面和完整系统测试仍需完成。

直接复用结果只意味着在原对象、原样本和原评价协议下引用历史事实；改变模型、数据或指标后，要重新评价。已有候选案例不等于新选择方法通过验证，旧排序 Gate 仍保留未通过状态。

证据索引为原汇报稿附录 E1、E2、E3、E4、E8、E9，权威文件位于 C:/Dpan/codexproject/paper-disc-organized/paper/毕业论文汇报稿_通用密集检测分割与系统_20261014.md 。其中 COCO-Dense 历史评价为一千五百七十六张图，动物外部评价为 Faro 与 Bama 共四千八百五十八条图像记录；这些规模不自动成为新实验的样本集合。

# 15_RCMC历史证据

这页只说明已有原型可以作为实施起点。在 COCO val2017 相同的四千五百张图和三万二千八百三十一个普通 GT 的旧协议下，m 模型 Mask AP 从基线四十三点三八，到固定平滑四十三点八三，再到选择性响应门控四十三点九四；s 模型对应为三十九点四二、三十九点八零和三十九点九零。

选择性方法同时减少了修复和误伤，不能只报告其中一项。m 的修复从九百零七降到八百零一，误伤从五百七十六降到四百四十五，净修复由三百三十一升至三百五十六；s 的对应净修复由二百八十五升至三百四十。这些是固定匹配的 Mask IoU 零点七五诊断，不是 AP 的样本分母。

结果来自一次门控拟合，验证数据曾参与早期探索，AP 未给置信区间。因此它只能支持所测条件下的原型，不能证明新增邻居信息、密集子集或动物场景已经获益，也不能与原生五千图的基线串表。

m 的源 Run 为 RUN_e0e0d46defb74e3d9a90094f49ce26fe，s 为 RUN_f9df48632ac742248343184263262429，均在 C:/Dpan/codexproject/paper-disc-organized/experiments/mask_boundary_route_20260914/runs/ 对应目录中；冻结摘要副本位于 paper/manuscripts/mask_boundary_calibration/reproducibility/evidence/ 下同名 Run 目录。

# 16_实施与验证顺序

实施上先统一比较口径，包括模型、样本分组、候选预算和评价规则，再分别检验两个方向。候选选择要对照质量信息和关系信息各自的作用；掩码修正要比较原收益模型与新增邻居特征。之后将基线、两个单模块和组合放在同条件下比较，区分收益来自哪一步。

最后在猪只案例中进行独立应用确认，并测试统计误差、端到端延迟和连续任务稳定性。最近的一个具体步骤，是固定毕业论文的比较口径，并将已有基线推理接入统一接口。这里是实施建议，没有因此启动训练，也不改变独立期刊论文中系数纠错研究线的当前协议。
