# 原S1机会兑现核对结案：优先推进可恢复失败的条件修复学习

结案日期：2026-10-16（Asia/Taipei）。Study 名保留协议准备日 20261015；实际执行时间以 Run 为准。

**我主张下一阶段聚焦“让当前输入学会已知可达的掩码修复”，优先解决修复器的学习目标问题。** 原S1已找到解的122条中，当前无门控Δc仅兑现22条；其中10条被原面积门控撤回、12条保留。余下100条即使关掉门控也没有达到Mask75。按事前冻结的L/G比较，学习侧是本面板未兑现机会的主要所在；面积选择器确实存在覆盖损失，但优先放宽门控不能解决主要缺口。

这是对固定成品和固定256条面板的直接核对，不是对所有系数方法、所有训练目标的因果判定，也不把条数差换算成全量AP差距。新方法效用尚未证明，既有S3的+0.3点幅度Gate失败不变。

## 2. 同检测与COCO任务身份

每条固定的是原S0官方bbox@.75匹配的最终输出行，ID是原预测文件SHA加全局行号。GT/类别/图像相同；BoxIoU≥.75、原生该检测MaskIoU<.75且原GT任务失败均独立核对。没有用其它检测的最大IoU替代。

本轮的12条门控后同检测修复，在原S3全量COCO账本中也对应12条GT任务恢复，匹配的最终行恰好是该固定Box75检测。这是此次逐条核对的事实，不是预设框/掩码匹配相同。无门控的全量COCO任务匹配本轮未重算，不能把22条同检测修复写成22条COCO任务恢复。189条原S3全量任务恢复来自另一个分母，不参与本表。

## 4. 支持与削弱的主张

本轮直接支持：在原S1面板和当前checkpoint上，主要未兑现机会位于预测修复器一侧（100条），门控撤回是较小的剩余项（10条）；当前修复器确实已经学到部分有效修复，且原面积策略保留了一部分收益。

本轮削弱：把当前收益不足主要归于面积门控过严，因而优先扫阈值/放宽阈值的建议。即使理想保留已被撤回的10条，另100条仍缺修复。

本轮未区分：输入信息、监督目标、优化或模型容量中的哪一项造成学习缺口，也未证明追加epoch、换loss或更大模型能解决它。旧[原生系数分支oracle方向对齐失败](../coefficient_oracle_alignment_20261009/REPORT.md)仍是有效负证据：单纯回归oracle系数方向没有现成支持。它的候选和分支与本轮不同，不能冒充本轮已测试的对照。

## 5. 唯一下一步：冻结训练集内的可达掩码目标学习对照

**我建议下一阶段聚焦“固定P下可达掩码目标的条件修复学习”，因为本次100个已知可修但当前未修好的检测、以及全部22个已学会修复都属于oracle机会集，提供了直接对象依据；优先解决无GT输入能否预测出可达的修复，第一步是冻结一个仅在原train2017训练图内构建同最终检测oracle掩码教师的学习对照协议，以原S2修复收益和成功损伤门槛决定继续或停止。**

这一方向是有依据的待检验方法主张，尚不是有效方法结论。具体设计只选一项学习目标对照：监督重点放在oracle解码后可达的掩码功能上，现有B架构、P/c0/F、原成功保持项及损伤验收保持可比；教师仅来自训练图，当前256条验证配对绝不作为训练标签。oracle向量参数本身不作唯一正确解，避免重复旧方向回归主张。先在新协议中明确教师空间、目标、训练内拆分、预算、对照和失败停止，不能直接把本报告当启动命令。

改判条件：只有新方案在未作教师的评价配对上提高修复且通过原成功损伤门槛，才支持进一步投入；若只是拟合训练教师或再次损伤超标，关闭该具体学习方案，不以放宽门控/Gate救场。本次不追加训练、不启动上述后继、不启动S4、不提交或推送。
