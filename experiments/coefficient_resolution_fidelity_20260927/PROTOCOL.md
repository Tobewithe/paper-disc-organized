# Experiment 7P：8×8 归属网格是否保留 oracle 修复效用？

7O 的 8×8 neck ROI 监督没有稳健改善失败掩码，但这一结果只有在评价网格本身仍能反映完整像素尺度上的修复时才有解释力。固定 7D 已保存的 `lambda=0.003` 系数 oracle，不训练模型，在同一 val 候选的预测框内，分别计算原型 logit 上采样到 640×640 并与原始 GT 对齐后的指标，以及 7O 使用的 8×8 自适应平均网格指标。8×8 原 logit 从 160×160 prototype 图框内平均，8×8 软标签从 640×640 GT 框内平均，严格复用 7O 的构建方式。GT 仅用于评价与已经固定的 oracle；本实验不试图构成无 GT 方法。

在两种分辨率上使用相同原型、相同系数、相同预测框与当前 GT 所有权标注。每个候选报告两尺度的原始和 oracle 值、增益；用图像聚类重采样给出均值增益及尺度差的 95% 区间，附增益秩相关、方向一致率和 `640 gain>0.01` 的检出情况。组别按既有原图 Mask75 与 Box75 划分，不依本次结果筛选。7D 的 200 个实例事先按失败状态平衡，不代表 COCO 人群发生率。

实现核对：7D 已保存的 640 网格指标使用官方 `ops.crop_mask` 定义支持区；最终比较直接按 image ID／annotation ID 引用该指标。8×8 指标由同一缓存的系数、原型、640 所有权标签及预测框重建，并逐像素核对 7O 的原 logit 与软标签。简化矩形框裁切的 640 指标不得替代官方支持区。

判读规则：若 oracle 在 640 网格有实质收益、8×8 明显消失，则 7O 的网格本身限制了判别；若 8×8 能保留大部分收益，7O 负结果不能简单归咎于标签／评价分辨率，但仍可能因输入 ROI 的 8×8 压缩丢掉信息。
