# 用户指定执行顺序：本体外观优先，生成算法贯穿各阶段

用户最新原话：“第一步先要把猪渲染的像和真实的看起来差别不大，第二步才是各种姿势算法，第三步是场景渲染，第四步碰撞”。该顺序取代此前下一步继续随机联合场景/姿态/碰撞的安排，旧Run、程序与失败记录保留。

1. **猪本体外观**：先固定已核源猪、站姿、相机、简单背景与灯光，制作并实际比较皮肤/细表面/可见部位细节。与已允许无标签TRAIN RGB的外观证据比较，先消除明显模型/塑料感；阶段1未过不开展新姿态/场景/碰撞实验。
2. **各种姿势算法**：本体外观通过后再开放可采样姿态算法及姿态范围，不以几个固定姿态mesh代替。
3. **场景渲染**：再把实例随机参数、环境设施、材质与成像联合生成并核像素标签、分布覆盖和回放。
4. **碰撞/挤压形变**：最后接入每次新参数下的碰撞/接触求解，不重复固定接触资产冒称物理随机化。

用户上一条“记住调整算法而不是固定资产”仍有效：各阶段保存算法、参数、种子、约束与审核，而不是把一次生成的资产或贴图目录当终点。阶段1也优先可复现程序化外观构造；已有基础MAMMAL源表示与固定验收样例用于对照，不是完整生成能力。

“差别不大”须由实际原图审核和与允许RGB的可见证据比较，不能只看几何/标签或由固定特征相似度自动放行。不以改灯/曝光掩盖未解决的本体缺陷，不用无依据的精确生物材质参数作真实测量结论。此前批准的有限宽度站姿仅说明该几何变体可用，未证明皮肤/毛发/细表面接近真实。

完整合格合成数据目标保持，真实既有标签/旧拟合/dev-test、对抗/特征自动反馈、Qwen/YOLO等训练、定时器/自动续跑和GitHub推送仍禁用；已登记服务器GPU并发≤6。阶段1必要的单猪固定站姿是外观对照，不启动新姿态算法研究。
