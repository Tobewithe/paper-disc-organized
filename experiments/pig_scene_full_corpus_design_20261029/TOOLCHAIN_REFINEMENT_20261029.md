**额外模型只保留一个有明确缺口的候选：SAM2（U14）。** `RGB＋本轮新产生的点/框 → 候选Mask`可帮助9B取得更细的像素支撑；仍由9B解释语义、owner与歧义，几何负责合成真值。它不负责隐藏部位恢复，也不能因分出了两块就保证属于同一头猪。只有RGB侧边界质量成为已记录的阻塞、并在同一新RGB复核口径下比OpenCV候选有明确增量时，才值得另冻版本/调用预算接入；本轮不下载、不安装、不将它纳入冻结Qwen主链。

**暂缓项有具体替代关系。** Optuna ask/tell（U08）适合将来异步外部评估，但当前低维有限搜索直接用SciPy，免去第二套优化状态/数据库。Trimesh＋python-fcl（U11）是需要真实mesh碰撞窄相时的候选，PyMeshLab（U12）用于自交/非流形诊断；不同时把它们全部安装成前置条件。检查发现拓扑问题时先保留失败，不能自动修复/重网格后继续沿用旧三角part ID。

## 3. 真正接入的是一组受限动作

以下名称是**待实现的白名单接口设计**，不是声称仓库已经提供这些可执行工具。每次返回输入SHA、资产/相机/geometry_id、坐标变换、参数和状态，禁止模型调用任意Python/shell。

| 受限动作 | 负责方 | 返回给下一环的结果 |
|---|---|---|
| `observe_rgb(image, roi, context)` | 9B＋固定原图/裁剪工具 | 实例/部位候选ID、owner备选、可见连接与遮挡者证据、unknown；原坐标与裁剪坐标双向映射 |
| `measure_roi(rgb, evidence, policy)` | OpenCV固定程序 | 有来源的边界候选、可读片段/宽度/对比度及区间；失败不强行出一个数 |
| `propose_recipe(constraints, allowed_actions, budget)` | 显式网格／SciPy | 受限候选参数和原因；不改预算/容差/目标，不可支持的格返回unsupported |
| `render_labeled(asset, recipe, pixel_policy)` | 现有Blender，或经parity后采用的BlenderProc封装 | RGB＋实际变形网格/映射＋实例V/T/A、部位V/T/S/P＋occluder map；各层按原合同定义 |
| `audit_geometry(export, camera, policy)` | Open3D独立射线核验，必要的专门碰撞检查另配 | owner/三角/深度一致性与明确不能判的项；硬错误阻断接收 |
| `compare_observables(real_evidence, synthetic_rgb)` | 共同测量定义＋盲于候选排序的RGB复核 | 同口径可见条件是否进入目标区间；不拿真实侧猜测的隐藏比例对比合成3D真值 |
| `select_coverage(accepted_pool, obligations)` | 确定采样／后续SciPy MILP | 合格且可追溯的覆盖清单、实际接收分布/重复父族；无支持不填假权重 |

2B可以在`observe_rgb`之前找参考、在合格池后辅助近重复检索，但不串成必经步骤，也不担任`compare_observables`的主裁判。9B负责“是什么、属于谁、哪些证据可判”，测量/搜索/几何程序负责确定计算与执行。9B不需要临场自行写py文件。

## 4. 首个实例：一条腿被横栏切开

这是选择的**开发案例类型，尚未从本Study真实RGB验证其发生频率**。首条闭环先限制为一头猪＋一根横栏，固定已核可用的腿姿态/相机/材质；邻猪遮挡和复杂接触是下一种独立遮挡者，不混在首例里扩大参数维数。全属性目录仍保留，当前激活字段为腿owner、部位组、可见段、遮挡者及投影像素条件。

1. **先得到可核的真实证据。** 只读批准构建用途的TRAIN RGB原图，输入清单/来源/分组/图像SHA另冻；不读dev/test426或任何已有标注。9B从原图提出两段可见腿候选与“中间有横栏”的证据。复核只看RGB确认范围；近端连接、侧别、owner不清则unknown，不用既有框/Mask、中心最近距离或“猪应有四条腿”填补。
2. **形成共同的二维目标。** 用声明的最终输入尺寸记录可读片段数、横栏投影宽度和可见腿段范围，带边界/可读性不确定区间；片段连通性4/8邻域、最小有效像素/区域和缩放政策都须在实际Run前冻结。真实隐藏腿长、遮挡面积比例、米制关节/体长不进入目标。
3. **只动确实控制该缺口的参数。** 首先搜索横栏高度/截面宽度两个变量，其它固定；这能检验栏杆是否真正切断已映射腿组的可见投影。若只有移相机才能表达所见条件，再另登记相机动作，不能在失败后悄悄扩大动作集。原始腿组不支持必要轮廓即asset_gap，不用更多seed或肤色掩盖。
4. **生成前后成对证据。** 每个候选保存实际几何/参数、RGB、物理可见腿Mask和栏杆occluder。另保留移除横栏的同场景反事实，区分原本自遮挡碎片与横栏造成的新增断片；这只是合成侧因果检查，真实侧没有孤立腿真值。变形mesh/part映射、标签层级先过硬约束，随后才比较可见条件。
5. **把几何正确与RGB可读分别重测。** Open3D核首命中身份/三角/深度；相同像素政策下核片段及栏杆贡献，再用与真实侧相同的RGB测量/复核检查片段是否实际可辨。`k_geometry`不等于`k_readable`，不能因已知合成Mask有两块就说图中能看出两段。只有同一9B/2B打分上升不接收。
6. **预留三种能改变决策的出口。** 目标可见条件进入预冻区间、参数作用符合预期且硬护栏通过 → 首条闭环工程通过，下一步才扩大该遮挡类型；映射/几何/控制失败或有限预算内无合法支持 → 停止该配置并补对应资产/控制；真实owner/边界不可判或核验不一致 → 证据不足，不给自然频率、不继续量产。工程通过也不等于AP提高。

此例可先用保守的空间分离约束使横栏在猪前方且世界包围盒不交叠；**AABB不交叠可排除交叉，AABB交叠只能拒绝/转窄相，不能宣称已发生真实穿透。** 若要放宽到邻猪紧贴或复杂接触，实际变形mesh的穿透/包含检查必须先可用。无碰撞不等于姿态自然或有生物支撑，仍需资产/姿态核验。

## 5. 实施时必须防住的工具接口错误

- **逻辑实例不能直接等于对象ID。** `triangle → canonical leaf → parent part`与`object/triangle → pig instance`分别保留；同猪多个mesh合并owner，单mesh多部位须有面/表面属性映射或明确拆分方案。拆分不能破坏rig、边界或生成假切口面；未知表面保留remainder。
- **映射跟随实际变形和拓扑。** Blender的evaluated mesh才是投影对象；modifier/三角化/拓扑改变后不能盲沿用原面编号。锁三角映射并核姿态；两个射线器共享映射时只构成数值交叉核验，语义仍要独立审。
- **射线和深度单位显式声明。** Blender场景ray接口会规范化方向；Open3D的`t_hit`量纲受射线方向长度影响。统一坐标/方向归一化、near/far、相机z与沿射线距离后才比较，不能将z-depth直接与t_hit逐值相减。
- **RGB与ID使用同一相机/最终输入域。** 离散ID不做双线性插值；抗锯齿/覆盖率与硬Mask边界政策前置明确。裁剪、畸变、缩放同时作用于对应RGB/真值，保留坐标变换；改变透明度、位移、曝光时刻/运动模糊的处理需另订真值政策。
- **搜索有总预算而非只设代数。** 首例显式候选总数最清楚；若用DE，固定`polish=False`、实际函数调用硬计数和单次/总超时，避免默认polish在停止后追加昂贵渲染。求解器/Slurm分别记账，不设自动续跑；本页未激活调用/渲染预算。
- **覆盖求解不伪装自然分布。** MILP可约束已接受候选的覆盖、父族重复和总数；无可用候选即缺支持。超时有可行解与证明最优分别报告，不以success字段笼统判所有结果。目标自然频率仍须来自合法无标签RGB核验、保留unknown分母。

## 6. 当前决策与唯一下一步

**优先方向是把可读身体片段与生成动作接通，使用现有OpenCV/Blender/SciPy，补Open3D独立几何接口；不优先扩模型、资产库数量或全量聚类。** 依据是猪部位研究已指出断片与owner失配，而本项目尚缺一个真实证据→参数变化→重测的完整例；这些工具恰好补测量、执行和核验三个断点。它比再加通用视觉模型更直接，也保留OpenCV不足时引入SAM2的可检验理由。

来源核验阶段的下一步是：完成必要映射和最小固定工具适配，冻结TRAIN RGB例证、像素政策、候选/调用总数、资源与数值验收，再实施一次受限闭环。该阶段只交付可执行设计与真实来源/环境核验；后继用户授权的实际执行见下节。旧28项检查、资产Run、预算和失败继续保留原身份。
