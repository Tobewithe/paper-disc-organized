# 固定合成数据集 V5：实例—身体部位—归属优先

日期：2026-10-29（Asia/Taipei）。这是对V4合成方案的继续完善。用户已澄清当前工作是**合成数据方案，不是模型训练**。本版不启动渲染、训练或新release。

我选定的主方向是：**先把合成数据做成可验证的“实例—部位—owner—可见性”真值，再扩展场景外观与联合分布。** 猪的整体Mask或姿态正确，不能掩盖耳、腿、蹄、尾被分给邻猪；因此合成数据的核心单位从“猪实例框”提升为“实例内的部位记录和部位像素层”。这一选择与猪群部位关联研究中“部位定位后仍可能错误关联”的失败机制一致，也保留V4对真实联合几何、遮挡和成像的设计。

## 1. V5与真实RGB解析的边界

真实RGB的作用只有三种：观察目标域的画幅/尺度/设施与成像范围；发现合成覆盖缺口；在未来冻结release后做无标签部署检查。真实数据已有标注、旧Qwen输出和人工框不进入合成监督。Qwen9B的候选可以提出“需要更多腿交叉/耳邻近/细栏遮挡案例”，但不能把候选直接编译成目标频率、姿态标签或部位位置。

因此V5不做“从真实标注拟合猪的部位分布”。它采用两层来源：

1. **独立合成真值层：** 猪资产、rig、部位映射、相机、设施、深度和渲染计算产生所有目标字段；这是训练导出的唯一真值来源。
2. **无标签目标域约束层：** Qwen仍解析真实RGB的完整实例/部位属性，并保留候选尺度/密集度/遮挡/设施及不确定性。候选先作`coverage_hint`；逐字段经独立RGB复核后，可成为`admitted_constraint`约束配方，记录可判/未知分母；不永久把Qwen降为只说几句场景提示，也不把未核候选自动当自然频率。具体对应见[RGB到配方桥接](RGB_TO_RECIPE_V5.md)。

## 2. 身体部位主词表

### 2.1 必须覆盖的粗到细层级

| 组 | 部位层级 | V5的定义重点 |
|---|---|---|
| 头面 | head → snout → nose_tip / nostril / mouth / lower_jaw / eye | 头的owner先于五官；五官像素不足写不可观察，不因常见结构补齐 |
| 耳 | ear → ear_base → ear_pinna → ear_tip | 每只耳单独ID；图像左右和解剖左右分开；邻猪耳不可借用 |
| 颈肩 | neck → shoulder_surface_anchor | anchor是可见表面定义，不是内部肩关节；连接被遮时保留断开证据 |
| 躯干 | thorax / dorsal_trunk / ventral_trunk / lateral_trunk / lumbar | 同一表面最底层分区保持互斥；胸腹/背侧等语义组可由叶子并集生成，父子区域可重叠 |
| 臀尾 | rump → rump_surface_anchor；tail_root → tail_shaft → tail_tip | 后臀背线锚点不叫尾根；尾根和尾尖必须分字段，出框/遮挡不能写缺失 |
| 前后肢 | visible_limb → fore/hind candidate → elbow/carpus/stifle/hock surface candidate | 关节是表面候选，不能假称隐藏骨骼角；近邻距离不能决定owner |
| 蹄接地 | visible_hoof → hoof_contact_candidate → claw/dewclaw（像素足够时） | 接地候选、物理contact、二维贴近三者分开；不强制四蹄都可见 |
| 细部位 | teat/udder/navel/external_genital/tongue/tooth | 只有最终RGB像素门槛通过才启用；不把不可见写成解剖不存在，也不推断性别/健康 |

完整类别、层级和字段见[PIG_PART_TRUTH_SCHEMA_V1.json](PIG_PART_TRUTH_SCHEMA_V1.json)。

本版在RGB观察目录40项上显式增加`ear_pinna`，共41个术语；它们包含表面区域、地标、关系和观察时的角色候选，**不是41个可互斥分割类别，也不是每张图必须出现41项**。合成资产已知前后肢/侧别时直接保存几何角色；`candidate`仅是兼容真实观察的别名。坐标地标不强制生成面积Mask。

### 2.2 一个部位记录必须回答什么

`scene_id → instance_id → part_id → component_id → attribute`。每个part保存：

- **owner和父级：** 属于哪头猪，父部位是什么，是否为可见断片；
- **定义和侧别：** 该点/区域代表哪个表面或部位，解剖左/右/中线/未决；
- **实例与部位投影：** 实例V/T/A；部位V/T/S/P，其中S保留同猪自遮挡，P表示只投影该部位原始表面；
- **遮挡和截断：** 被哪一个猪/设施遮挡，是否出画幅，是否自遮挡；
- **支撑和关系：** 蹄/躯干与支撑面的几何接触、局部遮挡、部位附着；
- **像素门槛：** 在最终输入分辨率下可见像素、短轴、抗锯齿和细部位启用决定；
- **哈希链：** asset/scene/render/label文件内容SHA与生成器版本。

`component_id`用于记录同一部位被栏杆切开的多个可见片段；这些片段共享owner和semantic part，但不能把片段本身误当成多个实例。完全被外部遮挡的部位仍可在amodal/完整投影层存在，但不进入physical visible正例。

表面分区有单独`partition_id`：叶子表面互斥且合起来覆盖该猪可见区域，未映射表面放`unknown_surface_leaf`；不能漏掉后当背景。`head`包含`snout`等后代时，父Mask由相应叶子并集得到，与后代重叠是正常层级。地标另存原图点、定义、侧别和深度/射线可见性，不能把鼻端点、内部关节和头部区域混为同一标签。

## 3. 最重要的困难场景

V5不只增加猪数量，而是明确生成以下可验收反例：

1. **腿交叉：** 一条腿从猪A身体轮廓旁穿过，连接点被猪B遮挡；几何owner仍唯一，visible component与occluder分别保存。
2. **耳头邻近：** 猪A耳尖靠近猪B头，颜色相似；两只耳的owner来自资产/深度，不按最近中心或像素颜色绑定。
3. **尾部三段混淆：** rump anchor、tail root、tail shaft/tip同时可见或部分被遮；标签定义不能用论文中“tail”名称替代。
4. **栏杆断片：** 细栏、料槽或墙切开头/躯干/腿，保留多个可见片段、遮挡者和任务政策；不把断片外接成完整Mask。
5. **猪间互遮：** 局部遮挡关系可交错，保存部位级有向边；不要求整图深度关系形成DAG。
6. **画幅与小部位：** 耳尖、鼻孔、蹄、尾尖出框或低于分辨率时，使用out_of_frame/unobservable gate，不产生伪负例。
7. **支撑反例：** 蹄看似贴地但深度/接触未验证；二维接触、物理contact和支撑姿态分别导出。
8. **相同几何不同外观：** 外观对保持相机、pose、geometry和几何标签不变；曝光/阴影仍可改变细部位可读性，逐张重核字段使用掩码。改变几何投影或不透明遮挡关系才生成新geometry_id。

## 4. 真值层和标签政策

对同一个scene/camera/render grid，导出：

- `physical_visible (V)`：第一不透明表面，猪/猪/设施都正常遮挡；同一像素不能同时属于两个物理可见owner；
- `task_visible (T)`：由任务政策从V确定性导出，bridge哪类设施必须逐类写明；
- `amodal_in_frame (A)`：移除外部遮挡物后的同相机视锥投影，自遮挡仍保留；
- `part_self_visible (S)`：整头猪孤立渲染时该部位可见的像素，仍可被同猪其他部位遮住；
- `part_complete_projection (P)`：只保留该部位原始表面时的投影，不添加切割封口，允许不同部位重叠；
- `occluder_map (O)`：部位/实例被谁在何处遮挡，像素增量和深度字段独立保存。

实例层严格可见应有`V=T`，合法bridge下`V⊆T⊆A`。部位层在同一不透明/采样政策下应有`V_p⊆T_p⊆S_p⊆P_p`；实例A由规范叶子的S并集得到，不能对全部P直接求和。细栏补回的T区域不能被当成猪皮肤RGB；任务Box、完整投影Box、可见部位RLE和amodal RLE不能混用。

几何可见性与可读性分两组字段。`out_of_frame`、`fully_occluded`、`self_hidden`分别由投影/深度决定；即使V有像素，`observability_state`仍可能因低分辨率、污渍或暗光不可读。几何真值继续保存，只禁用对应细字段的可见监督，不删除整猪或粗部位。具体像素门槛在P1实测前不写死。

## 5. 采样与拆分

V4的几何核心池、成对成像和困难池继续保留，但V5把每个联合格再拆成**部位覆盖格**：身体组×可见性×owner难度×设施遮挡×尺度。配额表示覆盖义务，不直接声称真实自然频率。Qwen/真实RGB只提供缺口提示，未知值不做均匀填补。

先声明要隔离哪些泛化轴，主版本按asset parent family、scene family与派生关系分组；camera family只有在宣称新相机泛化时才作隔离边，不能因为普通共用镜头把无关资产全连起来。相同mesh换姿态、相同geometry换材质、同场景裁切和反事实图始终成组；若只有一个连通分量，只能叫train+qa_replay，不能伪造synthetic-dev/test。

## 6. 生成接受与失败账本

每次候选都经过：资产/部位映射 → pose/support合法性 → 窄相碰撞 → 相机投影 → body-part visibility → task policy → RGB/ID/深度标签导出 → RLE/坐标重载。任一步失败都保存`candidate_id,parent_id,stage,reason,cost,SHA`，不换seed掩盖。

必须拒绝的情况包括：part owner冲突、tail anchor定义缺失、细部位不可读却启用该字段、规范叶子重复像素、ID插值污染、RGB与标签尺寸不一致、三维穿透、任务政策缺失、拆分泄漏。细部位未通过只隔离该字段，父子Mask重叠不误拒；自然资产缺失标`support_gap`。

## 7. 版本状态与唯一下一步

本版是可审阅设计和结构合同，尚未有合格资产、合格渲染器、P1小集或新release。V5本地结构核验只用人工构造的抽象fixture，不读真实RGB、真实标注或模型。模型训练不在本次动作内。

本版支持及适用边界集中于[理论D47](../../paper/manuscripts/spm_yoloseg/SPATIAL_OBJECT_THEORY_SUPPORT_20261025.md#d47-身体部位优先的合成数据与rgb约束桥接)。[本地协议](ENGINEERING_PROTOCOL_V1.md)已执行抽象合同核验，实际结果见[Study](study.json)；通过不代表解剖、真实渲染或数据效用通过。

**唯一下一步：** 先建立独立猪资产的部位rig/landmark清单和一组最小场景fixture，核验part owner、V/T/A/P/O层、遮挡关系、细部位分辨率门槛和RLE/坐标往返；通过后再做有限P1渲染。若资产不能稳定给出部位owner，停止扩展外观和数量，优先修资产/部位映射。
