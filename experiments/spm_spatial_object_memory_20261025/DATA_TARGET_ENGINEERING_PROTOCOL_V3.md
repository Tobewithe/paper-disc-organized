# 正常输出身份与训练owner：重复前景不能当背景

2026-10-25。v1/v2的工程结果保留，但其一对一Box训练关联不再用于新训练。官方Box/Mask是独立一对一评价，不意味着每个没抢到GT的正常查询都是背景。V20真实前景/背景不对称的阴性要求修复这个监督问题，而非等训练失败再解释。

新训练owner规则：各正常查询独立选Box IoU>=.5的GT；重复框可共享同一GT。无可靠Box owner时，若原生**实际640掩码**与某GT IoU>=.5，则以该掩码owner形成训练目标。仍无可靠owner但框内含任何GT前景则该查询task/细标签unknown；只有框内没有任何原始GT前景才教空任务mask。没有已知查询的图仍计曝光、不换图/注入GT框；零查询只施加原本的规范锚和DDP零梯度连接。该规则只是训练标签，不替代COCOeval匹配或同检测诊断。

真实主任务优先解原始manifest的完整RLE，保留重叠/孔洞；不能用单值ids默默丢掉重叠。正式数据必须带原RLE。仅历史工程元数据缺RLE时允许明确记录的ids回退，不作完整数据parity主张。

policy对未知owner的查询使用KEEP决策标签，而不对其对象词条或像素造背景；候选器在该阶段冻结。mask原成功可能对应不同于Box owner的GT，成本中原生75成功保护使用原生最佳掩码GT（若>=.75），不假定两个匹配相同。完整640面积/解码规则不变。
