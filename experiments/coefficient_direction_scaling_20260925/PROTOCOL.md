# Experiment 7F-A: training size versus held-out correction direction

Use the existing frozen official YOLO26m-seg one-to-one 10,000-image train2017 bank and its seed-20260924 deterministic order. Verify this order is disjoint from the 7E 200-image train2017 dev and 200-image val2017 sets. Retain λ=0.003 and the exact strongly convex 7D BCE-plus-quadratic target solver. Cache only cloned 64-dimensional `h` and 32-dimensional regularized correction for each official positive. Train a shared `h`-only direction/radius predictor on nested 800/1,600/3,200/6,400/10,000-image prefixes; keep architecture, update budget, seed, optimizer, and fixed dev checkpoint rule identical across sizes. No validation GT target is read during fitting or checkpoint selection.

Because the pre-existing 10,000-image cache omits predicted boxes, it cannot reproduce 7E's predicted-box prototype Gram on training samples. This run therefore trains on **coefficient direction cosine and log-radius error only** and evaluates both coefficient and pixel-logit-effect cosine on the untouched 7E validation bank. The N=800 point is the within-7F reference; do not subtract it directly from 7E's differently trained h-only model. Report fit/dev/val curves, image-clustered validation uncertainty, and no-GT mask effects for the selected checkpoints if these justify a later decode run. A plateau of this particular model/input/target/loss is not a proof that the correction is intrinsically unidentifiable.

The existing full bank's prototype tensors are FP16 and cast to FP32 for target construction; an earlier audit found maximal same-image loss discrepancy 2.44e-5. The 7E targets used a separate FP32 cache. Record this source difference when interpreting the curve. Store target chunks by disjoint contiguous image ranges so an interrupted long generation run retains completed work.
