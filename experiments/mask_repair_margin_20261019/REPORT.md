# 修复解容错余量核验：工程中止结案

2026-10-20（Asia/Taipei）。本实验在笔记本 `28358lan / YANGLEI` 执行，训练步数为0。原定256条/243图，最新正式Run保存113条/107图后，在第114条触发冻结的扰动幅度精度检查并退出；这些保留产物已完成两机独立核验和回传。

**主判断：目前不值得进入这套最大最小余量目标的稳定性训练。** 本实现没有形成合格的完整比较，不能把它写成“稳定性机制无效”，也不能把113条结果替代256条。G_budget最终权重仍不可用，其同面板参照保持待补。

| 维度 | 本次实验的整体研究链路 |
|---|---|
| **问题** | 固定P下已经存在优于原生的系数修复解，但可达修复不等于网络能稳定兑现。已有C在原256条中找到159条Mask75见证；CET的固定幅度压力可明显降低教师质量，却未区分独有真实误差方向。本次要判断：同样正确的掩码，是否能换一组更耐扰动的系数，从而为稳定性训练提供正面依据。 |
| **机制假说** | H：修复系数位于同掩码可行域边缘，重新居中可以在不改变掩码质量与logit尺度的前提下提高任务稳定性。竞争解释是，扩大最小像素边界距离并不带来有意义的原图IoU/Mask75稳定性增量。前者要求等幅压力下的改善通过预设幅度和区间门槛；若求解或数值控制不可靠，则两种解释均不能据此裁决。 |
| **针对性方法** | 复用原S1的256条、原生缓存和有限C解；固定P、c0、检测身份、解码与数据。仅依据C的二值符号做有限系数重新居中W，强制首阈值掩码及原图RLE与C完全相同、logit RMS相同。用训练拟合库的真实误差方向、随机方向及通道错配方向，各8次，固定为C logit RMS的10%；C/W使用配对方向和幅度，不扫阈值、不训练。至少244条候选有效，才有资格结合完整243图的主增量≥.005、见证保留增量≥.05及其区间等条件判断机制支持。 |
| **整体结果** | 新正式Run保留113条，其中98条新中心通过候选验收，14条因矩阵病态、1条因中心尺度不符退回C；另有1条线性代理精度越限。第114条的压力在最多8次固定目标幅度校正后仍超5e-5容差，程序按协议停止。即使余下143条全通过，最多241条，仍少于244条。**相对原生与已有G_budget的完整收益、损伤及区间均未取得**；G_budget还有checkpoint缺口。保留113条的W与C无扰动掩码完全相同，故这部分名义质量没有新增收益或损失；它们是GT辅助C解的质量，不能记为新设计贡献。 |
| **研究决策** | 按协议以`INVALID_ENGINEERING`结案；覆盖不足及代理越限同时构成数值未决因素，不作机制阴性结论。停止本实现继续重跑与训练投入。**我主张优先保留并独立确认固定P轻量系数适配的实际收益，以G_budget为参照**：它已有完整AP正增量及低损伤，而本次最大最小余量干预尚无合格增量证据。**唯一下一步：服务器恢复后，回传并按原SHA核验G_budget最终checkpoint，恢复可用于后续独立确认的本地固定参照；尚未启动。** 重新考虑稳定性训练须另有数值有效、控制公平且通过原目标效用要求的正面证据；本次不追加诊断、改loss或重训替代。 |

通俗地说，本来想检验“同一个好答案能不能站得更稳”。现在发现，这套实现还不能对所有对象精确地施加同样大小的扰动，因此本轮没有做成公平的完整比较。已经保存的答案和读数可以复核，但不足以据此投入训练。
