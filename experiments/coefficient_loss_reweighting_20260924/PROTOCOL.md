# Experiment 7B：监督目标是否对框内误报不够敏感

## 假设

7A显示逐实例oracle不仅改变整体阈值，还会提高目标像素响应、压低邻居和背景响应。7B在固定原型、框、backbone和neck时，只改变共享系数修正头的像素损失，检验官方均匀BCE是否没有充分强调框内高置信误报。

## 固定条件

- 官方COCO预训练YOLO26m-seg、Ultralytics 8.4.100；官方one2one正样本、`mask_ratio=1`、`overlap_mask=true`、640标签网格。
- 使用既有800 fit / 200 dev / 200 val官方缓存；原模型、原预测框、原型、类别和框分数全部冻结。
- 四臂均为相同P3/P4/P5分立的`h`-only大MLP残差头，零初始化，参数量相同；AdamW、lr=.001、weight_decay=.0001、相同seed、图像顺序、batch和15轮预算。
- 修正头只在正样本位置训练；推理时不使用GT、oracle系数或额外图像编辑。

## 四个损失臂

对每个实例的官方框内像素logit `z` 和标签 `y`，令 `bce=BCEWithLogits(z,y)`。所有加权损失除以该实例像素权重均值，再用相同首批8张训练图匹配各臂初始参数梯度范数；逐臂记录倍率。这只匹配初始尺度，后续梯度范数仍可能变化。

1. `official_bce`：原始均匀BCE。
2. `negative_weighted`：负像素权重`w=1.5`，正像素权重1。
3. `positive_weighted`：正像素权重`w=1.5`，负像素权重1。
4. `hard_negative`：正像素权重1；负像素权重`w=1+1.5*sigmoid(z)^2`。权重中的概率停止梯度，只改变监督采样强度而不额外改变损失导数方向。

## 评价

在固定val正样本上报告：原图固定预测框下的Mask IoU、Mask75、目标覆盖率、框内误报像素；640网格框内ROC AUC及AUC变化；200个既有oracle实例上的`cos(Delta_z_model, Delta_z_oracle)`，并按失败/框好失败子集报告。所有臂统一按**未加权的开发集官方BCE**选择检查点，保留第0轮原系数作为不修正基线；另报告固定最后一轮，避免开发集BCE选择掩盖其他指标变化。若改损失只降低训练损失而不改善未见图像AUC/Mask75，不能称为机制验证。

## 判定

支持假设的最低条件是：某个重加权臂在独立val上相对官方BCE提高框内ROC AUC或Mask75，目标覆盖不下降，且模型`Delta_z`与oracle方向更一致；单独的训练集损失下降不够。若四臂均无收益，则“官方BCE监督不匹配”降级，回到实例条件信息或端到端联合训练问题。
