# 同一官方权重的 COCO 原预测与内部替换诊断

2026-09-16。Study `STUDY_0d6c34943231461f83c5b94d3cad98af`。本轮执行已结束；未经微调的官方 COCO 预训练 YOLO26m-seg，Ultralytics 8.4.100，COCO val2017。未启动新训练。

## 先明确：只有一套权重，三种不同性质的结果

**本轮只使用一套官方 COCO 预训练 YOLO26m-seg 权重，没有重新训练，没有 baseline/改进模型的权重对比。** 本地文件是 `assets/models/coco_clean_20260911/yolo26m-seg.pt`。已核对本地文件内容与生成 500 图、4,500 图缓存时记录的权重内容一致；两个图集是同一模型的分批推理。

one-to-one 和 one-to-many 是这一权重文件中模型内部的两个分支，各有自己的头参数，共用上游网络和原型。它们不代表两套独立训练的模型。本次正常结果使用 one-to-one 输出；诊断时额外读取了 one-to-many 的内部张量。

| 本报告中的内容 | 实际是什么 | 能回答什么 |
|---|---|---|
| 原模型预测及全量 Mask AP | 一套权重正常生成预测，再由 COCOeval 对照 GT 评分 | 原模型在固定评测设置下表现如何 |
| 框好/掩码差等分类 | 对同一批预测与 GT 作进一步对应和分组 | 哪个预测的框和掩码分别出了什么问题 |
| GT 挑选、替换系数后的 4/27 | 看过 GT 后人为改变内部系数，保留原框和原型 | 在这些人工选择条件下，是否存在局部改善空间 |

**COCOeval 只是评测程序，不生成预测、不加载第二套权重，也不训练模型。** 下文 Mask75 指按掩码 IoU≥0.75 的 COCOeval 规则判断 GT 是否被正确预测；“按框选定的诊断候选失败”与“该 GT 在全部最终预测中未通过 Mask75”是不同对象，必须写明。

## 当前结论与撤回的推断

原预测的 AP、逐实例 IoU 和人工替换后的数值，均有明确的输入、程序与输出；不确定的是失败原因，以及能否靠一种可学习的方法改善正常预测。此前的汇报把两种不确定性混在了一起。

32 个按框选出的诊断失败里，5 个 GT 的原始其他预测已经通过 Mask75，只有 27 个 GT 原预测未通过。上一轮初期汇报将这 5 个也描述成可恢复对象，容易被理解成新增任务收益；后续解释应以 27 个未达标对象为准，保留原 32 例作为分组来源。

在这 27 个对象上，GT 辅助系数替换使 4 个越过 0.75，按框质量挑系数也能做到 3 个；多出的 1 个仅达到 0.7517。**这不是新权重的性能提升，也未证明需要教师蒸馏、改头或改变正样本分配。此前将这些方法作为下一步立项方向的建议撤回。** 训练 GT 本已提供监督，另一位置的较好预测不自动构成更有价值的监督。

本轮保留价值限于：原模型全量评价、可复核的失败清单、简单候选替换收益受限的证据，以及少量同框同原型下可改善的实例。4/27 不能作为全 COCO 改善率，不能写成方法效果或失败根因。下方保留具体过程和原始证据，供逐例追查，而非用统计数量替代机制说明。

## 4. GT 辅助内部替换：结果及其边界

官方 TaskAlignedAssigner 重放沿用原生代码：one-to-many topk10，one-to-one topk7/topk2=1。输入为同图全部非 crowd 原始 COCO bbox，经真实 letterbox 映射到输入网格。它反映当前冻结模型在这些原图上的分配，不是历史增强训练时的正样本记录，也没有测量过去的梯度。

固定最终 one-to-one 原型和预测裁切框，从被原生分配器分配给同一 GT 的 one-to-many 正样本中取系数：

| 在 27 个原预测未通过 Mask75 的对象上的操作 | 平均 Mask IoU | 达到 Mask75 |
|---|---:|---:|
| 保持官方 one-to-one 输出 | 0.6178 | 0/27 |
| one-to-many 同位置系数 | 0.6287 | 1/27 |
| 同 GT one-to-many 正样本中取分类分数最高者 | 0.6217 | 1/27 |
| 同 GT one-to-many 正样本中取框 IoU 最高者 | 0.6359 | 3/27 |
| 同 GT one-to-many 正样本中取固定框 Mask IoU 最高者 | 0.6509 | 4/27 |

最后一行比原输出平均增加 3.31 个 IoU 百分点；图像重采样区间见源结果。最后两行都使用 GT 选教师，不能视为部署方法。掩码选择比框选择额外恢复的只有 1 例，IoU=0.7517，接近阈值；当前新颖性和独特收益证据仍弱。

在 32 个固定槽位成功对照上，无条件替换为最佳 one-to-many 正样本系数，会把 1 个对象从 Mask75 成功变成失败。该对照说明替换还可能损伤原本成功的对象，不能据此认定附加教师训练有效。

| 27 个原预测未通过 Mask75 的对象 | 平均 Mask IoU | Mask75 |
|---|---:|---:|
| A 原输出 | 0.6178 | 0 |
| B 只换系数头 | 0.6287 | 1 |
| C 只换取系数位置 | 0.6000 | 1 |
| D 头与位置同时换 | 0.6509 | 4 |

只换位置在成功对照中会破坏 6/32 个 Mask75。教师位置对 one-to-many 合适，不代表该位置的 one-to-one 系数也合适。head 与位置的作用存在组合差异，但教师位置由 D 的 GT Mask IoU 选出，天然偏向 D；不能把组合优势当成无偏的因果主效应或训练失败根因。成功对照也有较大的组合差异，因此它尚不是失败对象专有特征。

## 6. 当前应保留的研究顺序

原先据此安排的教师训练对照尚未执行，其立项建议已撤回。下一步先解决一个可以逐例核对的问题：**同一套权重在原图上，究竟哪些目标没有正确预测，具体错了哪些像素或哪一个框。**

每个拟深入研究的对象保留原图、GT、同类最终预测、预测索引、分数及同一预测的 Box/Mask IoU。先确认原预测是否真的未通过事先写明的指标，再区分框定位、掩码遗漏/多余、类别或输出竞争。COCOeval 负责原预测的统一任务评价；内部候选分析负责追查该预测如何形成，两者不能混用来报告修复收益。

只有针对确定的失败表现，能用一个受控改动区分具体解释，才追加对应诊断。没有这种区分作用的统计不扩量；没有说明正常 GT 监督为什么不足的证据，就不把“再加教师监督”当作创新。已保留的 4 个替换改善案例可作观察材料，尚不足以指定方法。

## 8. 训练分配与损失源码核对

2026-09-16。本节为源码核对与评价设计修正，没有新增训练、没有新增数据集统计。核对项目固定的 Ultralytics 8.4.100 实现及官方 v8.4.100 标签源代码。既有 64 图分配回放保留原样；其候选池和分数资格范围见第 3 节，不能扩称完整 raw 几何扫描。

**结论：只有几何分类与最终评分，足以描述结果，但不足以解释训练失败。需要沿同一 raw ID 加入实际训练责任、监督像素及梯度路径；不能用依赖分数的 TAL 取代分数无关几何评价。**

### 官方的 GT 责任如何进入损失

`SegmentationModel.init_criterion` 在 end2end 模式使用 `E2ELoss(model, v8SegmentationLoss)`。对每个分支，先解码框并取得类别分数，再在 no_grad 下调用 TAL；分类分数和预测框传入 assigner 前 detach。分配之后，box 与实例 mask 使用同一 `target_gt_idx`，由 `fg_mask` 选择有效正样本。

1. 先筛选位于 GT 候选区域的预测点。小于最小 stride 的 GT 宽/高在候选区域计算时扩展；回归目标仍是原 GT 框。
2. 计算 `GT 类别得分^0.5 × max(CIoU, 0)^6`，不是 mask IoU，也不是要求当前 argmax 类别已经正确。
3. one-to-many 使用 topk=10；one-to-one 使用 topk=7、topk2=1，并解决同一位置与多个 GT 的竞争。最终数量需读取结果，不假定每个 GT 都必有固定数量。竞争处理按框重叠，TAL 不是全局 Hungarian 指派。
4. 返回 `fg_mask`、`target_gt_idx`、目标框和归一化后的软 `target_scores`。非正样本处的 GT 索引为占位值，不可解释为训练归属。

源码：[本地 TAL](../../shared/vendor/ultralytics_8_4_100/ultralytics/utils/tal.py)、[官方 v8.4.100 TAL](https://github.com/ultralytics/ultralytics/blob/v8.4.100/ultralytics/utils/tal.py)。

### 损失与原说明的关键差别

| 项目 | 8.4.100 实现及诊断意义 |
|---|---|
| 分类 | 所有位置、所有类别参与 BCE，包括负样本；正样本目标受 TAL 质量归一化影响，不能概括为只有正样本对标签 1 求 BCE。 |
| 框回归 | 正样本使用按 target_scores 加权的 CIoU 损失；YOLO26 配置 reg_max=1 时另用图像尺度归一化的 ltrb L1，不能只写成 1−普通 IoU。日志沿用 dfl 槽位不代表正在使用 DFL。 |
| 实例 mask | 仅正样本系数组合原型，计算 BCEWithLogits。GT 由检测分配的 target_gt_idx 取出；逐像素损失按对应 **GT bbox** 裁切、按 GT 框面积归一化，再对正样本平均。没有单独按 mask 质量重新选择 GT。 |
| 辅助语义 | Proto26 训练期另有语义输出，使用 BCE+Dice；不可把它误写成每个实例 mask 都使用 Dice。它提供额外监督，因此不能把实例 crop 外无直接 BCE 等同于整个网络在那一区域完全无约束。 |
| 分辨率 | 原型输出分辨率不等于 loss 分辨率；该版本在尺寸不同时双线性上采样 proto 到训练 mask 尺寸。不能把原型 160×160 直接当作固定监督尺度。 |
| overlap_mask | 当前设置为 true，训练 mask 是按面积排序后的实例 ID 图，重叠像素在该图中只有一个实例 ID；框/类别按相同顺序重排。预测概率图仍没有实例间互斥归一化，这两件事不能混淆。 |
| 共享原型 | Proto26 融合 P3/P4/P5 特征再生成原型，并非只从 P3 生成；32 个通道是学习得到的基底，没有被指定为“头/腿/纹理”等固定语义。 |
| 双分支梯度 | one-to-one 头输入特征 detach，传给该分支的 proto 也 detach；该分支的 mask loss 可更新自身系数头，但不能经这条路径更新共享原型/上游特征。one-to-many 提供相应共享路径的梯度。两分支损失权重还有调度。 |

源码：[本地 loss](../../shared/vendor/ultralytics_8_4_100/ultralytics/utils/loss.py)、[官方 loss](https://github.com/ultralytics/ultralytics/blob/v8.4.100/ultralytics/utils/loss.py)、[本地 Segment26](../../shared/vendor/ultralytics_8_4_100/ultralytics/nn/modules/head.py)、[本地 Proto26](../../shared/vendor/ultralytics_8_4_100/ultralytics/nn/modules/block.py)、[官方 Proto26](https://github.com/ultralytics/ultralytics/blob/v8.4.100/ultralytics/nn/modules/block.py)、[训练标签格式化](../../shared/vendor/ultralytics_8_4_100/ultralytics/data/augment.py)。

分配阶段本身计算 GT 与候选的成对质量矩阵；并非因为成对计算“必然爆炸”才不用逐对 loss，而是一个预测在该次训练中需要明确的监督目标。框当前不够好也不意味着一定没有正样本。定位失败可能涉及特征、回归、分配及输出筛选，不能把现象与某一模块写成一对一根因表。

### 后续如何用这些事实诊断

每个失败 GT 联合查看三类关系：**不看分数时有哪些好候选；官方当前分配把哪些候选作为它的正样本；正常推理实际保留了哪些候选。** 三类关系允许不同，但共享 raw ID 和 annotation_id。训练视图还需记录正样本数量/权重、GT crop 内外的错误、实际训练 mask 与原始 GT 的区别及对应梯度路径。

值得检验的具体问题是：**在已有较好 mask 候选的真实失败中，当前分配是否系统性选择了 mask 更差的位置，还是正样本本身的 mask 就没有学好？** TAL 不使用 mask IoU 是代码事实；这件事在本模型上造成了多少失败，当前尚无解耦后的完整统计。应先从已有回放检查，补齐缺失候选，不直接据此提出新匹配器或宣称新机制。

已将监督视图补入现有规范第 6.4 节。回放使用的是当前权重和指定标签批次，只反映该条件下现在会怎样分配，不能证明这些候选在预训练历史中始终有或没有受到监督。
