# 基线复现与配置一致性

**统一采用“官方评估作锚点、实际配置作合同、同协议本地基线作增量分母”。** 先用指定版本的官方权重、数据和评估路径核对发表指标，运行前冻结验收标准；方法及消融沿用这份合同，除预注册研究变量外不改变条件。官方发表值与本地复现值分别列出，论文增益相对本地同协议基线计算。

**合同记录最终生效值及来源，不能只写“默认配置”。** 按“官方说明／权重元数据／固定版本默认／调用覆盖／运行时实际值”核对差异；未公开的官方条件标为未知，不凭一次 AP 相同宣称所有条件完全相同。版本、权重和模型专属数值只维护在研究线；每个 Run 保存冻结副本、SHA、命令、完整环境与产物。

| 合同范围 | 必须冻结并核验 |
|---|---|
| 模型与数据 | 代码 commit、实际导入路径与源码哈希、依赖及设备环境、权重 SHA、模型分支与模式、数据/标注/图片清单及身份校验、拆分、类别映射 |
| 推理与后处理 | 尺寸及实际输入几何、批量和顺序、精度/数值开关、融合、增强、置信度与候选预算、抑制/排序/解码/裁剪/缩放/阈值、序列化精度 |
| 评价 | 评估器与版本、同一预测文件、匹配规则、阈值、ignore/crowd、面积来源、计数预算、单位、主指标及容差 |
| 训练与选择 | 初始化、可训练参数、样本/步数/有效批量及梯度累积、优化器/调度/损失权重与归约/增强/标签栅格化、精度/随机性、验证及 checkpoint 选择规则；官方预训练记录不自动成为新方法的训练配方 |

自写导出器/评估器先在同一输入上通过原生输出身份、数值与指标等价性核验，再用于主比较；任务专属容差在见结果前写入协议。任何非研究变量变化形成新配置身份，并补相应的同协议基线，不能直接拼表。

每个实验结束后、判定结果和推进下一阶段前，核对冻结合同、实际生效参数及产物身份，保存配置核验记录；特别核对推理几何/精度/评价器，以及训练初始化、样本顺序、有效batch、实际步数、参数白名单和冻结项前后SHA，差异未解释清楚不得放行。

官方指标复现、工具等价、某次本地结果有效性分别判定。复现未过就保留差异和真实产物，停止“官方已复现”的声明并定位差异；不得事后调参追分。有效的本地配对结果保留其配置范围，不能冒充已复现的官方基线。

## 可复制提示词

适用于新研究线建立配置规范、审计现有基线或复现官方指标。补充方括号中尚未提供的信息，其余沿用当前会话；本提示词不改变已有 Run 的冻结协议。具体模型数值写入研究线配置，通用规范只保留流程。

```text
请为 [仓库／研究线] 的 [模型、任务及官方权重] 建立可复用的基线配置合同。
目标指标及官方来源：[表格／论文／发布页；尚未给出时先查官方来源]。
本轮范围：[只读核查／完善配置规范／复现基线]；执行环境、资源预算和已有授权沿用会话，确实缺失时指出缺项。只读核查不得改文件、安装依赖或启动实验；完善规范不自动授权实验。已明确授权的工作直接完成。

目标：先建立可信的本地基线，再让方法和消融只改变预注册的研究变量。不要为了追平官方小数点扫描参数，也不要用框架默认值代替未经核实的官方设置。

1. 先读权威入口并查真实进度。
检查 Git 状态、分支、HEAD、远端、仓库规范、研究线规则和生效协议；保留未提交改动，不自动拉取合并。检查本地及指定执行环境已有的 Run、配置、日志、预测、摘要、checkpoint 和任务归属。没有 GitHub 大文件不代表没有执行；有效产物先复用，不重复启动已完成或仍在运行的任务。

2. 先查指标出处和官方权重记录，再决定复现配置。
核对官方论文／版本化文档／release、官方评估入口及源码、权重 SHA 与完整元数据。除训练参数外，还要检查训练指标、结果历史、对应 epoch、模型分支、源码 commit、保存版本和日期；版本号相同不代表源码相同。
把官方发表值、权重内记录值、本地实测值分别列出，标明任务、数据拆分、指标字段、单位和精度。区分精度评测命令与速度测试命令，区分公开复现默认值与发表那次 Run 已有直接证据的设置；未公开条件写“未知”，不能用推导值补成运行事实。

3. 沿调用链列出配置差异，确认实际生效值。
对照“官方证据 → 权重元数据 → 固定版本默认 → 调用覆盖 → 运行时最终值”，逐项列出参数、来源、作用阶段和对结果的影响；冲突要追到对应版本代码或运行记录。按本规范的模型与数据、推理与后处理、评价、训练与选择四类覆盖，不只审计一个可疑参数。
分别检查训练、训练中验证、独立验证、预测／导出入口的隐式覆盖，以及加载的模型／EMA、eval 模式、融合、精度和数值开关。标出未生效的字段，不因参数同名就认定行为相同。记录实际样本顺序、输入形状、resize 和 padding；batch 可能改变分组与预处理，不能一律当作纯吞吐参数。比较执行 batch 的影响时应固定每张图的输入；若输入也变了，明确这项变化。

4. 冻结一份主比较合同和验收标准。
在研究线保存机器可读配置及简短说明；每个新 Run 保存冻结副本、哈希、实际命令、环境和输入／输出身份。官方预训练配方、基线评估合同、新方法训练配方分别记录；冻结基础模型不自动要求重做预训练。
在见结果前固定主指标、单位、公开显示精度或可获得的未舍入值、容差及资源预算，使用现有协议门槛，不事后放宽。基线、方法、消融共用所有非研究变量；若更换评估或预处理条件，建立新配置身份并补同协议基线。不得把“官方指标复现”“自写工具等价”“本地配对结果有效”合成一个通过状态。

5. 只在授权范围内运行最短必要复现路径。
若需要新运行，先检查输入与资源，做小样本全链路 smoke，再执行官方原生入口的全量评估；依赖固定到选定版本。按需保存有效配置、覆盖率、原始预测、评估摘要和错误日志，确认全部目标样本被处理、目标评估器实际成功运行，不能把内部指标或失败后的回退结果当作官方评估结果。smoke／工程检查通过不等于完整基线达标。
只有研究问题确实需要时才增加内部特征缓存或大规模审计。自写工具在进入主比较前，先用相同输入／预测核验输出身份、数值及指标等价；不同匹配定义和指标对象分别核对。

6. 不一致时先定位第一处分歧，再做一个有判别力的检查。
先排除指标来源、舍入与单位、权重／源码／数据身份及配置记录错误；再用同一份保存预测交叉核验评估器，避免重跑模型。若差异发生在预测阶段，按同一样本的输入张量与几何 → 模型原始输出 → 后处理／序列化结果定位。选择证据最强的一个假设，写明最小对照、预期观察、预算和停止条件，再在授权范围内执行；没有判别力就不启动全量重跑。
“发现设置不同”“根据代码推导”“观察到运行差异”“对照验证因果”分开表述。同一权重、相近 AP 或静态形状计算都不足以证明完整配置等价，也不足以证明某参数就是指标差异的根因。保留失败和部分产物，后续检查优先复用。

7. 给出唯一采用的配置与有证据的结论。
交付配置合同、参数差异表、三类指标来源及三个独立验收状态，附官方链接、本地文件路径和 Run ID。论文同时标注官方发表值与本地同协议基线值，增益只相对后者计算。
如有阻塞，指出当前唯一阻塞变量及消除它的最小测量，不泛列优化建议。达到既定验收或用户明确接受的本地比较范围后完成交付；尚未通过的官方复现状态照实保留，不自动追加追分实验。只有结果形成可判定证据后才下科研结论，并指定唯一下一步。
```
