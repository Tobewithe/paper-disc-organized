# 同一对象的编码漂移是否对应真实几何漂移

这是v0结案后的唯一后继建议，尚未启动。原v0的体形码稳定性Gate失败保留，不以本建议重判为通过，不增加当前配置训练。

**我主张继续聚焦标准身体几何先验，但先检验同一对象在外观/遮挡变化下的几何不变性。** 依据是S的完整身体误差在8族上较U平均减少46.67%，同时16维体形码RMS漂移0.22384，不能直接把两者合并成“对象已稳定”或“身体变形22.38%”。

有依据的解释H_code是：给定形变基的尺度和相关性、以及体形/姿态/残差之间的补偿，使潜码数字变化较大，最终标准身体表面可能仍稳定。其支持是几何误差小而编码漂移大，以及模型确实允许上述补偿。竞争解释H_geometry是：外观/遮挡信息进入体形状态，最终身体表面也随之改变；其支持是配对编码漂移在S/U两分支都超过冻结上限。当前Run没有按两个干扰因素分开存储几何不变性统计，尚未区分这两种解释。

最小下一步只复用当前检查点和已经生成的2×2外观/遮挡组合：分别固定遮挡换外观、固定外观换遮挡，再计算潜码变化、标准姿态解码表面变化和同姿态完整身体变化。全量使用原8个留出族，不选择最好案例，不训练、不换数据或重选旧Gate。

若潜码漂移较大而标准表面稳定，且不是全部体形塌缩成同一身体，则保留S的几何输出作为原型接口，优先规划真实域对象状态对齐。若标准表面也明显变化，则优先解决体形与外观/可见性的分解，暂不投入YOLO融合。结果仍未区分时，保留未决并维持当前配置不扩训，不自动接一串诊断。正式启动该项零训练重放前另冻几何单位、非塌缩检查和继续/停止数值出口，不能按看到的结果选择阈值。

这一步比继续扩全局字典或直接增加一个Loss更值得优先：它能决定已经训练出的几何对象应怎样接入真实任务，也能避免把任意潜码坐标的变化误当成对象本身改变。
