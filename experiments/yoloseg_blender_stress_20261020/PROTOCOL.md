# YOLO-seg 合成视频压力测试：设计与首轮工程核验 V1

状态：2026-10-20，用户要求设计多种真实场景（密集、遮挡等），并通过 Slurm 申请一张空闲服务器 GPU。仅零训练渲染、推理与核验；当前 LCF 四臂训练及其它视频研究保持独立。本协议在本 Study 第一次 GPU 执行之前冻结。

## 1. 整体研究链路

| 维度 | 本次实验的整体研究链路 |
|---|---|
| 问题 | STA 原256条中原生掩码有28条实质分裂、106条跨实例混入候选；静态面板没有回答密集运动、遮挡及重新出现是否诱发持续或瞬时错误。需要带真实实例身份与几何标签的视频，区分检测丢失、类别错误、掩码连接错误和时间不稳定。 |
| 机制假说 | H：近邻/遮挡改变局部可见证据，使逐帧掩码对局部连接的控制失稳。竞争解释：合成资产域差异造成整体识别失败，或真实遮挡改变可见拓扑、检测关联及评分阈值造成表面跳变。此轮观察与成对场景对照能定位现象，不能证明固定P不可表达或全局系数耦合因果。 |
| 针对性方法 | 同资产、动画、相机、种子的成对视频，只改变指定因素。Blender几何产生全分辨率可见ID、独立投影与遮挡、持续表面点。冻结官方原生YOLO权重/版本/解码，逐帧预测不使用GT/跟踪器/平滑。GT仅离线关联和评价。 |
| 整体结果 | 执行前未知。首先报告场景有效性、检测覆盖与错误类型，不能把合成场景分数当COCO官方AP，不能把未匹配实例当拓扑正确。首轮没有新方法、没有相对旧G的增益结果。 |
| 研究决策 | 优先建设“真实可见拓扑变化与模型额外错误可分离”的成对压力测试。首轮只执行下面384帧工程核验，核验标签、原生重放、可识别性和资源，按结果确定已设计大矩阵是否适用；不训练、不扫阈值、不挑失败帧扩样。 |

## 2. 场景设计

首轮工程核验：Cow，固定种子20261020；4组×2版本×48帧=384 RGB/标签帧，12 fps，每段4秒。640×384，Cycles/OptiX、16 samples、固定渲染种子、关闭运动模糊、去噪开启。RGBA不作标签，几何标签为像素中心射线的离散可见归属。各组标签和参数先冻结，执行后检查实际遮挡率，未生成预期事件就记覆盖不足。

| 首轮组 | 控制 | 压力 | 固定项目与解释限制 |
|---|---|---|---|
| density | 4个对象 | 8个对象 | 前4对象保持相同路径；新增4对象，数目/遮挡共同构成“密度”干预，不声称独立拆分其机制 |
| crossing | 4对象分散深度通道 | 同4对象更近的深度通道相向经过 | 对象数、动画、横向运动一致；报告真实重叠及可见度 |
| wall | 挡板在所有目标后方 | 同挡板在前方 | 目标轨迹一致；前后位置会改变遮挡及阴影，不声称纯遮挡视觉因果隔离 |
| fence | 栏杆在目标后方 | 栏杆在目标前方 | 真实GT可见区域可多连通，不能自动记为模型分裂 |

完整矩阵是**设计，未获本次smoke自动执行许可**：上述4类，加同向并行、三方交错、不同类别接近、出画再进入、远小目标、平滑相机/亚像素运动、背光/低对比、密集+遮挡复合场景，共12类。建议马/牛/羊3种COCO类别、3个预定布局种子、成对版本、96帧/24fps：12×3×3×2=216段、20736帧。复合场景只评估压力，不用于单因素因果归因；非COCO动物如猪不算闭集分类错误。三种低多边形资产不代表真实世界泛化，正式矩阵须补充域有效性说明。先按工程核验实测时间估算总预算，再冻结实际矩阵，不自动启动。

## 3. 配置与数据身份

- Blender4.2.1已安装包及私有运行库，只读使用。复用旧资产导入函数，复制其源码并纳入本Study冻结；所有源资产读取已有清单并逐项SHA核对。原共享脚本/资产不改写。
- Ultralytics8.4.100；官方yolo26m-seg.pt SHA `16b636f04e8fb6a325b3370f22dc5e5535ff473e384f4d041fd28d788f6ee9f5`。使用LCF服务器已冻结的环境/profile作为只读来源，复制profile，核实际版本、源码SHA、运行数值策略。
- 原生验证入口，而非任意predict视频默认值：imgsz640、batch16、rect=true、FP32、end2end=true、agnostic_nms=false、max_det300、conf=.001、iou=.7、augment=false、原生process_mask_native及原图RLE。保存每帧真正输入H×W、batch位置、P/c0/输出身份与zero-delta重放通过记录。不把batch大小当无关项。
- .001保留完整输出；展示和固定操作点评价从同一预测离线取score>.25。两者分开；不根据结果扫描阈值。所有帧全读、不丢帧；压缩预览视频仅供观看，不作为模型输入。
- 每帧GT保留物理track ID、COCO类别、可见mask、独立目标投影、可见比例、出画比例、遮挡者、表面点投影与可见状态。所有mask与RGB同640×384网格；不将历史低分辨率标签最近邻放大当精细拓扑真值。
- 完全遮挡/出画目标不进入当帧可见分割GT，但保留事件账本；重新可见后计算检测恢复。所有可见GT包括低覆盖对象在总账本保留。

## 4. 评价

1. 正常无GT完整输出保留；操作点中使用预测框与可见GT框的类别无关一对一关联（BoxIoU>=.5，先最大匹配数量、再最大IoU，固定排序）。错误类别独立统计；GT不进入模型、不挑raw。此关联是诊断，不冒充COCO官方匹配/跟踪ID。
2. 正确类别与框关联的共同对象计算原图IoU、覆盖率、分裂量/粘连量。复用STA算法：GT真实每个连通部件内部判断多片；与邻居可见独占区、且连至自身核心的误覆盖为混入。8连通主定义，1%GT面积为实质阈值；GT真实多部件/漏部件/其它孤岛分别列出。384帧工程核验不报机制显著性。
3. 分别报告全可见对象检测缺失/错类、成功配对数、可判拓扑分母；禁止只统计检测成功对象后宣称整个系统稳定。
4. 时间：稳定三角形重心点随骨骼运动投影，相邻帧双方都可见且周围3×3 GT归属纯净时，记录其预测前景状态翻转率。分母为有效点转移及序列/实例；无匹配是检测中断，不混入掩码翻转。稀疏点只测内部覆盖抖动，**不声称完整边界抖动**；表面点缺可见性或网格身份则记不可判。检测on/off、类别切换、原图IoU时间曲线同时报告。
5. 每段输出RGB/GT/预测/错误叠加预览与逐帧账本；同时提供所有场景，示例若按严重度选择必须标注。首轮仅原生N，相对已有G/LCF的效用“未测”。后续若比较必须对同帧同配置且不改LCF已冻结COCO Gate。

## 5. 工程门槛、资源、停止

- 单次Slurm，1张A6000、4CPU、16GiB RAM、2小时上限；只在自己的新目录运行。GPU由调度器分配，不指定/挤占其它任务的卡；no-requeue，失败保留，不自动重启。无定时任务、目标模式、训练、自动提交推送。
- 启动前冻结协议、脚本、profile和输入清单。每次真实执行独立Run及原命令、Slurm/GPU UUID、环境、日志、进度、输出SHA。失败不覆盖。
- 图像/标签同尺寸、可见mask⊆独立投影、128点/帧的独立scene.ray_cast与BVH归属一致、表面三角形身份与连续投影有效、模型zero-delta RLE完全一致。几何错误或身份漂移停止工程运行，禁止改容差。
- 工程完成后报告绝对检测覆盖；如果无压力对照中的操作点正确类别Box50召回<80%，仍保留全部结果，判合成域/资产识别不足，不把该资产的掩码失败归为原型结构局限。80%是本轮预设适用性筛查，不是证明真实泛化的阈值；不按结果删除困难实例。
- 如标签/模型重放无效：修工程并保留失败版本；如域识别不足：优先改进资产真实性/数据域并另立版本；如检测充分而压力新增实质错误：可将此成对测试作为未来LCF外部评价；如未观察新增错误：在已测范围报告稳定，不加大压力追失败。唯一下一步在首轮结案时据真实结果裁决。
