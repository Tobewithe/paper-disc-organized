# 实例局部原型条件检验

前置实验为 `coefficient_data_scaling_20260924`。问题是固定系数特征 h 与全图池化原型未能在新图上复制逐实例系数 oracle 的收益时，实例**预测框内**的原型响应是否提供有用的条件信息。

沿用官方 COCO 预训练 YOLO26m-seg、Ultralytics 8.4.100，冻结原模型。按原 one2one 正样本与原始预测框，从每张32通道原型图对每个实例采样 32x32，再平均池化为4x4，即512维条件输入；标签与分割损失保持官方 replay。预测框用于条件提取，GT只进入训练损失，验证时不使用GT产生条件。

对照是 h-only、h+真实局部P、h+同图另一实例局部P、h+错图局部P。四臂采用相同的每尺度 MLP 架构及参数数目、同一训练图顺序/优化器预算，评价使用同一dev和val。对只有一个正样本的图片，同图错实例不可定义；此组在同图错实例的主比较中排除，另记录跨图回退的全量分析，不把回退称作同图错配。

主判定为真实局部P相对两个错配P在未见图像上的配对损失有稳定优势，而不是只比 h-only 或训练集分数。第一轮800图是快速机制筛查，不能单凭其负结果排除更大样本的局部P方法；如真实局部P有效，应在正式完整COCO抽样上复现，并评价最终掩码/任务指标。若各组均无收益或真实与错配无差异，不把“需要局部P”写成机制结论。第一轮四臂使用同一训练子集、归一化、训练轮数、开发集选择规则和参数量；h-only的额外512维输入恒为零。

**缓存身份纠错**：`RUN_40b7f79e476e45d7a6d64aa82c4b25f1` 的历史试跑使用的是旧 `native_bank.py` 生成的 Box50 几何匹配和160像素监督。它不能与本轮官方one2one、640像素结论合并，也不能作为本实验的主判定。正式运行必须使用 `coefficient_predictability_20260924` 的 `RUN_d2e3941a644c4cdbbf43405b3b54035f` 官方监督缓存及 `official_local_p.py`。
