# Qwen9B主导的RGB-only猪实例全属性解析 V5

日期：2026-10-28（Asia/Taipei）。本版落实[用户范围](USER_SCOPE.md)：**把真实数据视为无标签，Qwen3.5-9B从RGB自行发现实例，逐实例解析可观察属性、部位归属及关系。** 不再以已有框提供“答案中的对象”。

**我选定的路线是：覆盖扫描 → 实例身份账本 → 证据原语 → 分组属性 → 局部关系 → 合成需求。** 核心工程对象首先是“这块证据属于哪头猪”，然后才是字段数量。固定图像工具负责原图访问、裁剪、坐标映射和计算；9B负责实例发现、语义判断和请求补看。不给9B任意文件读取或自由执行Python的入口。

## 2. “所有属性”怎样变成工程规格

输出是有身份、有证据的实例记录，不是一段长描述。每组字段无论能否判断都必须存在；不能回答时填typed unknown及具体原因，不能悄悄漏字段。目录见[ATTRIBUTE_ONTOLOGY_V5.json](ATTRIBUTE_ONTOLOGY_V5.json)。

| 属性组 | 要记录的细节 | 判定与工程边界 |
|---|---|---|
| 实例存在/定位 | 当前图内实例ID、候选状态、可见范围框、可见锚点、发现视图、重复/争议组、画幅截断 | 框是模型定位候选；坐标合法不证明定位正确。半张脸/一只耳可形成未决候选，不能凭群体模式补出完全不可见猪 |
| 身体/部位归属 | 头、鼻、耳、颈、躯干背侧/腹侧、臀部、尾根/尾尖；可见肢体/蹄；每部位区域/点、可见性、owner、解剖侧别证据 | 邻猪的腿不能按最近距离分配；身体框内不必都是目标猪。解剖左右和图像左右分字段；看不出解剖侧时用visible_limb_1等临时ID，不强猜左右 |
| 支撑与姿态 | 腿部是否支撑、躯干离地/接地候选、胸腹/身体侧面支撑、肢体伸屈、背部弯曲、头部高低、站/坐/胸腹卧/侧卧/卧姿未分/未知 | 先记录可见支撑证据，再推粗姿态；顶视/遮挡下的离地高度常不可辨识。仰卧等目录外状态允许other＋证据，不强塞进侧卧 |
| 方向与观察面 | 头朝向的图像方向、头—尾二维轴、相机看到的背/侧/前/后面、轴端点与角度、侧别歧义 | 角度仅为像素平面量；头朝右不等于猪解剖右侧可见，不据二维轴恢复世界yaw/pitch |
| 可见形态/投影尺度 | 框长宽比、画面归一化位置、身体可见跨度、局部轮廓候选、同图投影大小比较 | 只从有效测量域计算；未有合格Mask时Mask面积为unknown。投影大小不是年龄/真实体长，遮挡轮廓不是完整体形 |
| 表面与标记 | 图像中的浅/深/花色、局部色斑、可见污渍/反光、外观湿润候选、可见鬃毛、耳标/标记及可读文本 | IR/强阴影下不还原真实肤色；污渍与花色不确定时保留备选。耳标文本只是可见字符候选，不能据此导入数据库标签或宣称跨帧身份 |
| 遮挡与分段 | 遮挡者类型/候选ID、被遮部位、遮挡边界证据、可见片段及归属争议、设施切割/猪间重叠 | Box重叠不直接叫遮挡；可见片段比例不等于真实遮挡率。not_visible与解剖不存在、边缘截断、被遮和未知分别处理 |
| 猪—猪关系 | 图像左/右/上/下、框邻近/重叠、局部前后遮挡、表观接触、头靠近身体等 | 像素关系与语义/三维关系分开。相互遮挡可发生在不同部位，不强迫整图遮挡关系是DAG；看似接触不保证三维接触 |
| 猪—设施/地面 | 附近地面、栏杆/墙/料槽/饮水器候选；头/蹄/躯干与其局部空间关系、支撑表面证据 | 头靠近料槽是单帧关系，不直接断言正在进食。设施ID也由RGB发现，未知遮挡者可用未决entity引用 |
| 实例成像条件 | 原始与模型实际可见像素尺寸、局部亮度/对比/边缘清晰度、压缩/模糊/阴影/过曝候选、证据可读性 | 整个框的亮度不是皮肤反射率。黑色不自动是无效FOV；Laplacian/频谱不等于物理运动速度或光学标定 |
| 证据与质量 | 每字段值/备选、可见或推断、证据view/ROI/点、方法/工具/提示词版本、未知原因、冲突、审阅状态 | 模型说observed仍是模型候选；自报0.9不是校准概率。结构校验与语义审阅分开 |
| 合成接口 | 可复现的2D条件约束、资产/姿态需求、相机/设施投影需求、外观范围、缺支持项 | 待可靠性核验后才进入对应约束；不直接把语义词映成唯一PBR/三维数值 |

真实米制体长/体重/年龄/品种/性别/健康诊断、隐藏3D关节、完整身体面积、真实遮挡率和跨帧动物身份均不作为必须强填的已知量。若存在清楚可见的局部性征/表面异常，只保存所见证据，属性推断与诊断权限另列。本版先完成静态图，不冒称视频行为和完整三维重建。

## 3. 逐字段的统一记录单元

每项属性至少包括：

```json
{
  "value": null,
  "state": "unknown",
  "authority": "unverified_model_candidate",
  "evidence_refs": [],
  "alternatives": [],
  "unknown_reason": "supporting_legs_occluded",
  "method_ref": "prompt_and_tool_version",
  "generator_use": "not_approved"
}
```

`state`分为observed_candidate / inferred_candidate / measured_pixel / unknown / unobservable；它与authority不同。measured_pixel表示对声明像素域执行了算法，不代表该ROI语义纯净或物理量已标定。值非空却没有证据引用的语义字段不进入合格记录；unknown必须给原因，unobservable表示当前输入原则上不识别该量。

部位另带`part_id / owner_instance_id / ownership_state / anatomical_role / anatomical_side`；关系带`subject_id / predicate / object_id / subject_part / object_part / evidence_refs`。有冲突时保留两个候选及争议边，不多数表决成“真值”。所有输出继承RGB、view、工具、prompt、模型SHA链。

## 4. 实例发现：不把单目标grounding冒充找全

### S0 RGB隔离

独立清单只允许`path, sha256, width, height, split`。旧实例数/类别/框等字段出现即拒绝导入，不采用“忽略部分键但整包仍传模型”。文件路径仅由宿主持有；模型获得由RGB SHA生成的匿名image_id。工具只接受image_id/view_id，不接受任意路径。

### S1 全图＋确定性覆盖扫描

先全图形成场景及猪候选，再在原图执行固定覆盖网格，要求每个区域允许0/1/多个猪候选。首个工程候选为2×2网格、相邻窗口20%窗口宽/高重叠；它是有限覆盖起点，来自原图小目标问题与局部搜索机制，不是文献证明的最优格数。实际视图尺寸、窗口与模型processor网格全部留存。

固定扫描覆盖整个画幅，即使全图模型说“没有猪”也执行，防止发现器决定自己是否还需要观察。不能只放大模型已经找到的猪，遗漏区/边缘/高密度区域也进入覆盖账本。4K原图窗口经缩放后仍很小时，触发有上限的细分/放大；插值放大不宣称恢复原来不存在的细节。

### S2 候选对账与稳定身份

每项候选带原图框/可见锚点、来源view和可见证据。宿主分配持久候选ID，属性阶段不能自行重排ID或把数组序号当身份。来自多窗口的候选先建“可能同一/明确不同/未决”的关系账本。

IoU/中心距离仅产生待核候选对，不能直接NMS掉密集邻猪。对疑似重复，9B读取原图联合裁剪及分别标明的目标上下文，回答same / different / unresolved并给同一身体证据。alias合并保留原ID、证据和历史；若A=B、B=C但A与C有明确不同证据，记录冲突，不强制传递合并。不能因身体被栏杆切开就多计两头，也不能把两头贴近猪并成一头。

报告“已接受候选数、未决候选/争议组、覆盖完成度”，不把这些相加当真实总数上界；系统仍可能漏掉全部提案器都没发现的对象。完全无可见证据的隐藏猪不生成实例。输入裁剪、采样或预算耗尽不能自动记作“已找全”。

### S3 无标签漏检复查

把覆盖网格与已归属证据叠图给9B做受限复查，允许提出新候选、撤回误检或维持unknown。复查阶段不用“本图应该有N头”的提示；不得只问肯定式“这里还有一头猪吧”。统一遍历空区、边缘与未决区域，保存找不到证据的negative候选。

单模型自检是另一观察轨迹，不是独立真值。新增、合并、拆分和消失分别记账；不以三次回答一致宣布准确率。

## 5. 属性、部位与关系的解析顺序

1. **实例证据原语。** 对每个持久ID请求同一原图中的实例裁剪和带目标标识的上下文；先找可见头/躯干/臀/肢体/支撑/遮挡边界。原图图像与编号叠图分别保留，不能把标记覆盖处当作视觉事实。
2. **身份与部位归属。** 独立记录每个可见片段的owner与歧义。头、腿和尾若可能属于邻猪，先unresolved，不能把特征更多的邻猪器官借来凑完整。
3. **属性分组。** 姿态/支撑/方向；表面/局部质量；形态/截断/可见性分别输出短卡，引用同一证据账本。全属性分组是为了避免长JSON截断和属性互相暗示，不意味着新增模型或训练。
4. **候选轮廓。** 允许9B提出稀疏点/多边形；图像边缘/交互分割算法只能辅助候选轮廓，不能以其输出宣称精确Mask。不能由Box直接计算Mask面积、部位像素率或遮挡率。像素级分割合格能力未证明时，该字段明确未完成，保留定位/属性成果。
5. **关系解析。** 对相邻/框重叠/实例提及的对象和设施取联合裁剪，分别输出像素关系、局部遮挡及表观接触。关系不只限最近一个邻居；宿主保存未展开候选对。若受预算限制筛过候选对，不宣称全体N×N关系已解析。
6. **一致性编译。** 检查引用、同一像素坐标、空值/单位、显式矛盾和字段覆盖。对“站立但无可见支撑”只标需复查，不能硬改为卧姿；解剖常识是排错线索，不是删除异常或补全隐藏部位的许可证。

## 6. 坐标和工具：计算精确与语义正确分开

接口见[TOOL_CONTRACT_V5.json](TOOL_CONTRACT_V5.json)。固定工具包括图像注册/网格、原图裁剪、坐标投影、编号叠图、像素描述量、边缘/线段候选与预算/日志；它们不调用旧检测器或标签服务。9B提出观察目标/候选坐标，宿主执行白名单工具，再把实际RGB和结果回送9B。论文中的开放Python程序路线不是本任务的必要条件。

每个坐标引用`image_id, view_id, unit, coordinate_convention, transform_id`。原图和裁剪使用连续像素边界坐标，框为xyxy半开区域，原图边界允许x=W/y=H；定位点需在有效画幅。归一化0..1000仅为当前提示词约定，必须转换后保存浮点结果；裁剪才按明确floor/ceil规则取整。不能把Qwen3-VL的坐标约定自动当所有Qwen版本的天性。

对于原图裁剪`[x0,y0,x1,y1]`缩到`w×h`，视图点(u,v)映回原图：`x=x0+u(x1−x0)/w, y=y0+v(y1−y0)/h`。变换算得精确不证明u/v指到了正确猪。0..1000的整数提案还存在原图尺度约W/1000的量化，不能靠保留小数谎称亚像素定位精度。

工具返回请求/实际裁剪、缩放、hash、原图变换和有效域；越界/退化/NaN不静默修成合法框。明确的padding裁切可限界，但须记录实际范围。EXIF方向、RGB解码、镜头/FOV/像素单位不暗改；没有RGB自身支持的相机标定不读作者解算值来补。

## 7. 9B控制器与有限预算

采用结构化action而非任意Python：`propose_instances / request_view / attach_evidence / update_attributes / propose_relation / resolve_identity / finish_stage`，宿主核schema、对象权限和预算。`finish_stage`只关闭当前阶段；覆盖、未决和字段缺项均另记，不能由模型自称完成覆盖实际未处理请求。

每图固定全图+网格开销；每实例属性开销与新增候选N相关；身份/关系复核按实际冲突候选对另计，不能继续用旧27956分母估计工作量。正式前分别冻结max_model_calls、max_tool_calls、max_input_pixels、max_generated_tokens、per_image/per_stage时间及Slurm GPUh上限。触顶输出partial_budget_exhausted和未做字段，不能丢掉困难猪或无限重试。

本地[core.py](core.py)实现RGB能力白名单、坐标/覆盖和证据记录边界；它不是已通过实际9B的完整控制器。真实9B action解析、图像回送和字段准确性须在服务器新前置核验，不以模拟回调或CPU检查冒充。模型权重、processor、解码、tool schema、分阶段prompt及实际视图同入缓存键；不能把旧场景/GT身体缓存拼进本版。

## 8. 可信度验收与会改变取舍的对照

**H_evidence：** 原图覆盖/可追溯局部观察和稳定实例账本能减少漏检、重复及器官错归属。**H_decoding：** 主要限制也可能来自冻结9B的感知解码/身份理解，工具和更细字段未必带来实用改进。原始研究支持两者均需检验，不能预设工具调用多就更准。

首先比较普通全图9B与本版完整RGB-only工作流：同权重、同原图池、预先相同总资源上限和输出定义，报告实际调用/像素/时间差；它先估计复合工程效用，不单独归因某个prompt或工具。若以后声称自适应调度优于固定扫描，须另有相同视图/预算的必要对照，不因方案中存在模块就自动追加实验。

| 验收对象 | 最少必要读数 | 决策意义 |
|---|---|---|
| 信息隔离/坐标 | 源读取白名单、原图/变换往返、schema与引用、错误保留 | 任何真实标注读取或身份/坐标链错误均工程失败，不进入全量 |
| 实例发现 | 冻结输出后新RGB盲审的可判实例召回、伪实例、合并/拆分/重复；人也无法判定的区域单列 | 找不全/归属差则优先实例发现，不扩大属性卡或全量 |
