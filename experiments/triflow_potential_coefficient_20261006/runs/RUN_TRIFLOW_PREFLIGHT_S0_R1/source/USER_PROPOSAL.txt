我更推荐这个版本，暂时叫：
TriFlow：Tri-Ownership Potential Field → Prototype Coefficient Evolution
核心链路：
\[
\boxed{
\text{Self/Neighbor/BG 连续归属势场}
\rightarrow
\text{边界流}
\rightarrow
\text{Prototype Jacobian}
\rightarrow
\Delta c
}
\]
这已经和普通 mask refinement 很不一样了。
1. GT 不再只是三分类，而是构造成“三区域势场”
对目标实例 \(i\)，GT 把局部区域分成：
\[
S=\text{Self},\quad
N=\text{Neighbor},\quad
B=\text{Background}
\]
但不直接监督：
\[
[S,N,B]
\]
而是分别计算像素到三个区域的距离：
\[
d_S(x),\quad d_N(x),\quad d_B(x)
\]
再定义两个相对归属势：
\[
\boxed{
\phi_N(x)=d_N(x)-d_S(x)
}
\]
\[
\boxed{
\phi_B(x)=d_B(x)-d_S(x)
}
\]
这两个量已经把很多信息压进去了。
例如：
\[
\phi_N>0,\quad\phi_B>0
\]
说明 Self 最近。
如果：
\[
\phi_N<0
\]
说明 Neighbor 比 Self 更合理。
如果：
\[
\phi_B<0
\]
说明 Background 更合理。
但它不仅包含类别。
因为：
\[
|\phi|
\]
还代表归属有多确定、离归属边界多远；
而：
\[
\nabla\phi
\]
天然给出边界方向。
所以：
\[
\boxed{
\text{类别}
+
\text{距离}
+
\text{边界法线}
+
\text{竞争强度}
}
\]
被统一成了一个连续对象。
这就比单纯三分类高级很多。
2. 模块不做普通 ROI Conv，而做“冲突区域建模”
我会把模块设计成三个部分：
模块	作用
Conflict Tokenizer	找真正需要修的局部位置
Tri-Ownership Interaction Transformer	推断 Self / Neighbor / BG 的连续归属势
Prototype Jacobian Compiler	把局部几何变化编译成 32D coefficient


这三个模块是一个完整方法，而不是三个外挂。
3. Conflict Tokenizer：不在整个 ROI 上平均学习
先根据当前模型找三类“争议位置”。
第一类是当前 mask 边界：
\[
|z_i(x)|\approx0
\]
第二类是实例竞争位置：
\[
|z_i(x)-z_j(x)|\approx0
\]
即自己和邻居都觉得这个地方像自己。
第三类是 prototype 高信息位置。
对于：
\[
G=P^\top P+\epsilon I
\]
定义局部 leverage：
\[
\ell(x)=p_x^\top G^{-1}p_x
\]
它表示：
在这个位置改变响应，对32维 coefficient 有多强的辨识力。

最终不是均匀取 16×16，而是从：
\[
\boxed{
\text{边界不确定}
+
\text{实例冲突}
+
\text{prototype高杠杆}
}
\]
里选例如 64 个 token。
这个就已经比“ROIAlign→Conv”更有针对性。
Mask Transfiner 的一个核心发现也是：真正决定高质量 mask 的往往只是少量 error-prone 区域，而不必重新处理完整稠密 mask。开放获取计算机视觉论坛
4. Token 本身也不是普通视觉特征
一个位置 \(x\) 的 token：
\[
t_x=
[
F_x,\;
p_x,\;
\nabla p_x,\;
z_i,\;
z_{N1},z_{N2},\;
\nabla z_i,\;
x_{rel},
h_i
]
\]
这里包含：
- 局部视觉特征 \(F_x\)
- 当前 prototype vector \(p_x\in\mathbb R^{32}\)
- prototype 的空间变化 \(\nabla p_x\)
- 当前实例响应
- 最强两个邻居响应
- 当前 mask 法线
- 实例内相对坐标
- 当前实例 query/hidden \(h_i\)
也就是说 Transformer 看的不是：
“这里长什么样？”

而是：
这里长什么样、当前实例怎么解释它、邻居怎么解释它、以及这个位置在当前 prototype basis 里能怎么改变 mask。

这才真正把 \(P\) 放进推理机制里。
5. Tri-Ownership Interaction Transformer
这里也不应该把所有 token 混起来普通 self-attention。
我会设计三类对象：
\[
Q_S,\quad Q_N,\quad Q_B
\]
其中：
- \(Q_S\)：当前实例 token
- \(Q_N\)：由与当前框重叠的 top-K 预测实例聚合出来
- \(Q_B\)：背景 context token
每个局部 token 同时向三个 ownership token 做 cross-attention：
\[
a_S(x),a_N(x),a_B(x)
\]
但最终不是直接 Softmax 三分类。
它输出：
\[
\boxed{
\hat\phi_N(x),\quad
\hat\phi_B(x),\quad
w(x)
}
\]
其中：
\[
w(x)
\]
是这一位置的可信度 / stiffness。
因此网络真正学习的是：
当前像素相对于 Self，究竟离 Neighbor ownership 更近多少；相对于 Self，离 Background ownership 更近多少。

而不是：
“这个像素类别是什么。”

6. 更有结构的损失：Potential + Direction + Ordering
GT 已经有：
\[
\phi_N^*,\phi_B^*
\]
所以第一项：
\[
L_{pot}
=
\rho(\hat\phi_N-\phi_N^*)
+
\rho(\hat\phi_B-\phi_B^*)
\]
用 SmoothL1 即可。
但是仅拟合数值还不够。
方向损失
因为：
\[
\nabla\phi^*
\]
就是 ownership boundary 的法线信息。
因此：
\[
L_{dir}
=
1-
\cos
(\nabla\hat\phi,\nabla\phi^*)
\]
它要求模型不仅知道：
谁是谁。

还要知道：
边界应该朝哪个方向。

更重要的是局部次序损失
沿真实边界法线取：
\[
x^-,
x^0,
x^+
\]
比如从 Self 穿过边界进入 Neighbor。
应满足：
\[
\phi_N(x^-)
>
\phi_N(x^0)
>
\phi_N(x^+)
\]
因此可以定义：
\[
L_{order}
=
Softplus[m-(\phi^- -\phi^0)]
+
Softplus[m-(\phi^0-\phi^+)]
\]
这实际上是在训练：
\[
\boxed{\text{局部 ownership 的正确变化方向}}
\]
而不是单独预测一个 label。
我觉得这比简单 CE 有研究味道很多。
7. 最关键的一步：从势场导出“边界流”
当前 mask：
\[
z_i(x)=p_x^\top c_0
\]
它的零水平集：
\[
z_i(x)=0
\]
就是当前预测边界。
对于边界点 \(x_k\)，根据预测 ownership potential，可以沿当前法线：
\[
n_k=
\frac{\nabla z_i(x_k)}
{\|\nabla z_i(x_k)\|}
\]
寻找预测的 ownership transition。
例如从当前位置沿 \(n_k\) 找到：
\[
\hat\phi_N=0
\]
或者：
\[
\hat\phi_B=0
\]
对应的最近交点。
得到一个 signed displacement：
\[
\boxed{\delta s_k}
\]
含义非常明确：
\[
\delta s_k>0
\]
边界应该向外扩；
\[
\delta s_k<0
\]
应该向内缩。
同时我们知道它是在：
\[
Self\leftrightarrow Neighbor
\]
还是：
\[
Self\leftrightarrow Background
\]
之间移动。
这已经变成一个真正的 Ownership Flow Field。
8. 不是让网络预测 \(\Delta c\)，而是用 shape derivative 编译
这部分是我觉得最值得做成方法核心的地方。
对于隐式边界：
\[
z(x,c)=0
\]
如果边界沿法线移动：
\[
\delta s_k
\]
一阶 shape derivative 给出：
\[
\delta z_k
\approx
-\delta s_k
\|\nabla z_i(x_k)\|
\]
另一方面：
\[
z=P c
\]
所以：
\[
\delta z_k
=
p_{x_k}^{\top}\Delta c
\]
于是每个局部边界运动直接生成一个 coefficient 线性约束：
\[
\boxed{
p_{x_k}^{\top}\Delta c
=
-\delta s_k
\|\nabla z_i(x_k)\|
}
\]
这个非常漂亮。
网络说：
边界这里应该向里移动 3 个单位。

prototype Jacobian 负责回答：
那32个 coefficient 应该怎么共同变化。

网络完全不用学这个矩阵变换。
9. Neighbor 和 Background 还能产生第二组约束
在边界以外再取 region-anchor token。
如果预测为 Neighbor，则要求：
\[
z_i'(x)-z_N(x)
\le -m_N(x)
\]
如果预测为 Background：
\[
z_i'(x)
\le -m_B(x)
\]
如果 Self：
\[
z_i'(x)
\ge m_S(x)
\]
而 margin 不用固定死。
可以直接由 ownership potential magnitude 决定：
\[
m(x)=g(|\hat\phi(x)|)
\]
也就是说：
越确定属于 Neighbor/BG，要求当前实例退得越明显。

所以势场同时决定：
\[
\boxed{
\text{移动方向}
+
\text{移动距离}
+
\text{最终归属 margin}
}
\]
这就比三分类丰富很多。
10. Prototype Jacobian Compiler
把所有约束堆起来：
\[
A\Delta c=b
\]
其中 A 的每一行来自：
\[
p_x^\top
\]
或者 prototype 的空间 Jacobian。
由预测置信度：
\[
W=\operatorname{diag}(w_k)
\]
进行加权：
\[
\Delta c
=
\arg\min_d
\|W^{1/2}(Ad-b)\|^2
+
\lambda d^\top Gd
\]
其中：
\[
G=
P_R^\top P_R+\epsilon I
\]
最终闭式解：
\[
\boxed{
\Delta c=
(A^\top WA+\lambda G)^{-1}
A^\top Wb
}
\]
只是一个 32×32 系统。
这里我甚至不想叫它 solver。
更适合论文叙事的名字是：
\[
\boxed{\textbf{Prototype Jacobian Compiler}}
\]
因为它在做：
把局部几何语言“编译”为 coefficient 语言。

11. 训练时再加一个真正重要的闭环
不能只训练：
\[
L_{pot}+L_{dir}+L_{order}
\]
否则又可能出现：
势场预测挺准，但最终 mask 没改善。

所以 Compiler 必须在计算图中。
\[
\hat\Phi
\rightarrow
\delta s
\rightarrow
A,b,W
\rightarrow
\Delta c
\rightarrow
c_1
\rightarrow
Pc_1
\]
最后：
\[
L_{task}
=
L_{mask}(Pc_1,Y_i)
\]
于是：
\[
\boxed{
L=
L_{pot}
+
\lambda_dL_{dir}
+
\lambda_oL_{order}
+
\lambda_tL_{task}
}
\]
但四个 loss 不是随意拼接。
它们对应非常明确的层次：
\[
\text{势场值}
\rightarrow
\text{势场方向}
\rightarrow
\text{局部拓扑次序}
\rightarrow
\text{最终 coefficient 效用}
\]
