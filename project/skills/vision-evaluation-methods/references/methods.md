# 错误诊断与成本测量的方法知识

## TIDE：用理想修正观察错误的影响

TIDE区分跨类别误分、定位错误、两者同时错误、重复检测、背景误检和遗漏GT。对某类错误作理想修正，计算`ΔAP = 修正后AP − 原AP`。每类修正从同一原始预测出发，避免逐类累积引入顺序偏置；不同修正存在交互，各类ΔAP不可直接相加为唯一的AP损失分解。

错误计数与AP影响不同，因为分数排序、误检和遗漏共同影响指标。总AP变化很小，也可能掩盖不同错误的增减。oracle的结果用于识别可能值得处理的错误，不是已经实现的修复收益，也不独立证明训练原因。

使用固定版本TIDE时需保留以下区别：

- `evaluate`默认在IoU50分析。`evaluate_range`计算多阈值AP，但错误分析在指定的`pos_threshold`上进行。GT75问题应明确使用相应阈值，默认dAP50不是AP50:95的贡献。
- `BOX`和`MASK`模式的定位错误分别由框IoU和Mask IoU定义。Mask定位错误不直接说明框退化。
- 单类任务的跨类别误分项可能恒零，分数下降、阈值筛除和排序变化仍可能影响AP；要同时观察原分数、排名和几何覆盖。
- bbox使用`[x,y,width,height]`，Mask使用多边形或COCO RLE。保留画布、图像与实例身份、零检测图、空Mask、ignore、分数和顺序，并核对maxDets及匹配口径；默认每图上限为100。
- Missed GT oracle改变有效GT分母，没有生成新检测。其dAP不代表模型已能找回遗漏实例。

先核输入转换和原评价是否一致。若基础AP有差异，检查匹配、ignore、截断与格式等条件，保留原任务评价的身份；按尺度、来源和配对运行比较错误变化，避免用总量掩盖局部损伤。

## 成本测量：定位开销与测量实际速度

Profiler用于找出时间花在哪里，正常基准用于测量实际推理成本。分别执行这两项观察，可以控制记录工具本身的开销。

Profiler记录CPU与CUDA活动及有意义的命名范围。self时间与包含子调用的total时间需要区分，嵌套算子的total时间不能重复累加。并发CUDA工作应结合时间线分析，算子耗时之和不一定等于端到端墙钟时间。

正常基准固定设备、线程、输入与数据驻留条件，明确计时是否包含数据传输、预处理、模型与后处理。冷启动和预热状态分别报告；预热后重复测量，报告中位数和波动。CUDA操作异步，应使用正确同步的墙钟计时，或明确只测设备区间的CUDA Events。PyTorch Benchmark Timer提供预热、线程设置及必要同步支持。

PyTorch 2.5中的shape与stack记录会带来额外开销；shape记录还会暂时持有Tensor引用。`with_flops`只估算部分算子，如矩阵乘法与2D卷积，不能默认它给出了完整模型FLOPs。

`max_memory_allocated`表示Tensor峰值分配显存，测量前可重置峰值统计。allocated、reserved和Profiler分配事件总和是不同口径，应分别解释。Slurm作业总耗时也包含作业过程中的其它活动，不能单独用来声称网络结构更快。
