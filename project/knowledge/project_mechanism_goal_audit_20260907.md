# 项目审查：共同失败机制目标与当前执行是否一致

日期：2026-09-07。用户要求按开放根因发现、跨架构对照、证伪与混杂控制审查现有项目。本轮为主控依据本地证据所作的审查，不是外部模型审稿、方法验收或新实验授权。

审查参考了当前 ARIS research-review Skill 的上下文收集要求；其 Gemini review_start/review_status 在当前可用工具中不存在，因此未运行该外部审稿流程，也不声称 cross-family 接受。没有借本轮审查评价 ARIS 与 AI Scientist-v2 官方能力的优劣；用户提供的比较用作风险清单，未作为已验证事实。

## 核心判断

项目已经建立了有价值的失败分类、跨数据集描述和 YOLO26 输出阶段诊断，且多次明确拒绝把 oracle 恢复当作根因证明。项目不是从零开始，也没有实际进入堆模块阶段。

但“发现密集遮挡实例分割的共同深层原因”尚未形成完整执行闭环。当前工作集中在一个固定 YOLO26 checkpoint 的候选/掩码/筛选路径；文献中的多个机制族没有转化为具有不同预测、可区分实验和明确状态的竞争假设。另一个实质问题是状态恢复失真：旧跨架构结果和调整混杂因素的统计已经存在记录，却没有被当前简报可靠接入，部分原始分析路径也已失效。

因此当前定位应是：已有较扎实的症状和部分阶段证据，正在寻找机制；尚不能宣称找到跨架构共同根因。

## 已有证据必须保留的价值与边界

1. R012 全量外部数据：4,858 图、27,745 GT；含旧 PigLife 后 YOLO 基线覆盖 5,284 图、32,219 GT。失败类型分布扩大样本后总体稳定。这是症状分布的稳健性，不证明共同机制。
2. 原始候选严格质量完成范围为 PigLife/Faro 586 图、6,226 GT；不能把全量外部最终输出写成全量内部机制诊断。
3. 固定 conf .05 下扩大 Top-K 对当前 trace 无效，能限定一个具体操作，不等于排除所有选择/排序机制。
4. Faro 307 个 raw 严格质量缺失失败中 37 个框支持不足、270 个支持可行而无合格 mask。它排除了“270 个都因为任何框也包不住”的解释，没有定位 feature/prototype/系数或证明框定位已经良好。
5. 当前 YOLO26 记录为 end2end=True。既有 score/Top-K 重放不执行通常的重叠 NMS；外加 Mask-NMS 是诊断对照。不能套用所有 YOLO 都经历同一 NMS 的通用流程。训练 assignment 也不应直接插入单次推理流程作为已经观测的一层。

但两个旧分析目录与 20260827 重建目录在记录位置均未找到；本轮没有重新复算三模型逐 GT 数据。因此上述联合计数和回归属于已读历史归档证据，尚未在当前 ARIS 路径下重新验收。

旧归档明确分析 score >= .50，并加入 purity>=.50 AND coverage>=.10 弱关联；当前一级分类 score 门为 .05 且只用核心边。数字不同不能直接解释为模型或样本变化。

### B. 混杂控制并非空白，恢复和扩展才是任务

旧 20260827 归档记录以 R=0..3 为响应，控制 log GT 面积、图像边缘距离、单图 GT 数及接触交互项，并用图像聚类标准误、Firth、置换和 bootstrap。它支持调整后的统计关联，不能被概括成“只看 density 与失败相关”。

同时归档记录置换成功 854/1,000、bootstrap 成功 530/1,000。若要用于论文，须恢复失败原因和成功重复的选择影响；不能只引用 OR/p 值。这里没有把旧统计重新认证，也未宣称新的因果效应。

### C. R005c 最新审计不是通过，也不再只是运行中

`experiments/yolo26_confidence_audit_20260907_v2/audit_results.json` 已存在，generated_at 为 2026-09-06T18:20:36Z，`deterministic_verdict=fail`。文件同时写 `acceptance_status=accepted`，二者冲突。具体异常包含 stage flags/source mapping 核对失败，以及置信度集合 expected=actual=10,166，但 missing=7、unexpected=7。COCO 重算 mismatch 列表为空不代表整体审计通过。

这可能来自审计实现/口径或被审计产物；本轮没有定位原因，因此不能直接判定原结果错误，也不能忽略 fail。此前“12 恢复、269 退化”应保留为原计算的结果、附待澄清审计限制，不作为已通过独立完整性审查的定案证据。R012 另有独立的固定最终预测核对范围，不被自动判为失败。

### D. 项目状态没有可靠反映科学知识状态

官方 run 仍为 idea-discovery running、method Gate BLOCKED，这个科学阶段合理；但 FINAL_PROPOSAL/REVIEW_SUMMARY 仍保存“具体评分器、实施批准”旧表述，gap_map 保留大量历史下一步，R005c 又滞后于实际 fail 回执。旧 findings 中后续修复没有覆盖上层状态，导致 agent 可能重复解决旧问题。

当前风险不只是探索线性，也是恢复项目时将旧状态当作当前事实。应标明历史方案和已被替代的限制，而非删除历史证据或把更多文件数当作研究进度。

## 对用户叙述需要补充的三点

1. 多架构在同一 GT 失败提升共同机制假设的价值，但不能证明它们在同一内部环节失败；训练数据、标注、有效尺度和难度分布共享也能产生共同错误。必须同时比较共同失败和架构分歧样本，不能只筛三模型交集。
2. 某一层 probe 分不清实例，可能是 probe 能力、表示坐标或测量不足；“最早测不到”不自动等于“信息不可逆丢失”。跨架构比较应对齐功能与测量，不强迫网络层一一对应。
3. 单帧困难与任务不可辨识不同，多帧增益也可能来自平滑或更大计算量。需确定同一任务/GT，并加入适当对照。合成密集场景、邻居抹除和 oracle 支持也可能引入新图像分布或标签信息，只能回答明确限定的干预问题。

## 下一轮建议：恢复已有证据后，再让假设竞争

以下是供讨论的审查建议，不是已接受的方法路线、实验合同或后台任务。

优先级 0：澄清 R005c 的失败回执；恢复旧三模型逐 GT 表与调整统计，必要时从已存在预测重新生成。先明确旧/新 score 与关联图规则，分别报告或做预定敏感性，不能混表。

优先级 1：利用已有 literature_landscape 和 gap_map 补齐机制维度，而不是机械要求几百篇。每个机制族需有关键原始文献、反例/限制、适用标注、混杂与可区分预测；当前 27 个 Wiki 页和四份本地 PDF 既不说明文献充分，也不说明除此之外从未阅读过全文。

每个实验运行前写清：A 与 B 假设预期出现什么不同现象、什么结果削弱当前假设、干预本身是否成功、失败后返回哪个尚未排除的假设。支持/部分支持/反证之外必须允许未检验和不可判定，不能把没观察到收益一律判为证伪。

先形成机制证据再设计方法的两阶段划分合理；是否拆成两篇论文取决于诊断本身的概念、可复用性和验证贡献，不由 workflow 阶段数决定。本次不改题、不选新模块，也不自动重新训练所有模型。

## 当前可说与不能说

可说：固定 YOLO26 在三数据集的失败分布不同；扩充 Faro/Bama 样本后一级结构总体稳定；既有跨架构历史分析显示共同与分歧病例；部分输出阶段/框支持条件已被限定。

不能说：密集遮挡共同根因已经找到；某个 feature/assignment/mask 模块已被证明负责；所有共同失败共享同一原因；特定模型改进或泛化已得到验证。

本轮记录与修正的是证据状态和审查结论，不修改原预测、分类规则、旧审计回执或任何模型参数。
