# 运行登记与本地 / GitHub 协同

适用跨研究线的新运行与回传；不回填或迁移旧 Run。当前任务路由见 [ACTIVE_PLAN](../ACTIVE_PLAN.md)，评价身份见 [候选身份与评估口径](候选身份与评估口径.md)。

## 单一事实来源

| 问题 | 唯一事实来源 |
|---|---|
| 现在做哪个阶段 | ACTIVE_PLAN；其它独立研究线按用户选定入口 |
| 怎么跑、什么算通过 | 该 Run 启动前冻结的 protocol + 执行合同及 SHA |
| 是否真的运行/完成 | 执行端 run.json、原始日志、退出状态和产物 |
| 为什么继续或停止 | DECISION.json 的来源 Run、Gate、证据与后继动作 |
| 文件在哪里、是否回传 | artifact manifest；GitHub 缺文件不表示本地未执行 |

## 开始、冻结、运行、交接

1. 本地先读 git status / 分支 / HEAD 和当前入口，核实已授权环境中的既有 Run、进程及产物。发现同阶段正在运行则接续状态核查，不另起重复任务；不能据旧服务器名自动连接。
2. protocol 与执行合同先完成冻结项；记录 code_commit、dirty_patch_sha（如有）、protocol_sha256、input_manifest_sha256、baseline_run_id、环境和资源上限。不得只记 main/latest。工程 smoke 与正式 Run 使用不同身份和状态。
3. 真正开始执行时才分配 run_id、创建 runs/<run_id>/；记录 executor、started_at、command/参数文件、日志路径与当前 stage。训练、重试、重算为独立 Run，通过 parent_run_id / retry_of 关联，不覆盖旧结果。
4. 同一工作副本启动器应原子获取本地阶段锁（含 study/stage/run/host/process 信息）。跨机器执行靠明确的单一 executor 交接，GitHub 文件不是分布式锁。疑似过期锁先核实进程和交接，不盲删。
5. 结束记录 ended_at、exit_code 和真实终态。有效终态后才更新 SUMMARY / DECISION 和总控；上传中断只改变 transfer_status，不能改写 execution_status。
6. 提交轻量交付包，检查无凭据和意外大文件；远端 HEAD 已变化时读取差异后合并，不强推覆盖用户或另一代理改动。拉取也不以 reset --hard 清掉用户工作。

## 最小字段与状态（示例结构，不预创建假 Run）

- run.json：study_id、run_id、stage_id、protocol_path/sha256、code_commit、baseline_run_id、started_at/ended_at、executor、command、execution_status、exit_code。
- EVAL_CONTRACT：按候选身份规范记录模型/数据/预测/decoder/单位/匹配等；训练和 oracle 再加所属阶段要求。
- SUMMARY.json：指标值、unit、numerator/denominator、population、来源文件；未计算值为 null，不用 0 代替缺失。
- DECISION.json：gate_id、passed/failed/blocked/unadjudicated、evidence_refs（路径+SHA）、reason、claim_scope、next_action。
- ARTIFACT_MANIFEST.json：每项 relative_path、sha256、size_bytes、role、storage_scope、availability；大文件本地定位不含密码、token 或有凭据的 URL。

分别记录 plan_status、execution_status、scientific_status、artifact_status、transfer_status；不得用一个 completed 同时表达五件事。历史 study.json 的旧 status 字段保留兼容性，不据此猜新执行状态。

## 回传范围

提交：冻结协议/参数、真实命令与环境版本、run 元数据、SUMMARY/DECISION、精简 REPORT、校验日志、文件散列清单、必要的小型样本与表格。原始 COCO、checkpoint、特征张量和大型逐 GT 表留执行端，按清单追踪。SHA 只能证明取得文件后的内容一致，不能证明文件当前可访问。

若结果已存在本地，优先核对和回传；缺失历史缓存只阻断依赖该缓存的主张。正式大评估是否需要重跑由合同兼容性和必要输入决定，不为了补齐 GitHub 目录而重跑。

## 修改边界

当前未冻结计划可修订，必须记录改了什么及原因；已经冻结或跑过的协议不覆盖，创建新版本并写 supersedes/reason。新结果只写所属 Run 的新产物与决策；历史结果、阴性、其它论文线和工作台数据库保持独立。不在旧长日志继续追加最新执行命令。

交接至少回答：当前阶段、已完成的真 Run、尚缺的确切文件/冻结项、被允许的单个下一动作、预算和停止条件。提交成功只是回传完成，不是科学 Gate 通过。
