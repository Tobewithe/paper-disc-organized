# 候选身份与评估口径：可执行通用契约

**适用：** YOLO/COCO 的正常输出、GT 任务失败、raw oracle、固定预测修复、候选身份与跨 Run 对账。训练 TAL 属于**可选、独立的科学对象**，不能因研究 Mask 失败而自动启用。当前主线与阶段入口始终从 [ACTIVE_PLAN](../ACTIVE_PLAN.md) 进入。本文件只定义身份和评价真实性，不增加模型训练任务。

## 1. 六个不能相互代替的对象

| `candidate_policy` | 对象与用途 | 严禁冒充 |
|---|---|---|
| `inference_output` | **无 GT 正常推理保留的最终检测行**，COCO AP/GT 任务失败/实际可部署方法 | 全 raw 能力 |
| `fixed_output_detection`（旧称 `fixed_output_slot`） | 固定一条最终检测的 Box、Mask、类别、分数、预测框裁切，用它自己的 BoxIoU/MaskIoU 诊断 | 官方独立 bbox/segm 两次 GT 匹配是同一条检测 |
| `raw_all` | 指定分支所有预筛选 raw，GT 辅助潜力/存在性上界 | 实际输出成功率或 AP |
| `raw_argmax_correct` | raw 最高预测类别与 GT 一致的诊断子集；**不附带 conf/Top-K 条件** | 官方 O2O 的默认类别输出规则 |
| `legacy_geometry_hungarian` | 用 GT 框挑选的几何候选/旧匹配总体 | TAL 正样本、正常无 GT 推理 |
| `official_tal_replay` / `actual_train_assignment_event` | 冻结 checkpoint 重放的 TAL 正样本 / 真实训练步骤记录 | 互相代替、推理后的 COCO GT 匹配 |

**后训练的 GT 标签关联**（`training_box_gt_join`）是另一个明确声明的监督规则：在 train2017 已冻结的*最终输出行*上，根据类别、Box IoU、分数顺序等预注册规则建立监督 GT，供新增 adapter 计算 Mask loss。它**不是 TAL**，推理时不能从 GT 取目标、候选或 gate。

## 2. 固定 Ultralytics v8.4.100 的真实 O2O 输出

以真实源码/调用为准：`head.end2end=True` 走 O2O，`end2end=False` 走 O2M+NMS。此版本 `cfg/default.yaml` 的 `nms=False` 仅用于模型导出 NMS 融合设置，**不能据此推断原生 `model.val` 的 O2O 分支**。

Head 的 `agnostic_nms=False` 默认 O2O 路径如下（`K=head.max_det`，COCO 正常 K=300，原 raw 总数取决于实际输入 H×W/网格）：

1. 各 raw 的 80 类 sigmoid 分数：按照**每 raw 最高类别分数**取前 K 个 raw。
2. 保留这些 raw 的**全部类别分数**，展平为 raw×类别，从中再选分数前 K 的**组合检测行**。
3. 每个组合行保留类别/分数，并通过可重复的 `raw_id` 取**同一 raw 的框和 Mask 系数**；多个类别行可以使用完全相同的框与系数。
4. `non_max_suppression(end2end=True)` 对**已经选择的组合行**执行 `score>conf`，不跑普通 NMS 的 `multi_label` 展开。故关闭普通 NMS `multi_label` **不能**把 O2O 变成每 raw 单标签。
5. v8.4.100 原生 `BaseValidator` 在 E2E 路径会向 Head 传递 `args.agnostic_nms`。若 **`head.agnostic_nms=True`**，Head 转为**每 raw 取最高类别→单次 Top-K**。需要同时记录真实 Head 属性和验证器参数，不仅记录参数名。

详情与官方发布权重/性能核验：[源码审计](../audits/candidate_eval_20261012/O2O_TOPK_OFFICIAL_COCO_BASELINE_20261013.md)。**同 raw、同 Box、同 Mask ≠ 仅一条 COCO 检测记录**。

## 3. COCOeval GT 任务与“同一检测的 Mask”两套视角

**任务标签**：以冻结的无 GT 最终预测 JSON，COCO val2017 原始 annotations，`useCats=1`、`areaRng=all`、`maxDets=[1,10,100]`、`IoU=.50:.05:.95` 为准。一个有效普通 GT 的 `Mask75` 成功仅表示 **segm `COCOeval.evalImgs` 的 `gtMatches[.75,g]` 有非忽略匹配**；`Mask75` 失败表示无此匹配。crowd、ignore、area 排除要按照 COCO 规则记账，不能当普通失败。逐 GT 成败比例 ≠ 类别宏平均 AP75/AP。

**任务匹配独立**：bbox 和 segm 在**同一份最终检测集合**上分别执行匹配，可能得到不同的 `bbox75_match_output_id` 与 `segm75_match_output_id`。二者都成功不意味着存在一条同时 Box75+Mask75 的检测。内部 Ultralytics `match_predictions` 的 TP 也不能冒充外部 COCOeval 的 `gtMatches`。

**同条检测诊断**：只有先以确定规则锁定 `d_b`（例如 COCO bbox75 关联的唯一预测），再用它自己的预测框与 Mask 算 `BoxIoU(d_b,g)`、`MaskIoU(d_b,g)`，才能说这条检测“框好/Mask 差”。`exists_same_output_joint75` 是 GT 级存在性，若未做一对一匹配不称官方召回；`raw_all` 最佳框与最佳 Mask 不得来自不同 raw 却拼成联合成功。

**面积/ID 口径**：固定 `predictions.json` 原始顺序、预测 ID 与导出散列。v8.4.100 原生 COCO `loadRes` 在含 bbox+segmentation 的 JSON 中优先用 bbox 算**检测 area**，segm IoU 仍用分割 RLE。做原生 bbox/segm 后端一致性复核时应对**相同完整 JSON**切换 `iouType`，不要擅自从 segm 输入删除 bbox，否则 AP_S/M/L/ignore 面积口径变了。若需 mask-area 专项诊断，另起辅助结果，不冒称 native parity。COCO JSON 原本无 raw_id 时，填 `raw_id=null`；不可从 COCO 检测 id 反推。

## 4. 身份和最小评价合同

**最终输出检测**主键：`checkpoint_sha, image_id, branch, input_hw, letterbox_policy, source_prediction_sha, output_detection_id, category_id`；相关 `score, bbox, segmentation/RLE, decoder, detection_ordinal, raw_id_if_traced` 作为字段。同 raw 跨类别检测必须保留两个不同 `output_detection_id`。

**raw** 需 `checkpoint_sha, image_id, branch, input_hw, letterbox_policy, pyramid_level, raw_id_global, grid_y, grid_x, stride`。GT 关系另外加 `annotation_id, relation_policy`；同 `annotation_id` 不意味着同 raw；P3/P4/P5 offsets 从真实 tensor shape 算。训练 TAL 独有 `owner/target_gt_idx/loader_version`，只在该对象相关时要求。

**每 Run 最小 `EVAL_CONTRACT`**：真实 `study_id, run_id, model/checkpoint SHA, source code revision, ultralytics file path/version, dataset/GT SHA, image manifest SHA, branch, actual input H×W policy, output decoder, candidate_policy, eval unit, main metric/threshold, baseline source, gate/stop path, artifact SHA`。若是**训练**才额外要求 fit/dev/confirm 清单、可训练参数白名单、优化预算与泄漏边界；若是 **raw** 才要求 raw manifest；若是 **TAL** 才要求分配/标签/criterion 元数据。**不要让不相关字段阻止一个正常输出 COCO 评估**；缺失的核心身份值记 `unknown` 并阻断其对应声明，不伪造。

## 5. 按命题激活 Gate，而非一切 Study 都跑全层

- **G0 输入和对象合法**：固定权重/数据/版本/分支/COCO 类别/预测集合/身份；COCO `is_coco=True`、80→91 类别映射与真实5000图片先预检。错则停，不用替代数据悄悄补位。
- **G1 本对象基线一致**：同一输出 `delta_c=0` 真实 Mask/RLE 与冻结 A 基线一致；若研究同一旧 raw 的数值重放，使用该历史 Gate 已登记的 `≤1e−6` 等容差；**不能把 raw 对比容差强行套在没有 raw 的 GT 账本上**。
- **G2 COCO/匹配合法**：有效 GT 计数、同一完整 JSON 双评价器 parity、预测行 ↔ 检测 ID、独立 bbox/segm 的 matched IDs 与 ignore/预算正确；失败只修评价实现，不做科学推断。
- **G3 数据和选模**：训练才要求 fit/dev/确认隔离；小样本烟雾不能变成正式发表结果，历史反复使用 val2017 不称盲测；样本和阈值不看结果后换。
- **G4 实用结果**：声称后训练改善部署 Mask，必须在冻结无 GT 正常最终输出下报告配对 COCO segm AP、原成功损伤、原预测 Box/Class/score/order 保持以及成本；oracle 不冒充方法。
- **G5 决策和停机**：每 Run 给 ``passed / failed / blocked / unadjudicated` 与来源；未过预注册科学门槛即停止该配置，不继续扫参数或堆多个模块。不同 Study 若也用 G0–G5 作为阶段名，其**数值门槛以该 Study 启动前冻结的 protocol 为准**，不套本节默认编号。

## 6. 历史与基线差异的合法用法

- 固定预训练模型 SHA 与官方 GitHub 发布的相同；官方 COCO val2017 640 E2E Box/Mask AP `52.5/44.1`，历史自定义 raw 导出 `51.980/43.518`；**尚无本会话实际原生 `model.val` parity Run**。`published_baseline_parity` 与 `native_gt_ledger_validity` 两个状态独立，不许互相代替。
- 历史 `Mask75 22767` 与另一旧报告 `22773` 属于不同输出/解码协议；不能静默按六个 GT 的差别覆写其中一份。当前 [GT 任务账本协议](../../experiments/official_gt_failure_rebaseline_20261013/PROTOCOL.md) 要求逐 GT 对账。
- 历史 E0 几何 Hungarian/TAL 强制重放只约束旧研究的证明责任，不成为当前固定权重后训练的前置；只有真正提出 TAL 假说才看 [可选 TAL 训练轨迹](../audits/candidate_eval_20261012/TAL_TRAINING_TRACE_PROTOCOL.md)。
- 历史 Run、旧封存协议、阴性试验、模型权重、COCO 数据和缓存**不可因规范更新而回填或覆盖**。仓库 GitHub 镜像缺 raw/权重/GT 大表不是事实缺失的证据；先在用户已授权设备检查实际运行状态。
