# 候选身份与评估口径：跨研究线强制契约（2026-10-12）

适用于新 YOLO26-Seg／COCO 实验及历史实验跨候选、跨分支、跨评价的科研解释；历史 Run 不覆盖，研究线协议可补充，不得跳过 Gate。

**适用性修订：** 本文件罗列的 raw/TAL/输出视角与 G0–G5 是条件 Gate，不代表每个实验都必须生产全套指标、缓存和图表。先按 [指标最小化与 TAL-GT 分类](指标最小化与TAL分类.md) 确定研究命题唯一主评价，再只执行相关分支。官方 YOLO26 默认推理分支依实际版本与 Run 调用核实，不能默认认为 one-to-one 是官方默认输出。

## 2026-10-13 补充：YOLO26-Seg 8.4.100 O2O 类别筛选（强制检查）

**默认 `head.end2end=True, head.agnostic_nms=False` 的 one-to-one 推理绝不是“raw 先取唯一 argmax 类别，再对各 raw 的最高分直接 conf 过滤”。** 固定版本 Head 的准确路径：

1. 以所有 raw 的 `max_class_score` 选最多 300 个 raw 位置；
2. 对这批 raw 的**全部 80 类分数**展平，选全局最多 300 个 `(raw_id, class_id, class_score)` 组合；
3. 使用**可重复的 raw_id** 收集对应框和 Mask 系数；`nms.non_max_suppression(end2end=True)` 再对已经生成的组合行以 `class_score > conf` 过滤，不执行普通 NMS 的 `multi_label` 扩展；
4. 因而同 raw 可以输出不同类别的多条检测记录、共享完全相同的原始框/Mask 系数；`raw_id` 不是输出记录的唯一键，需 `(image, branch, raw_id, category_id, output_detection_id)`。正常 COCOeval 的 bbox/segm 仍各自按最终输出独立匹配。

**例外：** 在 Head 内部显式 `head.agnostic_nms=True` 时，`get_topk_index` 采用一次 `scores.max(dim=-1)` + top-k，才是每 raw 最多一类。v8.4.100 原生 `BaseValidator` 会将验证器 `args.agnostic_nms` 传递到 Head；它因此可能切换为每 raw 单类别的 Head Top-K，而不只是改变普通 NMS 行为。在 O2O 的 `end2end=True` 早返回中，即便外层设置普通 NMS 的 `multi_label=False`，也不会取消 Head 已生成的重复 raw–类别组合。版本、实际 Head 属性、真实输入尺寸和两轮 Top-K 均必须记录。

**对应正式数值对账：** 本项目固定 COCO 官方权重 SHA 与 Ultralytics 发布资产**完全一致**，但本项目自定义导出评估为 `Box AP=51.980 / Mask AP=43.518`，而 Ultralytics v8.4.100 官方 COCO val2017、640、E2E 刊载 `52.5 / 44.1`，相差 −0.520 / −0.582 AP 点。不可将旧数值直接标为“严格复现官方发布基线”，也不能将差距归因于权重质量（权重哈希已核实一致）。验证官方 AP parity 的唯一补证为在相同官方权重上运行**原生 Ultralytics 8.4.100 COCO val**，再逐环节对比自定义导出；禁止新预训练。

**固定版本分支开关补充：** v8.4.100 的 `end2end=True` 才表示 O2O 原生验证；`cfg/default.yaml` 的 `nms=False` 是导出 NMS 融合选项，不能用来证明已进入 O2O。完整补证、逐 GT 分类、验收及停止条件固定为 [官方 GT 失败重基线计划](../../experiments/official_gt_failure_rebaseline_20261013/PROTOCOL.md)。逐项源码行号与模型权重证据仍见 [O2O Top-K 与 COCO 基线核验](../audits/candidate_eval_20261012/O2O_TOPK_OFFICIAL_COCO_BASELINE_20261013.md)。

## 1. 不可合并的对象层

| candidate_policy | 实际研究对象 | 可回答 | 不可冒充 |
|---|---|---|---|
| `inference_output` | 正常无 GT 推理结果 | COCO AP/AR、实际失败 | 完整 raw 能力 |
| `raw_all` | 指定分支所有原始预测位置 | GT 辅助潜在能力 | 实际部署收益 |
| `raw_argmax_correct` | raw 类别 argmax 正确，无分数/top-k 限制 | 语义条件下的能力 | 官方 TAL 或实际输出 |
| `official_tal_replay` | 当前冻结权重经官方数据管线重放 TAL 正样本 | 监督位置与训练损失 | 原始预训练历史或实际推理 |
| `legacy_geometry_hungarian` | GT BoxIoU≥0.5，最大基数优先几何配对 | GT 辅助异位诊断 | TAL 正样本与官方方法结果 |
| `fixed_output_slot` | 最终输出上的固定 GT—prediction 配对 | 同槽框/掩码表型 | 完整 COCOeval 匹配 |

旧几何规则不是无效诊断，但它与训练 TAL、正常输出是不同总体。one-to-one/one-to-many 与不同输入形状必须分别记账。

## 2. 先分类任务失败，再查 raw

1. 正常推理 + 标准 COCOeval 建立任务总账（TP/FP、GT 失败、类别、阈值、head top-k、NMS/E2E、maxDets、crowd、竞争）。
2. 对同一 GT 另建 `raw_all`、`raw_argmax_correct`：独立计算 best Box IoU、best Mask IoU、`exists_box75`、`exists_mask75`、`exists_joint75`；不同 raw 的好框与好 mask **不能拼成一个成功**。
3. 与 `official_tal_replay` 关联以回答官方监督位置是否覆盖可用 raw。TAL 使用 GT，绝非推理预测。
4. 将 raw 沿 score、top-k、conf、预算、NMS/E2E、匹配追踪至输出；无法回溯填 `unknown`，不把未知当丢失。
5. 机制实验必须在声明的层上冻结候选与框；由 GT 选 raw/系数统一标记 `gt_assisted=true`，不能作为部署改进成绩。

## 3. 原始位置身份与 GT 关系身份

物理 raw key 至少：
`checkpoint_sha256, image_id, branch, input_hw, letterbox_policy, pyramid_level, raw_id_global, grid_y, grid_x, stride`。

GT—raw 关系 key 还加 `annotation_id, relation_policy`。相同 annotation 不代表相同 raw；二分匹配的唯一性另审计。P3/P4/P5 offset 必须按本次真实 tensor shape 推导，不能固定假定 8400。缺少 key 的历史行标记 `identity_incomplete`，不可用于精确候选因果对照。

TAL 额外记录 `target_gt_idx, owner, target_box, loader_version, overlap_mask, mask_ratio`。输出保留预测类别/置信度及筛选版本。

## 4. 新 Run 的 EVAL_CONTRACT.json 必填字段

- `study_id, run_id, checkpoint_sha256, code_revision, ultralytics_version, dataset, annotation_sha256, image_ids_sha256`；
- `split, branch, input_hw, letterbox_policy, candidate_policy, gt_assisted, relation_policy`；
- `evaluation_unit`（`coco_ap` / `image_macro` / `candidate_mean` / `gt_recall` / `image_exact_n`）、主 metric、阈值、decoder、bootstrap unit；
- fit/dev/val 清单哈希、训练/选模所用 split、candidate_manifest_sha256、图/候选数、预注册 Gate/停止条件路径；
- 跨结果对比时必须有 `baseline_reference`（逐行来源、sha、数值容差）。

缺失记 `unknown`，禁止猜测。必要逐候选/逐GT、逐图、SUMMARY、run.json、哈希清单按研究层交付。

## 5. Gate / 失败即停

**G0 数据与身份**：确认权重、COCO 标注、版本、无泄漏的 split、分支、图像形状、候选 manifest。候选对象不一致就停止跨实验归因。

**G1 原始 A 基线复现**：相同 `(split,image_id,annotation_id,branch,raw_id,pyramid_level)`、相同缓存与 decoder 的原始 Mask IoU，须与旧官方逐候选记录比对；既有 Gate 容差为绝对误差 ≤1e-6，相同预测二值 mask 可进一步要求逐像素一致。差异超标必须停止，不得只打 warning；参考缺失则记 `unadjudicated`，不称完全同口径。

**G2 同槽评价**：A/B/C 用同一候选、预测框、原图 COCO GT、解码器、评价总体与分母。旧160和官方640的 BCE/J 绝对值不可直接比较。

**G3 统计与选模**：fit 拟合，dev 选定，val 按预注册规则确认。图像簇 bootstrap，候选平均和 image-macro 同时呈现不混用。被研发反复查看的 val 不算盲测。

**G4 部署效用**：声称方法提升正常分割必须提供无 GT 正常输出 COCOeval、原成功损伤和计算开销；GT oracle 或 TAL 正样本 IoU 只作机制结论。

**G5 判定与停止**：前置 Gate 不过记 `insufficient_inputs`，只补当前唯一缺项；科学门槛未过记 `negative_at_scope` 并停止当前配置。不得读 val 后换选样、Loss、阈值、分母或候选，再回填为预注册实验。

## 6. 历史处理与自动化边界

历史原始 Run 和报告不覆盖。审计状态：`verified`（窄事实核实）、`scoped`（保留特定对象结果）、`misattributed`（原解释跨域）、`needs_replay`（明确阻塞）、`invalid`（具体 Run 实现错误）。详见 `project/audits/candidate_eval_20261012/`。

先复用本地/远端现有缓存和报告，仅对可能改变论文判断的关键缺口重算。规范不会自动连接主机、生成缺失权重或重跑历史任务；需要实际 Run 的 Gate 和完成凭据才能宣布科研裁决。
