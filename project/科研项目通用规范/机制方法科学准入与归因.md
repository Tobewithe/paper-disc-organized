# 机制导向新方法的科学准入与证据归因

**版本：2026-10-16。适用范围：**所有研究线中**打算作为科研创新或论文核心机制主张**的新模型结构、loss、门控、参数化、训练策略及混合方法。纯工程修复、同协议重放、基线复现、既有模型读数、零训练诊断仍遵守真实性/冻结/评价规则，但**不因没有同容量训练消融就被禁止**。

**第7节“实验展示范式”适用于每次实验结束，包括成功、失败、零训练诊断和工程中止；面向用户的结案汇报和新写的结案报告均须采用。** 这是解释和交付要求，不要求每个工程任务创造机制假说或新增模型对照。

**权威边界：**本文件规定「什么有资格以机制方法立项、什么结果才能叫机制证据」。不宣布具体研究线当前执行动作，**当前动作以 [ACTIVE_PLAN](../ACTIVE_PLAN.md) 或相关研究线正式入口为准**；实际数值 Gate、样本量、训练预算、停止条件以**各自 Run 启动前已冻结的 Protocol**为准。本文不追溯重判、修改或重启既有 Run。阅读时还应结合[指标最小化与TAL分类](指标最小化与TAL分类.md)、[训练规模与结论边界](训练规模与结论边界.md)与[运行登记与本地协同](运行登记与本地协同.md)。

## 1. 先区分「结构候选」「机制假说」「机制证据」「方法效用」

| 类型 | 科学意义 | 可以宣称什么 | 不能自动宣称什么 |
| --- | --- | --- | --- |
| 工程/结构候选 | 增加模块、参数或换损失，运行成功 | 实现可运行、计算量/效果读数 | 因果机制、创新贡献 |
| 机制假说 | 从真实失败现象推导出会产生差异预测的解释 | 有依据的待检验主张 | 已证实唯一根因 |
| 机制证据 | 匹配对照/定向干预按冻结预测改变读数，且核验通过 | 在具体模型、条件及干预范围内该因素有独立效应 | 所有历史失败均归此因、跨数据普遍有效 |
| 方法效用 | 正常无GT输入、完整任务评价、安全护栏、代价与复现过Gate | 在冻结对象和数据范围内实现有效修复 | 因为 AP 增长就证明声称的机制成立 |

**核心原则：**机制证据与方法效用是不同坐标轴。一个结构可以有性能而没有归因；一个零训练干预也可以具有真实机制信息但没有部署价值。**不把诊断或负结果包装成「机制方法已经解决问题」。**

## 2. 四项科学准入要求：每项都要留下可复核答案

### M1｜有具体失效机制，而非只有低分/想涨分

- 先指明失败的**对象、统计分母、源 Run、已核实的异常**（例如同检测32D Oracle可修但原生/adapter未兑现；BCE下降而二值 MaskIoU 下降；应用修正后原成功实例损伤）。
- 明确 H 是对哪一个计算因子的解释：表示可达性、优化目标、特征→系数读出、阈值/decoder、应用选择、损伤保护等；列出至少一个**已有事实支持**的竞争解释 H_alt。
- 给出**为何需要这个方法特定操作**的方向推理。缺少正面证据/机制推导，或者旧Run已否定同一实现且没有新判别因素的，不能仅靠「换个结构可能成功」批准新正式训练。

### M2｜可证伪且有区别力的预测

- 预先写出「H正确时，哪一项主读数必须按哪个方向变化」以及「若 H_alt 正确，读数有什么不同」。尽可能把预测落实到**一项必要主指标和必要的风险护栏**，不要新增大量事后可筛选的统计量。
- 将**点值最小效应、区间/检验、样本单位/分母、阳性／阴性／无效或证据不足的唯一下一动作**在 Run 前冻结；这些数值需由所属Study制定，通用标准不替代。
- 如果无论出现何种结果都只会「换个loss/再测一个模块」，则没有决策价值：退回为讨论猜想或停止，不要自动开新实验。

### M3｜匹配容量与资源，尽可能隔离新增机制

**当研究者想声称某个新计算要素独立带来改进时，优先采用同容量对照，而不是只和原模型比较。**

至少核查并记录：
- **有效参数数目与可训练白名单**（不能只比网络名义总参数）、初始化/种子与共享权重；
- **输入信息**（额外图像特征、ROI、GT、邻居、类别、置信度）及其可用性；不同输入信息应有只改变该信息的对照；
- 数据图像清单、训练标签/关联、实际更新步数、优化器/loss权重、数值、增强、BN/EMA与checkpoint选择；
- 推理候选集合、检测身份、Box/Class/score/排序、decoder、GT是否进入推理、AP和损伤分母；
- 时间、显存、算力差异；主结论与计算量的交换需披露。

适当控制方式包括**相同MLP+空间布局打乱**、**同参数残差但投影回受限函数空间**、无机制信息的等维占位输入、同一checkpoint的无机制干预等。须在对应研究中论证对照是否真正限制了 H 所声称的成分。

**不可能完全等容量或输入同一时：**在 Protocol 明示不可消除的混杂、设计最接近的对照，并将因果结论降级为「复合配置效应」。不能为满足外观同容量而改变数据/损失或使用无效梯度的坏对照。**结构必要的参数增加本身不是违规，未经对照却声称机制独立性才是问题。**

### M4｜定向删除/受限干预，证明所宣称机制被实际使用

- 在**正式研究执行前**预登记「移除/破坏 H 独有因素后应如何变化」，优先保持其它因素、输入、参数初始化/训练预算/解码及样本身份不变。**启动前要求有可执行的消融设计，不要求消融在立项前已经阳性**。
- 能做时至少配合以下两种相互补充的证据：① 同预算/同容量训练的**受限机制臂**，② **同一已训练 checkpoint**上的定向删除或置换，明确删除前后冻结机制主指标；两种有不同优化和分布移位混杂，不能互相完全替代。
- 额外考虑**幅度/范数等价控制、训练梯度是否有效、参数/输入泄漏、阈值/decoder变化**。删除模块后 AP 下降，不一定表明该模块的特定机制被使用——也可能只是删掉了任何必要计算量；须对这一竞争解释设计控制。
- 记录原生对照、删除后的失败样例和反例、所有预登记子组；不能只展示漂亮热力图或只挑“修好的 GT”。

## 3. 分阶段准入：别把「先证明有效才准跑」做成循环门槛

| 阶段 | 必须提供 | 结果/允许动作 |
| --- | --- | --- |
| **构思及低成本探索** | 问题与旧证据、H/H_alt、对照是否可构造、资源上限；可以先做必要的只读或零训练可行性测量 | 标注 `HYPOTHESIS_ONLY` 或 `EXPLORATORY`；不得宣布方法/机制已通过 |
| **新方法正式立项、Run冻结前** | M1与M2完整；M3控制或不可避免混杂清楚；M4所需消融预声明；实验身份、指标/统计、预算、失败退出、现行Gate和用户/环境授权核验 | 缺项则`BLOCKED_DESIGN`，不能直接进入正式科学训练；这是新立项约束，不回溯旧 Run |
| **工程烟雾/有效性** | 真实特征/GT监督路径、零残差原生等价、候选及输出不变、梯度与白名单、冻结数据/代码/权重/decoder | `VALID_PIPELINE`才允许按已授权阶段执行；smoke成功不是阳性机制 |
| **同域受控评价** | M3有效对照及M4干预的真实 Run；机制效应、必要task/风险护栏、可信区间和成本 | 独立给出`MECHANISM_SUPPORTED_AT_SCOPE`、`METHOD_UTILITY_PASS`或`NOT_SUPPORTED/INCONCLUSIVE/INVALID`；不能拿一个替另一个 |
| **外推与论文声称** | 已声明的开发外/其他种子或模型域确认；对成熟强基线公平比较，证据与结果范围一致 | 只写数据、架构、干预范围所支持的结论；论文新颖性需要同期文献专门核查 |

以上状态为**科研报告建议用语，不强行覆盖已冻结 Study 的机器状态枚举或 decision JSON 字段**。纯数值诊断/数学证书可不训练同容量网络，其方法效用结论也不能借此成立。

## 4. 尤其不允许的「伪机制归因」

- **只比 A 与 A+新MLP：**新信息、参数量、优化路径同时变化，不能把差异归为某一个因素。
- **同时改变loss、输入、方向参数化与门控：**即使任务变好，也只能判复合配置有效；若要主张单项机制，需单变量匹配对照和定向消融。
- **GT辅助最优系数、有限BCE求解不成功：**前者只是可达性正见证；后者不是数学不可表达证明，更不能替代正常无GT AP。
- **仅观察训练loss降低/二值mask的漂亮例子：**不支持真实输出全量任务收益，更不支持成功保护。
- **方法输出曾参与阈值/模型选择的研发数据：**其CI不能冒充独立盲测；负结果不能通过事后挑选seed/条件分层挽救。
- **已有配置 Gate 失败后换名称继续跑：**除非另有独立正面证据、独特的可证伪预测与新版本冻结协议，否则归档而不是重复预算。

## 5. 给 Prototype→Coefficient 研究线的具体示例（只作范例，非命令）

**已知：**[S1 256同检测Oracle](../../experiments/mask_readout_mechanism_v2_20261012/S1_REPORT_20261013.md) 中 **122个** 找到固定 P 的32D Mask75修复见证；[BCE像素记账](../../experiments/mask_readout_bce_decomposition_20261014/REPORT.md) 记录特定异常组 FP→FP 的连续损失改善与TP→FN伤害；[S3报告](../../experiments/mask_gate_s3r_20261015/REPORT.md) 记录面积门控在同域得 **+0.141573 AP点**、原成功 **90/22957** 损伤，但未达到+0.3点晋级门槛。三者为不同统计对象，不能拼成单因果链。

**一个有依据但仍未验证的命题 H：**共享32D系数变化 `delta_z(u)=P(u)^T delta_c` 可能导致「错误背景修复—原正确前景保护」的方向冲突。其竞争解释是训练目标/实例特征不足、阈值/几何转换和门控选择。**不是**「32维容量不足导致总体失效」的已知事实。

**最小判别原则：**先遵从 [当前研究总控](../ACTIVE_PLAN.md)，用既有同检测 S1 256 条 Oracle/adapter/门控联查，判断机会损失在学习还是选择；只有指向修复学习问题且新主张有独立证据时，再另立**零训练、固定P/框/decoder**的系数修复与成功像素保护约束测量。有限求解失败记数值未知，不冒充不可行性数学证书。只有得到值得投资的新机制证据，才考虑同结构、同预算的目标干预训练。

**目前没有任何据本规范新增的训练授权。**

## 6. 开新方法 Study 可复制的最小准入摘要

```text
研究线/当前ACTIVE_PLAN节点/现有Run：
观察异常：对象、样本和分母、数值、来源：
H（主机制）与H_alt（竞争解释）：
针对性方法：改变哪个操作、如何作用于H、为何预期解决上述问题：
独特预测：H成立时____；H不成立/解释不充分时____：
单一主指标与必要损伤/成本护栏：单位、门槛、区间、统计簇：
双参照：原生模型Run/配置；预先指定已有方法Run/配置；两项比较的共同分母：
训练/样本/输出身份及合法GT使用位置：
对照：同参数、同输入/故意改变的信息、预算、冻结项；未消除的混杂：
定向干预：删除什么；是否有幅度控制和梯度路径验证：
阳性/阴性/无效三出口及唯一下一步：
已完成依据：____；拟新增Run：____；是否已获环境与研究授权：____：
论文最大可宣称范围；哪些结论暂不可说：
```

**执行准则：**仅新增复杂度不能成为新正式科学 Run 的充足理由；优先利用已有数据做能改变方向的最小检验。即使新机制假说值得立项，**它是科研问题，不是自动启动训练的许可证**。

## 7. 实验展示范式

**以一次完整实验为单位，交付一条连贯的“问题—机制假说—针对性方法—整体结果—研究决策”链路。** 用户应能看懂整项实验为何开展、它检验哪个解释、怎样检验、最终学到了什么，以及研究因此如何前进。展示单位由完整科研命题确定，不按命令、核验步骤或Run数量拆分。

### 7.1 单个实验的默认形式

先用两三句通俗说明实验名称、实际完成范围和最重要结论，交代对象/分母、是否训练及GT使用方式。随后使用两列、五行的整体链路表：

| 维度 | 本次实验的整体研究链路 |
|---|---|
| **问题** | 【整项实验针对的具体科研缺口、已有Run证据及解决它的意义。】 |
| **机制假说** | 【可能造成缺口的计算过程；有依据的H与H_alt，以及各自可区分、可证伪的预测。】 |
| **针对性方法** | 【整项干预和必要对照如何检验上述预测；变化因素、冻结项、对象与预算。】 |
| **整体结果** | 【主读数及关键对照是否符合预测；相对原生和已有方法的收益/损伤、Gate、不确定性和有效范围。】 |
| **研究决策** | 【整体支持/削弱/未区分什么；选定正向研究重点与唯一下一步，写明停止/继续或改判条件及启动状态。】 |

五行始终围绕同一个完整实验，形成连续的科学解释。必要术语随文解释；详细逐实例数据、完整控制表和日志保留在可追溯产物中。

### 7.2 整体叙述与支撑证据的层级

- **完整实验是主叙述单位。** 参照建立、对照/消融、幅度干预、解码重放、配置与数值核验、回传等是该实验的组成部分，放在整体方法、整体结果或证据附注中，不逐项另设一套科研链路。
- **多个独立实验分别呈现。** 可以每个实验各用一张上述表，或用“实验｜问题｜机制假说｜针对性方法｜整体结果｜研究决策”六列总表，每个完整实验一行。smoke、正式执行与独立核验服务同一命题时，不因各有Run ID就拆成多个实验。
- **问题来自证据。** 指明对象、分母、具体失效与源Run。“AP不够高”不能单独构成问题的机制解释；只引用支持本次立项的历史事实。
- **机制假说解释整项实验检验的原因。** 说明哪个因素可能怎样造成问题、已有依据及竞争解释，不把“方向不好”等现象标签自动当成已证根因。保留原先预测，不在看到结果后更换主假说。
- **方法围绕判别目的说明。** 解释具体干预为什么能区分H与H_alt，必要对照控制了什么，哪些因素冻结、哪些混杂仍在。对照在整体实验中承担科学作用，不只列A/B/C名字。
- **整体结果必须回答原始问题。** 综合主读数、关键对照和护栏，交代原先预测哪些实现、哪些没有实现。阳性、阴性、信息不足和未完成部分均保留；不能只挑一个成功步骤代替整项结果，也不能用工程通过代替科学通过。
- **整体决策由整体证据推出。** 分开说明机制支持程度、方法效用、冻结Gate及投入决定，再落实到一个有依据的下一步。教师机会、对照组自身收益或普通必要计算被删后的退化，不能直接归为新增设计贡献。
- **工程证据简要附后。** 配置一致性、哈希、测试、独立复算及回传用简短状态与链接交付。若某项失败影响可比性或科学裁决，在“整体结果”解释其影响；不为了填机制栏目而给工程步骤虚构机制假说。

纯基线、工程或描述性任务没有待检验机制时可写“不适用”，讲清整体核验目标、实际终点和结论范围。未测/待核实/不可比须明示；展示规范不要求新增实验。阶段进度表、总成绩表或操作清单可以作为补充，不能代替整项实验的研究链路。

### 7.3 相对原生与已有方法的收益分别交付

记原生基线为N，协议预先指定的已有方法为R，本次方法为M。在“整体结果”中分别报告同口径的M−N与M−R；低值更优指标解释符号。参照名称、Run、checkpoint/配置及比较分母在运行前固定，不依据结果改挑较弱参照。

- **相对原生模型：**报告实际改善和损伤，给出关键实测值、差值、单位、共同对象/分母、归约、协议要求的区间及风险护栏。
- **相对已有方法：**报告新增设计的额外收益或退化；相对原生有收益但相对已有方法无增量，可以同时成立，必须同时保留。
- **机制匹配对照：**若协议另设C，须说明M−C对机制判断的影响；不能用较弱消融代替已有方法，也不能把C自身的改善记作M的贡献。
- **比较权限与范围：**GT辅助oracle和无GT部署方法权限不同，描述性差值不得变成部署优势主张；IoU、AP点、相对百分比及不同分母/归约不混用。原生参照用同配置实测结果，官方发表值的parity状态单独说明。
- **不确定性：**未过效用幅度Gate不等于没有收益；超过原生不等于机制成立。损伤点估计低于门槛但上界未过，不得写成已证总体超限；像素保护也不替代原成功GT任务损伤。开发/独立确认边界依冻结协议。

数字较多时可另附精简对照表支持整体判断，无需把每项比较重新包装成独立实验。无可比结果或方法收益不适用时，注明原因并报告该任务的实际读数，不擅自追加实验补表。

### 7.4 研究决策与证据收尾

“研究决策”应直接说明：本次实验支持/削弱了哪个原先主张，保留什么事实，停止或继续什么，为什么优先选择下一方向。**Agent必须选定一个有证据支持的正向研究重点和唯一下一步**，写明最小行动、继续/停止或改判条件、证据范围以及是否已启动。方向可以是待验证假说，不能由旧方法失败直接推出新方法有效，也不构成自动启动授权。

表后只补必要的技术证据与限制，避免把决策重复汇报一遍。提供本次及参照Run、冻结协议、配置复核、必要独立核验及产物路径。补充分析注明性质，不回写为事前假说或冻结Gate；工程和回传通过不替代科学结论。
