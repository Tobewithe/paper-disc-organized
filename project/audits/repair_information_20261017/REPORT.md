# 修正器空间信息、监督与路线投入审查

2026-10-17。本轮复用了真实训练源码快照、缓存清单、训练日志、checkpoint 和已结案评价，另在笔记本只读加载一份原缓存核对字段。**没有训练、模型 forward、新干预、重新评价或新科学 Run。**

结论：**不再投入现有“单点 F＋8×8 原型采样汇聚”的配方试错；保留原型—系数问题，值得进入一次“保留实例区域 F 空间布局”的新设计论证。** 支持后者的依据是可修系数见证、已有无 GT 正收益和原空间布局对照的相对优势，以及本次查实的空间读取限制；尚未证明完整 F 布局能带来新增收益。本轮只裁决研究方向，不启动该设计或训练。

## 1. 实际信息链：读到了什么，在哪里受限

审查范围是本报告列出的当前O2O后训练支系，不代表通读仓库全部历史研究线。本节的“丢失”指输入表示或显式位置关系被舍弃，**不等于已经证明丢掉的是任务必需信息，也不等于能量化它造成了多少 AP 损失**。

| 环节 | 实际实现与尺寸 | 能明确判断的限制 |
|---|---|---|
| 原生模型进入 Head 的特征 | 缓存清单记录 `model.23`，来源层16/19/22，通道256/512/512，步长8/16/32。Head实际产生完整特征图；原生系数子头包含两层3×3卷积和末端1×1。 | 原生模型具备空间运算；不能把后训练输入受限直接说成基础模型从未看见空间或图像。 |
| 导出 F | `native_output_bridge.py:315–327` 根据最终检测的真实 raw_id 找到所属层/行/列，只保存 `F[level][:, row, column]`。每条最终检测对应一条向量；不是预测框中心采样，也不是 ROIAlign。 | **完整 F 图在缓存阶段就没有保留。** 所有最终输出的稀疏向量不能直接重建原特征图；forward也不把其它输出的 F 聚合进当前实例。 |
| 导出 P/c0 | 完整图像级 P、每个最终输出的32维 c0、预测框、score、类别、原生几何和 raw 映射保存。 | P本身仍含由图像提取的空间信息，不能说修正器“没有图像信息”。缓存完整 P 不等于预测 Δc 时完整使用了它。 |
| 旧 Adapter 的 P/z0 入口 | 对预测框取8×8格中心，bilinear、zero padding、align_corners=False；先采样32通道 P，再计算同网格 z0，共33×8×8。 | 每框固定64个采样位置，不随大框/复杂边界增加；这是点采样，不是把每个格子内所有原型像素做平均。未被采到的局部变化没有直接进入此分支。小框也可能被上采样，不能一概称所有框都降采样。 |
| 空间编码与汇聚 | 两层3×3、64通道卷积+GELU，得到64×8×8，再 `mean(H,W)` 为64维。 | 汇聚后没有显式的8×8位置索引。**不是全部空间信息消失**：汇聚前卷积可编码局部排列，zero padding也可提供边缘位置线索；B/C结果证明确有部分排列作用。缺少保持位置读出与均值读出的专门匹配对照。 |
| F、c0与几何融合 | 所属层的单点 F 线性投影到64维；c0投影32维；归一化框4维、score1维、类别embedding16维；与空间64维拼成181维→128→32。 | 每个实例只取一个金字塔层的 F，未读同实例其它层的区域网格。`raw_locations`的层号决定投影分支，行/列未作为显式输入；框几何并非每个像素的位置。投影有压缩，但尚无证据证明64维本身不足。 |
| 系数输出与解码 | 输出每实例一个32维 Δc；在**完整 P**上形成 `Δz(u)=P(u)·Δc`，继承原生解码。 | 同一系数同时影响多个空间位置，存在修复/损伤耦合；但159条固定P见证说明这些对象不能全部归因于“32维一定不够”。教师见证是逐实例GT辅助求解，不承担共享预测网络的可学习性证明。 |

实际结构可写为：`[GAP(CNN(框内 P/z0 的8×8采样)), 单点F投影, c0投影, 框, 分数, 类别] → Δc`。BCE、soft-IoU、AMT、CLD的核心读出均沿用它。AMT更换监督目标，CLD更换功能方向监督，均未增加完整实例区域 F。

其它已测支系也不能遗漏：球面 E2 在该核心上加入一个确定邻居的41维摘要，包括系数差、相对几何、冲突/熵等；所以不能说“所有方法都没考虑邻居”。但它仍没有引入密集区域 F。E4改变损失所在的解码尺度/排斥项，仍使用原 `CoefficientAdapter`；它检验过目标尺度调整，不是新的空间特征读取器。

### 最新 LRP 并不是“完整空间图像信息已经试过”

LRP的68维逐点输入为：插值后的P32维、c0×P32维、z1维、原生二值mask1维、框内xy2维。其 `68→32→32→1` MLP逐点独立；没有读取缓存中的F，没有RGB或显式邻域patch、跨点卷积/注意力。插值提供更密的输出坐标，**不会从原图取回未输入的纹理/边界细节**；xy可以提供位置，但不提供新增视觉证据。P及其派生量仍有图像条件信息，因此也不能反过来称它是完全无视觉输入的网络。

LOCAL推理处理编辑域内所有点；训练每个输出固定最多512点，三轮不重采样。UNIFORM以同网络预测的固定点均值作为整域偏移。LOCAL/UNIFORM的相对收益支持本受限功能对照下的小作用，未单独匹配实际修改幅度/像素数；不能归因为纯空间对齐。

面积≥9216和`abs(z)≤1.5`且框内的编辑域为硬限制。LEA原159条C见证只保留132条，丢失27条均存在教师修正锁定高置信错误的像素；这给出**当前编辑域排除必要修改**的具体证据。但是LEA的256条面板与LRP的400图不同，不能据此计算LRP的损失占比或宣称它是LRP的唯一原因。[LRP实现](../../../experiments/mask_local_residual_pilot_20261017/scripts/lrp_math.py)、[训练数据准备](../../../experiments/mask_local_residual_pilot_20261017/scripts/lrp_prepare.py)、[LEA报告](../../../experiments/mask_local_editability_20261017/REPORT.md)。

## 3. 监督、解码和优化核对

原B/soft-IoU的GT从原图按实际resize/pad投到proto网格，监督按预测框ROI计算；GT组与全部输出保护组各自归一化，再以0.1加权。因此“多数输出未匹配，所以GT loss被同一大分母稀释”不符合实现。CLD的方向MSE是连续功能响应误差；LRP则在固定编辑点监督锚定logit。三者都不是直接优化最终COCO AP或成功GT损伤。

本次确认的固定运行时原生解码为：全矩阵系数×P → 插值到原生输入尺寸 → `>0`二值化并预测框裁剪 → 按原ratio_pad缩放二值mask到原图 → `.byte()` → RLE。**最后不是另加一次0.5阈值。** 这一路径及其零残差等价已由原Run验证；本轮不改decoder，也不把连续监督与原生二值端点的差别误报成新配置漂移。[实际解码](../../../shared/evaluation/native_output_bridge.py)、[固定ops](../../../shared/vendor/ultralytics_8_4_100/ultralytics/utils/ops.py)、[固定验证器](../../../shared/vendor/ultralytics_8_4_100/ultralytics/models/yolo/segment/val.py)。

## 5. 路线裁决及唯一下一步

**我的判断是：原型—系数研究问题值得保留，现有摘要式读出配方不值得继续追加预算。值得重新论证的唯一方法方向是“让修正器保留实例区域 F 的空间对应，再预测 Δc”。**

选择理由是正面的：已有同预算B/C对照证明保留空间排列的相对作用，已有G证明固定P的无GT修正可获真实小收益；而真实缓存/代码显示，本次审查的当前O2O后训练方法并没有检验过完整实例区域F的空间读取。这里选择的是一个有依据、可区分的新计算因素，不是因旧方法失败便断言新方法会成功。F的原生步长为8/16/32，也不能把它笼统宣传成比P更高分辨率；待检验的是区域内通道和位置对应，而不是简单放大插值尺寸。

相比之下，只换loss/教师已多次未超过G；单独调幅的可兑现机会不足；直接扩数据缺乏本项目的因果支持；原型容错的误差迁移对照未达准入要求。故不优先解冻P、不扩量、不重开旧配置。已有59条CLD辅助修复、LRP小增量和G正AP全部保留，不把未过Gate说成一无所获。

**唯一下一步建议是设计审查，而非训练：**写出“同一实例区域F数值，保留空间对应/破坏空间对应”的匹配方案，说明新增F与原有P空间分支分别提供什么、如何控制容量/预算/幅度与监督、怎样同时超过N及公平的已有方法参照。旧400图的G暴露差异必须明确解决，不能继续把它称同训练预算盲测对照。必要效果和保护要求应在新协议中先冻结，原Gate不变。
