# 研究迭代全流程手册:从状态收敛到破局找新 idea

日期:2026-10-04。本手册面向所有执行线程(AI 或人),与 [EXPERIMENT_SPEC_STANDARD 第0节](EXPERIMENT_SPEC_STANDARD.md#0-有依据的研究头脑风暴) 互补:规范定义"什么不能做",本手册回答"一轮研究具体怎么走、每步注意什么、卡住了怎么找出路"。示例均来自本项目系数主线的真实经历。

---

## 第一部分:一轮研究迭代的闭环(七个环节)

### 环节 1:状态收敛 —— 先读冻结记录,不读最新实验

入口顺序:MAINLINE_STATUS → ACTIVE_GOAL(最新收尾段优先于历史段)→ 相关实验的 REPORT 结论段。先回答三个问题再动手:当前声明的未解决问题是什么?上一轮的停止条件是什么?哪些配置已被明令禁止重启?

**注意:**
- 状态文档里"最新"段落在顶部、历史在底部,读反了会把已停止的配置当成在跑的。
- "尚未回传"≠"执行失败","训练域改善"≠"方法有效",口径必须按原文保留。
- 两线程分工(服务器/笔记本)期间,对方线程的 Study 只读去重,不跟进、不复制其机制。

### 环节 2:缺口定位 —— 找矛盾,而不是找"还没试过的方法"

信息量排序:**两个结论相反的同构实验 > 一个强正结果 > 一堆阴性结果 > 空白区域**。先在证据库里找矛盾对(如:共享仿射在几何候选 +5.48pp、在官方候选 −0.99pp),矛盾处必然藏着一个未被命名的关键变量。没有矛盾时,找"强正结果的边界"——它在什么条件下消失(交叉回放、分层分解往往已有现成数据)。

**注意:**
- 阴性结果的价值在于"排除了什么",每轮收尾必须能说清排除域;连"排除了什么"都说不清的实验是设计失败,不是机制发现。
- 空白区域(从没人试过的方向)优先级最低:没试过往往有原因,先查为什么没人试。

### 环节 3:假设提出 —— 必须成对,必须有可区分预测

单个假设不是研究设计,至少写出两个竞争假设(H-A/H-B),各自给出**不同的**可观测预测;预测相同的两个假设在当前实验里等价,不值得花预算区分。本项目习惯用 H-位置/H-目标/H-混合这类命名。

**注意:**
- 假设要落到链路的具体环节上(实例特征 → 原型响应 → 系数生成 → 掩码形成),"模型能力不足"这种不落地的表述禁止作为假设。
- 提出假设后第一件事是**找已有数据证伪它**,而不是设计新实验验证它。本项目的教训:"目标口径假设"被阶段 B 报告里早已存在的交叉回放削弱了一半——答案常常已经躺在旧报告的附录里。

### 环节 4:去重审查 —— 四个来源逐一过

按规范要求覆盖:(a) **历史**:检索实验目录和收尾记录,确认机制、对象、预算三要素是否真的和旧配置不同,改名/换数据规模/换机器不算新机制;(b) **实现**:读原模型源码确认机制在实现里真实存在(如 proto.detach 的梯度路由),不凭印象;(c) **数学**:凸性、可行性界限、自由度计算能否直接预判结果(对偶证书曾直接证明一个家族的硬上限,省掉了整条试错线);(d) **文献**:提供设计先例和反例,但文献有效≠本对象有效,文献存在≠不许做(区别在于你的新增判别是什么)。

**注意:**
- 与已停止配置"部分重叠"的新组合是合法的,但必须逐条写明新变量(例:修正×异位读出,此前只各自单独试过一半)。
- 查到"已登记未执行"的旧协议(如 B0)时,评估其信息量是否已被后续结果降低,不自动续跑。

### 环节 5:判别设计 —— 因子化、锚点复用、解释图前置

- 把混杂因素改写成**因子矩阵**(2×2 或更高),已有结果填进格子作锚点,只补缺格。这是零浪费设计的核心:判别力来自正交对照,不来自新模块。
- **在看到结果前写死解释图**:每种可能结果分别支持哪个假设、下一步是什么、阴性能排除什么/不能排除什么。
- 主指标唯一且前置(本项目:val 图片级 macro Mask IoU),代价指标(原成功组损伤、coverage、FPR)必列,候选级/探索集只能作次指标。
- 继续/停止条件量化(如 ≥+0.5pp 且 CI 下界>0),写进 PROTOCOL 再启动。

**注意:**
- 永远优先零训练设计(求解、回放、重计权、证书);训练实验的短预算阴性无法区分"机制无效"和"训练不足",判别力天然残缺。
- 对照必须能区分机制与额外投入:加了参数/计算/数据的臂,要配等投入的无机制对照。
- 检查机制真的被激活(梯度确实流过、参数确实改变、路径确实被调用),否则阴性无意义。

### 环节 6:执行纪律

smoke(2 图级)先行核身份/数值等价,再正式;预算和时间上限前置;身份字段(image_id/annotation_id/branch/raw_id/level)全程绑定;SHA 核验回传;原始 Run 不覆盖、失败 Run 保留为审计记录(如 area 口径错误的 retry4)。启动前核实际 PID 与 Run 状态,禁止凭旧 PIPELINE_STATUS 重复启动。

### 环节 7:解释与归档 —— 结论的"允许写/不允许写"清单

每份 REPORT 以两张清单收尾:本轮**支持**的判断(带范围限定)和**不支持**的判断(防止后续引用时走样)。随后更新主线状态文档,把悬置的矛盾改写成已判别的事实。禁止:探索集冒充独立确认、GT 辅助结果当部署性能、BCE/诊断目标下降当掩码收益、候选级收益冒充图片级主判定、fit 收益当泛化。

## 第二部分:破局 —— 连续阴性时系统性找新 idea 的九个入口

困境的典型形态:某方向连续多轮阴性,每轮都合规收尾,但主问题没有进展。此时**随机换方法是最差策略**,按以下入口系统性搜索:

### 入口 1:矛盾挖掘(最高优先级)
把所有"强正结果"和"强负结果"配对,找同构但结论相反的组合。每个矛盾 = 一个免费的判别实验机会。注意正负结果可能散落在不同实验的附录里(交叉回放、分层表),要主动拼。

### 入口 2:口径审计 —— 怀疑测量,而不只怀疑方法
正负结果矛盾时,先查两边的候选集、标签语义、支持域、归一化、统计口径(候选级 vs 图片级)是否真的可比。本项目两次重大修正(面积分母错误、COCO 评分类别 ID 错误)都属此类。"方法无效"的结论必须建立在"测量正确"之上。

### 入口 3:oracle 阶梯 —— 在"完全自由"和"现状"之间插中间层
逐实例 oracle(+5pp)和现状之间的差距,用约束递增的中间 oracle 切分:共享仿射(一层约束)→ 逐层/逐类共享 → 条件共享 → 逐实例。每级的可达性落差指出瓶颈是"映射家族容量"还是"信息不足"。数学证书(对偶下界、凸性)能把某级直接钉死,优于试错。

### 入口 4:正结果的边界勘探
对唯一的正结果问三个问题:在谁身上成立(分层:尺度/原失败组/位置类型)?换什么条件消失(交叉回放)?最简退化版还剩多少(bias-only vs 全仿射)?边界形状本身就是机制信息,而且这些分析通常零成本——数据已在手上。

### 入口 5:问题重述 —— 换量词,不换领域
把"为什么模型没预测出好系数"重述为"在**哪些位置/哪些实例/哪种约束下**好系数是可预测的"。从存在性问题(有没有)改成条件性问题(何时有),阴性结果就从"失败"变成"边界测绘"。主线问题的每次收窄(外挂修正器 → 末层可达性 → 位置依赖)都是这种重述。

### 入口 6:半验证机制的组合
盘点所有"单独不够但方向为正"的部件(如:共享修正在某候选集有效;某选位代理单独无效),检查两两组合是否构成未检验的新机制。合法性判据:组合后的预测与任一单独部件不同。注意与规范的"不连续加模块救阴性"区分——组合的理由必须是机制互补假设,不是堆料。

### 入口 7:链路上游一格
当某环节的所有干预族都阴性,把问题上移一格:系数生成环节榨干了 → 问原型响应/候选分配环节(TAL 选位、候选形成)。上移的依据必须是本环节的**覆盖性证据**(多求解器、多目标、证书一致说"此处无共享空间"),不是单次阴性。

### 入口 8:外部参照物定标
引入一个强外部系统(如 SAM)不是为了借它的能力,而是测"这类信息在本模型的表示里能否兑现"。外部参照失败(−4.2pp)同样有信息:说明瓶颈不在缺那类信息,排除一整族"加信息"方案。使用时成本单列,不混称等预算改进。

### 入口 9:接受范围限制,转为论文主张
如果某问题经多角度判别后确认在当前对象上无解(或解不划算),这本身是可发表的范围受限结论(如可行性证书 + 位置依赖 = "末层在训练位置已近似最优"的论文级表述)。把"困境"转写成"界限",同时主线转向下一个可动环节。判断标准:剩余假设的预期信息量 × 成功概率 < 执行成本时,收束成结论。

### 破局时的纪律红线
- 每轮只开一个新机制问题;多线程时各守各的机制族,靠只读去重避免撞车。
- 新 idea 必须能写出"此前为什么没被检验"的一句话;写不出就回到入口 1-4 重新找。
- 连续三轮同一入口无产出,强制换入口,不换领域。
- 任何入口产出的 idea,仍要走第一部分环节 3-5 的完整流程,破局不豁免纪律。

## 第三部分:速查卡(可直接贴给执行线程)

```
一轮迭代: 读冻结状态 → 找矛盾/缺口 → 成对假设+可区分预测 → 四源去重(历史/实现/数学/文献)
         → 因子化判别设计+前置解释图 → smoke→正式+身份绑定 → 支持/不支持清单+更新主线

卡住时按序尝试: ①矛盾挖掘 ②口径审计 ③oracle阶梯 ④正结果边界 ⑤问题重述
               ⑥半验证组合 ⑦上游一格 ⑧外部定标 ⑨收束成界限结论

永远不做: 改名重跑停止配置 / 扫参救阴性 / 探索集当确认 / GT辅助当部署
         / 诊断目标当效用 / 结果出来后改主指标或删样本
```
