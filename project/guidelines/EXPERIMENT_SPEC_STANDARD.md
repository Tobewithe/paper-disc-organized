## 2. 数据转换：实例身份与像素保真规范

**核心原则**：严格区分“实例身份正确”与“像素完全保真”。

*   **标准转换流水线**：
    $$\text{官方 COCO JSON} \longrightarrow \text{固定版本官方转换器} \longrightarrow \text{官方 YOLODataset} \longrightarrow \text{官方增强与训练}$$
    原始 COCO JSON 必须作为评估和像素诊断的**唯一标注真值来源**。

| 审查项目 | 必须遵守的标准规范 |
| :--- | :--- |
| **实例身份** | 1 个 COCO `annotation_id` 严格对应 1 个实例。即使目标被遮挡产生多个 polygon（如电线杆遮挡人体），仍必须合并为同一实例，严禁拆分成多行！ |
| **类别映射** | 官方 COCO 80 类别 ID 映射到连续 0–79；导出预测结果做评测时，必须恢复为官方原始类别 ID。 |
| **图片筛选** | 采用预先冻结的图片清单；选中某张图片后，必须保留该图片内的**全部有效实例**，严禁在训练或测试前擅自剔除低密度 GT。 |
| **Crowd 处理** | 训练时按既定规则排除 `iscrowd=1`；官方评测时严格保留原始 crowd/ignore 语义。 |
| **转换输出** | 转换脚本必须保存“图片—标签行—annotation_id”完整对应关系及任何行剔除的原因。 |
| **缓存安全** | 标签文件发生任何改动，必须删除旧 `.cache` 并重新构建与核验，严禁盲信旧缓存。 |
| **数据完整性对账** | 实际读取图片数、实际实例总数、损坏/跳过数必须与清单逐条对账一致。 |

*   **转换器回退漏洞防范**：
    官方转换器若遇到退化或无效的多边形，可能会隐式回退使用 bbox 生成矩形分割标签（见 [源码快照 line 90](C:/Dpan/codexproject/paper-disc/experiments/coco_clean_20260911/audits/official_converter_source.py.txt:90)）。必须对此类回退设置断言和告警，不得静默接受。
*   **像素保真认知**：
    多边形桥接（thin bridges）、重采样、栅格化和下采样均会在像素级带来形变。论文中应将这些如实表述为“标准数据预处理行为”，严禁宣传为“与原始 COCO 像素掩码完全保真”。

## 3. 监督设置与格式化审计

**核心原则**：明确并固化 `overlap_mask` 与 `mask_ratio`。

- **当前冻结基准设置**：
  - `overlap_mask: true`
  - `mask_ratio: 1`。该设置来自官方 YOLO26-seg COCO 预训练权重保存的训练配置。
- **`overlap_mask=True` 运行机理与风险防范**：
  - 该设置将全图的所有实例编码到同一张单通道实例标签图上。当实例重叠时，根据预设规则（通常按实例面积从大到小排序，小实例后画覆盖大实例）决定重叠像素的归属。
  - **强制审计**：必须验证在排序重绘后，目标框、类别、掩码和 GT 索引始终保持一一对应（参考 [audit_training_pipeline.py:67](C:/Dpan/codexproject/paper-disc/experiments/coco_clean_20260911/audit_training_pipeline.py:67)）。
- **消融与对照规则**：
  - 若探究 `overlap_mask=False` 或更高分辨率掩码，Baseline 与方法组必须同步变更，作为独立对照组。
- 原始 GT 像素诊断与误差计算一律使用 `pycocotools.coco.annToMask`，严禁使用模型训练时下采样生成的标签做精度评估。

### 3.1 配置处理

数据集路径可以按机器调整，但 COCO 类别、实例和训练/验证清单必须保持不变。其余训练参数直接沿用统一基准，不在本规范中重复抄写；只有作为诊断、消融或方法变量时才显式修改并记录。

- 先用 seed 0 判断方法是否产生值得继续验证的效应；达到预先设定的门槛后，再补 seed 1 和 2，并报告成对结果的均值与波动。

### 5.1 训练/微调实验的设计完整性与逐级解冻

只要实验涉及训练或微调，协议在启动前必须主动写明以下内容，不能等执行后补充：

- **冻结与解冻范围**：逐模块列出 backbone、neck、prototype、分类头、box 头、原生 coefficient 分支、BN affine 参数与 running statistics，以及新增模块分别是否更新，并说明原因；

- **优化器和训练预算**：优化器、学习率、scheduler、weight decay、batch、梯度累积、epoch/更新次数、增强与恢复方式；
- **checkpoint 与 seed**：seed、checkpoint 选择规则、是否使用 EMA、最终评价使用哪个固定 checkpoint，以及失败/中断 Run 的保留方式；
- **公平 baseline**：方法组与 baseline 的初始化、数据、seed、训练更新数、输入、可训练参数量级和评价流程必须可比，只改变预先声明的机制变量。

默认采用逐级解冻：

1. 先训练新增模块，原模型完全冻结；
2. 只有已有证据显示冻结范围构成限制，才解冻与机制直接相关的原生分支；

4. 不默认进行全模型训练，也不在阴性结果后临时扩大解冻范围。

训练损失、机制指标和最终任务指标必须分开判断。损失下降不能替代正常原图 mask/AP 改善；机制指标改善也必须同时报告修复、损伤、coverage、AUC/FPR、延迟或其它实际代价。阴性结果不得通过临时增加数据、解冻更多模块、扫描超参数或延长训练来挽救；只有预先登记的新问题和独立协议才能启动下一阶段。

## 6. GT—预测映射与实例指标

**核心原则：先评价固定 raw 候选的几何能力，再分析类别、置信分数与输出筛选。两层分别对应 GT，不能用第二层的成功配对决定第一层的几何结论。** 在权重、输入、预处理、推理分支及解码方式固定时，调整置信阈值不会改善同一 raw 候选的框或掩码，只会改变保留集合。此处是评价解耦，不声称分类与回归在网络训练中相互独立。

### 6.1 固定原始候选与完整身份

- GT 使用原始 COCO `annotation_id`；同一 annotation 的多个 polygon 合为一个 mask。类别、bbox、mask、image_id 保留原始含义。
- raw 候选在任何基于分数的 top-k、conf 过滤和适用分支的 NMS **之前**读取。记录模型/Run、image_id、分支、raw index、实际预测 bbox、系数、共享原型、完整类别分数，以及预处理和解码信息。也可保存可重建相同候选的冻结输入与执行快照。
- 每个 raw index 的 bbox、系数和解码 mask 为同一个整体；最终输出另有 prediction_id，并保存其 raw 来源。类别展开生成的多条输出不能冒充多个独立几何候选。
- raw 候选与“未裁切掩码”是两件事：几何基准仍按相同的正常解码流程、用该候选自己的预测框裁切。关闭裁切、使用 GT 框或更换系数均为另一个干预条件。
- bbox 与 mask 对齐到原图坐标，GT mask 使用原始 COCO 标注。不能用 mask 外接框冒充预测 bbox；空 mask 保留身份与框；NaN/Inf 单列为异常。
- 主研究使用当前正常推理分支；另一分支单独报告，不能混合两分支取最好结果后冒称正常分支能力。

### 6.2 第一层：与分数解耦的几何评价

固定上述 raw 集合，对每个普通 GT 计算候选的 Box IoU、Mask IoU 及像素错误。**候选资格、GT 关联、配对顺序及并列处理均不得使用置信分数、类别分数排名或最终输出保留状态。** 纯几何评价也不先限制预测类别；预测类别是否正确在第二层检查，否则会再次把分类失败混入几何失败。

需要区分两个问题：

1. **是否存在合格候选。** 每个 GT 保存最高 Box IoU、最高 Mask IoU 及各自 raw ID，并检查是否存在同一个候选同时达到 Box75 和 Mask75。分别的最高框、最高 mask 不能拼成一个“框和 mask 都好”的候选。独立逐 GT 存在性允许暴露候选竞争，不直接当作实例召回。
2. **这些 GT 能否同时被不同候选恢复。** 按所研究的几何任务建立一对一关联；例如在 Mask IoU≥0.75 的边上计算最大二分匹配，可评价分数无关的 Mask75 几何可恢复数。同一候选不能重复救回多个普通 GT。需要连续指标或失败代表候选时，预先声明几何匹配代价、关联门槛和确定性的并列规则，不能用分数补位。

以分割为对象的代表配对应优先依据 mask 几何，定位诊断可另用 bbox 几何；每种配对都保留自己的完整候选，不能将两种配对的指标混入一行。单个代表候选的失败也不能覆盖“其他 raw 候选已经合格”的事实。无空间关联时保留 null，不强制指定身份。

当前 Box75 / Mask75 是诊断阈值，可同时报告连续 IoU 与 0.50 等补充阈值。几何可恢复数使用 GT 选择，是能力诊断，不是正常推理召回或 AP，更不是可部署方法效果。crowd/ignore 不作为普通独立实例，保留其原始状态。

**解耦检查：** 固定 bbox、mask 与 raw ID，只改变或打乱类别分数，第一层的候选范围、关联及所有几何结果必须不变。改变候选遍历顺序也不应隐式改变规则；并列按稳定 ID 处理。

### 6.2.1 当前诊断的主分类：依据候选集合，不依据任意代表预测

对同一 GT `g` 和完整固定 raw 集合 `C`，记每个候选的实际 Box/Mask IoU 为 `b_jg`、`m_jg`：

- `B_g = max_j b_jg`，`M_g = max_j m_jg`，分别保存达到最大值的 raw ID；并列用稳定 raw ID。
- `M_B75(g) = max_{j: b_jg >= 0.75} m_jg`；无 Box75 候选时为 null。保存取得该值的完整候选及其两个 IoU。
- `J_g = 存在同一个 j，使 b_jg >= 0.75 且 m_jg >= 0.75`。等价于 `M_B75(g) >= 0.75`。

这些是 **GT 级候选集合摘要**，不是将 B_g 与 M_g 拼成某一条预测的成绩。`J_g` 才能说明存在同候选双达标。所有计算均与类别分数、预测类别及候选输入顺序无关。

| GT 级几何状态 | 判据 | 可确认的现象 |
|---|---|---|
| 存在同候选框、掩码双达标 | J_g=true | 几何候选存在，随后检查分类与输出 |
| 有达标框，没有达标掩码 | B_g≥0.75，M_g<0.75 | 整个候选池均没有 Mask75，不因换代表候选而消失 |
| 有达标掩码，没有达标框 | B_g<0.75，M_g≥0.75 | 掩码可达标，实际框质量仍不足 |
| 好框、好掩码分属不同候选 | B_g≥0.75，M_g≥0.75，J_g=false | 两项能力分别存在，但没有同候选双达标 |
| 框、掩码均没有达标候选 | B_g<0.75，M_g<0.75 | 当前阈值下两项几何均不足，不等同于没有产生 raw 候选 |

五类对有效、完整 raw 集合互斥且穷尽；输出异常或数据不完整须另记 unknown，不强塞进第五类。候选存在性是逐 GT 的诊断；涉及多少 GT 能同时恢复，仍使用第 6.2 节的一对一最大匹配。最大匹配可能有多个等规模解，某个 GT 在其中未被选中不能直接当作该 GT 的固有失败。

代表候选只用于可视化与同候选像素诊断，不决定上述主分类。例：候选 A=(Box 0.90, Mask 0.60)、B=(Box 0.60, Mask 0.90)，应进入第四类，不能因先看框或先看 mask 而在第二、三类之间切换。阈值 0.50 与连续指标作为补充，不能把 0.749 与 0.751 描述为截然不同的物理机制。


### 6.3 第二层：同一批候选为何被保留或丢弃

在第一层完成后，沿 raw ID 追踪类别判断、GT 类别得分、输出类别得分、排名、head top-k、conf 过滤、适用分支的 NMS、最终导出与评价器计数状态。不存在或未记录的阶段保持 unknown；不能统一把所有未输出写成“低分”或“NMS 抑制”。

对几何合格候选分别判断：类别是否正确；是否通过指定阈值；是否受排名/数量限制；是否进入最终输出；最终评价是否对应此 GT。**不能只追踪几何最优的一条就宣布实例漏检**：还需检查其他候选是否已正确输出该 GT。

推理阈值和预算在比较前声明；可以在同一 raw 集合上画 PR 曲线或比较匹配 Precision 下的 Recall。调整阈值后只重算保留与评价结果，不重新按分数定义几何好坏。类别无关几何合格但分类不对、分数低、排名靠后等是不同观测，并非仅凭此就定位了训练根因。

标准性能仍使用原始 COCO 全部 GT，运行 COCOeval 的 Box/Mask AP、AP50、AP75、APS/APM/APL 等。评价器按分数匹配的结果属于本层。正常输出集合与 COCOeval 实际计数集合分别记录，例如模型 max_det=300 与 COCOeval maxDets=100。Box 与 Mask 分别提供正确字段，避免 loadRes 误用框面积作为 mask 面积。

### 6.4 追查训练机制时增加监督视图

分数无关几何评价与正常输出评价保持不变。追查“为何没学好”时，额外读取**同一前向、同一标签批次**中官方 loss 的训练分配，不能将其替代为几何主映射：TAL 本身依赖类别分数与框质量，其含义是当次监督责任，不是候选天然的 GT 身份。

- 分支分别保存 `fg_mask`、`target_gt_idx`、`target_scores`，并沿增强/排序后的标签索引追溯 annotation_id；只有 `fg_mask=True` 时，`target_gt_idx` 才表示有效正样本归属。负样本处的占位索引不能当作归属 GT。
- 对每个 GT 保存正样本数量、raw ID/尺度、实际软目标权重，以及这些候选的框和 mask 质量；检查几何合格候选属于自身正样本、其他 GT 正样本还是负样本。不能只保存一个“最佳正样本”。
- 同时记录实际监督 mask、GT 框裁切范围、像素分辨率与有效像素。`overlap_mask` 的实例排序、原始 GT mask 与训练 mask 的差别分别保留；训练目标用于解释梯度，原始 GT 用于评价效果，不能互相替代。
- 损失区分全候选分类、正样本框回归、正样本实例掩码及辅助语义项；正样本数量不能替代损失权重。检查模型真实的 detach 与梯度路径，不能由一个损失名字推断它更新了原型或共享特征。
- 固定权重下重算 assigner 只称“当前分配回放”，不冒充预训练过程的历史分配。几何差不等于零正样本；某 GT 当次无专属 box/mask 正样本，也不等于所有共享特征和语义监督均消失。

8.4.100 的具体实现核对与既有回放范围见 [训练分配与损失源码核对](../../experiments/official_coco_task_alignment_20260916/REPORT.md#8-训练分配与损失源码核对)。这些记录用于定位失败，未预设要修改匹配器或增加损失。


### 6.5 同一个 GT 的两层记录

| 记录 | 含义 |
|---|---|
| annotation_id、raw ID、几何关联依据 | GT 与原始候选的可追溯关系 |
| Box IoU、Mask IoU | 同一 raw 候选的实际框、解码 mask 与该 GT 的质量 |
| TP/FP/FN、覆盖率 TP/G、纯度 TP/P、FP/G、FN/G | 同一 mask 多画与漏画了什么，分母明示 |
| 存在 Box75 / Mask75 / 同候选双达标 | 避免代表候选掩盖其他候选已有的能力 |
| 类别、分数、排名、各阶段保留状态 | 后附的分类及筛选诊断，不参与几何关联 |
| 最终对应 prediction_id、任务是否成功 | 正常输出及 COCOeval 的独立配对结果，不要求与几何最优 raw ID 相同 |

几何主分类采用第 6.2.1 节的五种候选集合状态。同候选的框/掩码四象限仅作代表候选附表，不能代替 GT 级主分类。输出层另记录最终任务是否成功，以及几何合格候选的类别/筛选状态；这些观测不能混成一个已确定物理根因的表。

无关联的连续指标为 null；有关联的空 mask 的 IoU、覆盖率为 0，纯度为 null。平均质量同时报告样本数，召回分母保留全部普通 GT。预测补表保留重复、误报、ignore 及预算外输出，不能只靠 GT 表评价多报。

像素错误可再分自身遗漏、邻居误报和背景误报；邻居像素先排除自身，crowd/ignore 单列。声称裁切导致失败时需按真实解码顺序检查支持限制，不能由一个框内覆盖阈值直接推断网络根因。模型比较以 annotation_id 对齐；内部固定 raw 位置的干预与重新匹配后的任务收益分别报告。

**掩码失败还需区分裁切支持与掩码内容。** 对固定候选 j，以实际裁切、缩放、插值及二值化流程确定输出允许覆盖的像素集合 `S_j`，其预测 mask 必须包含于 S_j。令原始 GT mask 为 G，则：

`U_crop(j,g) = |G ∩ S_j| / |G|`，并有 `Mask IoU(j,g) ≤ U_crop(j,g)`。

因为预测与 GT 的交集至多为 `|G ∩ S_j|`、并集至少为 `|G|`，这是仅由支持限制给出的理想像素上界，原型空间未必能够达到它。不能直接用原图上的连续矩形包含率代替实际解码支持。

- 若 `U_crop<0.75`，固定该预测框和输出流程，仅改善框内 mask 不可能达到 Mask75；需先考虑裁切支持。该结论是对该候选成立，不自动推广到同图所有候选。
- 若 `U_crop≥0.75` 但 Mask IoU<0.75，裁切支持没有排除达标可能，继续查看自身遗漏和邻居/背景误报；这仍不能单独确定是系数、原型或特征的问题。

TP、FP、FN 是像素记账基础；IoU、覆盖率、纯度、FP/G 与 FN/G 是它们的不同派生表达，不算多份相互独立的机制证据。按固定 GT 队列比较结果，避免只对各模型各自成功关联的实例求均值造成样本组成变化。

## 7. 实验启动检查

涉及训练、正式评价或对应专项时只检查相关项目；已经验收且相关代码未变化的部分不重复审计：

- [ ] 适用时固定模型/数据/评价协议，并记录实际版本。
- [ ] 对照只改变本次研究变量；seed、预算、checkpoint 和范围可追溯。
- [ ] 小批量运行成功且结果记录了执行状态、证据范围和限制。

训练涉及冻结/解冻时，再记录模块范围、有效样本量、优化器/学习率和阶段停止条件；修改数据转换、推理分支、损失或断点续训时，只追加对应专项核验。

只有修改了对应模块时才追加专项检查：修改数据转换时检查实例身份和标签对齐；修改推理分支时检查 One-to-Many/One-to-One 路径；修改损失时检查关闭新增项后与 Baseline 等价；使用断点续训时检查恢复状态。
