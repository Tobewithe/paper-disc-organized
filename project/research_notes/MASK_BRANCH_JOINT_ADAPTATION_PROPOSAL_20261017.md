# 大推进提案：建立原生掩码分支联合适配强基线

2026-10-17。触发指令：“我需要一个大的推进”。研究线：原型—系数链路。

**状态：路线设计已完成；新命题、预算均为提案，未冻结执行，未创建 Study/Run、未导出数据、未训练。** 本次指令支持重新审查路线并提出可执行的大实验，不默认为已批准解冻 P 和扩大到 20k。旧 RFC-v1 及其它 Run 的协议、Gate、失败结论保持；本提案不是旧 G 的 S4，也不是通过更名恢复旧阴性配置。当前动作以 [ACTIVE_PLAN](../ACTIVE_PLAN.md) 为准。

## 1. 主判断与完整研究链路

**我主张下一项主实验转向“检测冻结、原生掩码分支联合适配”：让生成 P 的网络和原生系数头一起学习，建立足以超过现有 G 的性能基线。** 这是研究层级的改变，先回答可部署的掩码适配到底能获得多大净收益；联合微调本身不作为新颖机制贡献。

上一轮推荐整理论文证据，解决的是现有结果的收束；用户现在要求大的推进，因此优先完成这个新方向的具体设计。论文整合建议暂缓，不撤销旧证据。

| 维度 | 拟议完整实验的研究链路 |
|---|---|
| **问题** | G 的全量增益仅 +0.141573 Mask AP；固定 P 的159/256条GT辅助修复见证尚未转为强部署方法。AMT、CLD、LRP和RFC已削弱对应的目标替换、方向监督、局部编辑和区域F排列方案。当前缺少同口径、充分明确预算的原生掩码分支适配基线。 |
| **机制假说** | H：固定预训练 P 只让小修正器追逐每实例目标，可能限制了“共享掩码表示—可预测系数”的共同适配；在相同输入和预算下，允许 P 参与学习可提高正常输出的净修复。竞争解释 H_alt：增加数据/更新量，或直接使用原生系数头，已足以解释收益，额外解冻 P 没有实用价值。H 是机制推导，不是本次已证根因。 |
| **针对性方法** | 一项预注册实验包含三条同预算训练臂：旧 G 结构重训、仅原生系数头适配、P 与原生系数头联合适配。以联合适配为唯一主候选；用原生 N、旧 G 和两个同预算臂分开识别实际收益、预算效应与原型参与的总配置效应。统一完整5000图AP及全22957原成功GT损伤评价，不靠多个小面板串行换方向。 |
| **整体结果** | 尚无新结果。已有G低损伤正收益和原型/系数的联合掩码计算支持投入这项基线问题；RFC失败不能证明P是瓶颈，CET也未批准真实误差结构专属原型容错。 |
| **研究决策** | 优先建立这项强基线，暂停继续给原小Adapter串行换loss/网格/门控。唯一下一步是将本提案落实为一份新Study执行合同和原生掩码头训练入口，再按新范围的授权完成预检、smoke与三臂正式训练/全量评价。当前仅设计完成。若联合适配没有超过同预算参照，则停止为“P联合适配”继续加结构；若只是预算臂变好，则如实保留预算收益，不包装成机制。 |

## 2. 支持依据及不能跨越的边界

1. [G全量S3](../../experiments/mask_gate_s3r_20261015/REPORT.md)：N 44.0141748477 → G 44.1557477428 Mask AP；损伤90/22957。存在可部署的小收益，但原 +0.30 AP Gate 未过。
2. [固定P有限修复](../../experiments/mask_repair_preservation_20261016/REPORT.md)：159/256条C见证。它证明特定实例存在系数解；不能证明共享预测器容易学会，也不能把其它97条称为数学不可表达。
3. [RFC结案](../../experiments/mask_region_f_correspondence_20261017/REPORT.md)：A−G目标IoU +.002384，95%区间[-.000092,.004873]；四项布局/等幅对照均未过。不继续押注本版8×8有序F注入。
4. [训练内审查](../../experiments/mask_soft_fit_audit_20261016/REPORT.md)及[信息链审查](../audits/repair_information_20261017/REPORT.md)：训练内损伤、目标下降而掩码退化真实存在；未证明“都是2000图太少”。因此必须配同预算G，不能仅把联合方法扩大数据后和旧2k方法比较。
5. [历史原生系数头对齐](../../experiments/coefficient_oracle_alignment_20261009/REPORT.md)已有短训损伤与迁移不足；对象是历史GT关联候选，不能冒充当前正常输出的同协议对照，也不能宣称“原生系数微调从未做过”。
6. [CET](../../experiments/mask_coefficient_error_transfer_20261017/REPORT.md)未支持真实误差协方差专属容错训练。本提案不重启该目标，不添加其压力loss。
7. [YOLACT原论文](https://arxiv.org/abs/1904.02689)以原型和系数的线性组合生成实例掩码；[YOLO26官方文档](https://docs.ultralytics.com/models/yolo26/)描述多尺度Proto和语义辅助训练。这给出研究可学习掩码分支的架构依据，**不提供本项目联合后训练必然改善的证据，也不提供新颖性证明**。2026-10-17核对，具体执行仍按本地8.4.100源码。

## 3. 三臂与两个固定参照：每个比较回答不同问题

| 身份 | 可训练部分 | 作用 |
|---|---|---|
| N，固定参照 | 无 | 同配置官方权重原生输出，Mask AP44.0141748477。 |
| G_old，固定参照 | 无新训练 | 既有2k soft-IoU＋原生掩码面积≥9216门控，Mask AP44.1557477428。 |
| G_budget，预算对照 | 原G的CoefficientAdapter，按原初始化重训 | 检查更大训练预算能否解释收益；不能只拿旧2k G当较弱参照。 |
| C_native，分支对照 | 预训练原生O2O系数头；P冻结 | 检查原生空间读出和相同预算的效用，隔离“改用原生头”与“允许P更新”。 |
| **PC_native，唯一主候选** | 预训练Proto掩码生成路径＋原生O2O系数头 | 检验在该完整训练配置中允许P参与适配是否值得投入。 |

所有训练臂用同一数据、顺序、有效batch、实际更新数、共同loss/归约、固定最终checkpoint及门控。原生头从同一官方权重初始化，G_budget从原G的initial初始化；两类网络结构和初始化不同，必须报告。C_native/PC_native共享部分初始化完全一致。

**归因限制：**PC比C具有更多有效可训练参数。PC−C只能称“允许Proto路径更新的总配置效应”，不能单独证明纯协同、特定表示机制或参数效率。三臂是建立强基线的最小实用对照，不为凑因果论证伪造同参数控制。只有出现有价值的实际效用，才另议容量匹配和机制方法；本轮不自动追加第四种新结构。

## 4. 参数与输出边界

- 固定官方权重 SHA `16b636f04e8fb6a325b3370f22dc5e5535ff473e384f4d041fd28d788f6ee9f5` 作为起点；Ultralytics8.4.100、原数据和评价配置不升级。
- backbone、neck、box/class分支、所有非掩码参数与BN统计冻结；原生检测选择、raw来源、类别、score、框及排序不变。训练副本与原生参照分离。
- C_native允许`one2one_cv4`参数；PC_native另允许`proto.feat_refine`、`proto.feat_fuse`和生成32通道P的卷积/上采样路径参数。实际完整参数名、有效数目和buffer白名单须从权重核验后冻结，不用模型名称代替。
- 新P记为Pθ，新系数记为cφ；P0/c0保留作原生参照，不能继续宣称本轮P/c0冻结。原32通道与原decoder不变。
- 推理仍使用原生掩码面积≥9216这一固定门控；门外输出直接使用原生RLE。门内分别用P0×(c0+Δc)、P0×cφ、Pθ×cφ。不能用新P覆盖全局缓存而意外修改门外输出。
- 训练监督先沿用旧G的最终输出GT关联、soft-IoU和0.1原生保护BCE的定义及归约；不同时加入新loss、语义辅助、邻域排斥或按结果富集。所有符合原规则的训练对象保留，不能只选成功修复实例。
- 训练GT只用于关联和loss；模型forward、门控、候选选择均不得读取GT。最终bbox与segm分别完整COCO匹配。

### 已查实的实现前提

[固定head.py](../../shared/vendor/ultralytics_8_4_100/ultralytics/nn/modules/head.py)中`Segment26.forward`把one2one的proto设为`proto.detach()`；[Proto26](../../shared/vendor/ultralytics_8_4_100/ultralytics/nn/modules/block.py)在训练模式可返回语义分支。**只设置requires_grad=True，不足以保证来自one2one掩码损失的梯度到达P。** 官方完整训练还有其它监督通路，此事实不表示官方P从来未训练，也不表示旧固定P实验存在错误。

本提案需独立构建冻结特征F→可训练Proto/系数→同raw最终行→同decoder的掩码训练通路；直接调用Proto的掩码路径，避免one2one中的detach切断本研究所需梯度。不修改vendor，不偷偷改官方TAL或恢复历史分配。全部BN维持eval，Proto不启用额外语义目标。初始化P/c/最终RLE重放、P/C非零梯度与一步参数变化、非白名单参数及buffers不变都须真实验证。

最近官方网页对`nms`的分支表述与本项目8.4.100语义存在版本差异；继续按`head.end2end=True`和已核验调用链选O2O，不照抄最新网页CLI改变旧基线。

## 5. 拟议完整预算与配置冻结

**推荐预算为20,000张train2017、每臂3轮、有效batch4，即每臂15,000次更新，三臂合计45,000次更新/180,000图访问，单预登记seed。** 这是新命题的拟议预算，不是已经获得的扩量许可，也不是“20k已证明能解决问题”。旧2k图作为子集，其余按与效果无关的固定规则取样，保持fit/开发隔离并保存清单；原val2017仍是反复使用的开发集合。

三臂共同使用预先冻结的优化器、学习率/调度、数值设置及数据顺序。具体学习率、参数分组、梯度累计与在线特征重放实现尚未冻结；禁止凭框架默认补齐后直接运行。G_budget是共同预算/配方对照，原G_old仍保留，不能以一个可能不适合旧架构的共同学习率把它替换掉。若资源/优化选择不能形成合理对照，须先修设计。

拟使用原笔记本，单臂顺序执行；拟训练资源上限每臂8小时、合计24小时，评价与统计合计12小时。**这只是资源上限提案，不是耗时预测。** 实际参数量、梯度显存、吞吐和存储由≤32图工程smoke实测，再决定能否在笔记本完成；不够则报告缺口，不偷偷换主机、精度或缩数据。优先在线冻结特征前向并释放逐图张量，不预先制造全20k多尺度F大缓存。

评价沿用640、原batch16/rect几何及顺序、原数值精度、conf/max_det、mask_ratio/overlap_mask、decoder、COCO API与完整JSON面积语义。即使按微批计算训练，评价输入张量不能改变。正式末轮checkpoint固定，不看开发AP择epoch；中间checkpoint只用于工程恢复。

待冻结的最小缺项：20k清单与图像/标注SHA、精确训练配置和白名单、实现/梯度/资源smoke、完整执行命令与成本上限、统计脚本与源哈希。这些未补齐前不称“协议冻结”。

## 6. 从第一次正式评价就看全量AP与精确损伤

拟议实用目标：**PC_native对N至少+0.50 Mask AP点、对G_old至少+0.30点，两个配对区间下界均>0；对G_budget和C_native分别至少+0.20点且区间下界>0，才支持优先选择联合配置。** 这些是事前的投资标准提案，不是预期或保证能达到的数值。

- 所有三臂末轮checkpoint在同一5000图、相同原生检测集合上完成完整预测/COCO AP；N/G_old直接复用通过身份核验的预测。旧S2的655配对IoU只作诊断，不是该新命题主指标。
- 原生22957个Mask75成功GT逐一检查，精确损伤≤1%；同时报告PC−G_old的损伤计数差和修复数量。零抽样误差不等于未来域零风险。Box/Class/score/order、bbox匹配身份全通过。
- 使用2000次配对整图bootstrap，所有方法共用重采样索引与冻结随机种子；声明多个必要比较和开发性质，不挑最好的一个作结论。严格机制/外推结论不靠此单seed、反复使用开发集建立。
- 同时交付推理耗时/额外计算/显存，不能把更大的训练与推理成本藏在AP后。数值成本阈值须在资源smoke后、正式训练前冻结。
- 若PC优于N/G_old却不优于同预算参照，保留实际效用，拒绝联合适配独有贡献；不能事后改选主候选并复用同一确认性声明。

| 预登记出口 | 唯一动作 |
|---|---|
| PC对原生、旧G、两同预算参照均达到实用增量，且损伤/身份/成本通过 | 将联合掩码分支作为下一阶段方法基座，之后单独冻结开发外确认与必要容量控制；本提案不自动启动第二轮训练。 |
| PC仅超过原生或旧G，未超过同预算参照 | 关闭“额外解冻P值得优先投入”的主张，保留各臂实测收益，按预算/原生头基线解释；不继续围绕PC叠加模块追分。 |
| 主效用不足、损伤超限，或有效区间仍不能达到预设决策条件 | 停止本预算下这条扩展路线；保留现有G及失败证据，收束论文，不追加epoch/seed/阈值扫描。精度不足与已证退化分别标记。 |
| 输入、梯度、检测身份、资源或统计工程失败 | 保留失败，限于原科学协议的可验证工程修复；未有效完成不能判为方法阴性。 |

这是一项从训练到全量任务验收的完整研究，不是三次各自寻找下一诊断的试错。联合微调是否有效、是否值得成为新方法基座，以及是否存在可发表机制贡献必须分开回答。
