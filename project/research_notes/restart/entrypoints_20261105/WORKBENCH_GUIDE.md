# 工作台指南

**开展或接续任务前，先核对[project/ACTIVE_PLAN.md](../../../ACTIVE_PLAN.md)的当前部分，确认目标、任务状态和执行范围，再定位本次需要读取、保存或更新的文件。** 已读且未变化的指南与资料直接复用，按本次任务和新增变化补读。

本指南规定文件保存位置、内容形式、引用方式及更新分工。科研角色与算力资源见根[AGENTS.md](../../../../AGENTS.md)，模型实验要求见[通用规范](../../../科研项目通用规范/通用规范.md)。

## 1. 各类文件保存什么、何时更新

| 文件类别与位置 | 保存内容 | 更新时机与分工 |
|---|---|---|
| 纲要：`project/outlines/<id>.md` | 某个问题的已有认识、争议、排除范围、未知和可能方向 | 研究结果改变相关认识时更新正文，引用Idea或实验报告；必要时将认识反馈到上级及中心纲要 |
| Idea：`project/ideas/<id>.md` | 核心主张、依据、来源纲要、检验思路、探索进度和研究判断 | 想法形成或证据改变判断时更新，说明哪个具体版本受到支持或限制，保留变化理由与来源 |
| 研究线登记：`project/research_lines.json` | 稳定身份、入口路径及关联的Idea／Study | 新建研究线、关联关系或入口变化时更新；不在登记文件复制完整实验解释 |
| 研究线入口：`paper/manuscripts/<line>/README.md` | 该线探索什么、主要进展、所选Idea和实验入口 | 该线的探索方向、进展或关联材料变化时更新简要综述，通过引用组织已有实验 |
| 实验登记：`experiments/<study>/study.json` | Study身份、类型、协议与报告入口、关联Idea／Run、精简状态和远端定位 | 建立实验或状态、关系、入口变化时更新；详细设计和结果分别留在协议与报告 |
| 设计与协议：`experiments/<study>/PROTOCOL_V<n>.md`等 | 对应版本的问题、方案、输入、比较与评价、预算、停止条件和交付约定 | 执行前保存所用版本，实质变更时另存版本并说明替代关系；执行当时的版本继续保留 |
| 运行记录：服务器上所属实验的`runs/<RUN_ID>/run.json` | Run身份、所属Study、实际命令与环境、输入和源码版本、作业编号、起止状态及产物清单 | 真实执行开始及状态变化时记录；失败、重试和独立评价分别留痕，本地按需保存同ID的精简回执 |
| 实验报告：`experiments/<study>/REPORT[_V<n>].md`等 | 完整研究解释与关键汇总：实际结果、预期对比、异常或失败、结论、局限和取舍，以及全流程复盘、重要能力缺口、外部学习怎样影响研究与下一步改进 | 形成阶段结果或实验结束时保存，判断变化时明确补充或更正；完整逐例数据和原始证据留服务器 |
| 交接：`experiments/<study>/HANDOFF.md`等 | 记录时点、已完成内容、未决项、证据位置、剩余预算和待接续动作 | 现有报告与当前安排不足以支持接续时保存；明确时点并引用已有内容，避免重复抄写 |
| 当前安排：`project/ACTIVE_PLAN.md` | 当前目标、任务入口、进度、暂停事项及下一动作 | 任务切换、接续或结案时直接更新当前内容，引用所属协议、报告；需要保留的旧安排移到`research_notes/restart/`并标明时点，避免在当前入口累积历史 |
| 知识Skill：`project/skills/<name>/` | 按主题保存理论、成熟思想、方法、公式、经验、反例，以及阅读和实验形成的认识与来源；`SKILL.md`为入口，较长内容放`references/` | 全部知识补入相关Skill，形成独立主题时再新建；项目内维护完整主份，用户目录保存加载副本，不以可复用程度或当前实验受益为保存门槛 |
| 跨实验笔记：`project/research_notes/<topic>.md` | 需要单独保存的综合比较、讨论或跨实验解释 | 单份实验报告不能承载时按需建立，引用原Study／Run；综合整理不产生新的实验身份 |
| 文献资料：`project/research_notes/literature/<topic>/` | 检索范围、来源清单、实际阅读范围、当时分析及相关原文资料 | 按阅读主题或批次保存，保留日期与来源身份；形成的知识进入Skill，研究目标与候选判断仍由相关纲要／Idea组织 |
| 证据来源：`project/research_notes/sources/` | 被当前文档引用的固定版本文本、来源清单与SHA | 增加来源时保存独立版本，移动时更新引用位置，快照字节及原来源版本保持不变 |
| 维护记录：`project/research_notes/maintenance/<operation>/` | 文件整理、迁移、清理的说明、清单和回执 | 按实际操作保存，明确删除／迁移范围、核验结果及未处理项；历史回执保留当时内容 |
| 写作与展示：`paper/manuscripts/writing/{documents,drafts,presentations}/` | 写作文档、稿件、汇报材料及图源 | 按材料类型保存版本并引用研究证据，不作为新的研究线或实验登记 |
| Idea演变：`project/research_notes/IDEA_EVOLUTION.md` | 主要想法形成或转向的简短轨迹、变化原因和来源 | 主要Idea形成或实质变化时续写，不重复实验报告或纲要全文 |

沿用已有文件名、目录、ID和扩展字段；表中命名是保存范式，不要求重命名现有材料。实验可被多条研究线引用，不因换目录、论文归属或补关联而复制Study／Run身份。

**全部知识以Skill作为唯一维护正文。** [知识入口](../../README.md)按问题连接Skill、阅读记录与项目判断；[Skill主份目录](../../../skills/README.md)保存完整内容、来源和清单。理论、经验、反例和具体实验形成的认识均可保存，无须脚本或当前实验收益。研究Idea和纲要不是知识，不纳入知识迁移；目标、候选方案、预算与下一步保持研究组织身份。用户目录是加载副本，更新时从项目主份同步；原阅读、历史分析和实验材料保留证据与时点，不以迁移为名删除或改写旧结果。项目笔记引用Skill，不另行维护知识正文。

**同一事实有明确出处，其余位置引用。** 实验数值与原结果解释由报告承载，研究目标与候选判断由相关纲要／Idea承载，形成的知识由Skill承载，当前行动由总控承载。只更新被新证据实际改变的内容，不要求每次贯穿所有层级；已有报告足以接续时，不另造交接或历史副本。

## 2. 最小保存范式

以下示例区分文件职责，只创建本次确实需要的文件：

```text
project/
  outlines/<OUTLINE_ID>.md
  ideas/<IDEA_ID>.md
  research_lines.json
  ACTIVE_PLAN.md
  skills/<name>/
    SKILL.md
    references/
  research_notes/
    README.md
    literature/<topic>/
    sources/
    restart/
    maintenance/<operation>/
paper/manuscripts/writing/
  documents/
  drafts/
  presentations/
experiments/<study>/
  study.json
  PROTOCOL_V1.md
  REPORT_V1.md
  HANDOFF.md
  REMOTE_STORAGE.json
```

协议可直接承担设计说明；只有设计讨论需要单独保存时才另设`DESIGN.md`。报告已有可引用的数值汇总时直接复用；程序需要读取小型汇总时，可按需保存`RESULT_SUMMARY.json`并在报告中引用其来源和版本，避免并行维护多份数值总表。

纲要与Idea使用Markdown正文和frontmatter保存身份及关联。纲要注明`id`、`kind: outline`、`title`，有上级时填写`parent_id`；Idea使用`kind: idea`并通过`outline_ids`关联来源纲要，`line_ids`可为空，例如：

```yaml
---
schema_version: 1
id: IDEA_EXAMPLE
kind: idea
title: 想法名称
outline_ids: [OUTLINE_EXAMPLE]
line_ids: []
exploration_status: candidate
assessment: unknown
---
```

正文说明想法与依据、如何检验、当前认识及证据范围。探索进度和研究判断分别保存；示例ID需换成实际稳定ID并引用已存在的纲要，保留未知，不根据文件存在或进度自动填写科学结论。

`study.json`用`study_id`、`title`、`kind`说明实验身份与类型，按需保存关联和入口；完整Run记录在所属服务器实验目录的`runs/<RUN_ID>/`中。本地精简回执沿用同一Study／Run ID，明确服务器位置及本次实际核验范围，不把回传另记成一次新运行。

## 3. 每次实验结束后的反馈流程

**研究围绕下面四件事推进，可交替进行。实验结束后主动反馈与复盘，发现重要能力缺口时主动向外学习，无须等待提醒。**

1. **明确问题。** 说清本轮要解决什么、已有证据是什么，以及什么结果会改变选择。优先处理影响研究方向或结论的关键未知，复用已有认识。
2. **学习与选法。** 从目标、现象和已知条件出发，借助教材、专著、可靠综述与经典研究定位相关的成熟思想和方法知识，再沿引用与研究脉络深入代表性工作。允许文献修正问题表述，不受现有Skill或熟悉算法限制。比较原理、证据、适用与失效条件，说明知识为何相关及仍存疑之处；形成的知识补入Skill，必要工具随所属Skill维护，有合适问题时应用。
3. **做可信检验。** 设计能区分关键解释的适当比较，核清基线、主要训练条件、数据用途和评价口径。探索允许随证据调整；正式确认前明确关键比较、预算和停止依据。验证强度随主张与决策影响调整，具体要求见[通用规范](../../../科研项目通用规范/通用规范.md)。
4. **判断与积累。** 主结果可信后及时说明结果、可能原因和方法取舍，区分事实与推断，结合波动、收益损伤和成本决定继续、修正、转向或停止。复盘影响结论与下一步的关键问题，将新增认识写回相关Idea、纲要和能力内容；反复失败时重新审视问题与前提。

**学习质量取决于知识的依据与实际掌握，不以当前实验是否受益为前提。** 当前问题决定学习重点，也为重要基础和有价值的新方向保留空间。理解应体现在能够解释原理、辨别适用与失效条件、比较替代方案；高质量知识即使暂未用上，也可积累为能力。与当前问题的相关性和实际效用分别判断，新证据继续修正认识。

**证据足够就行动，信息不足就保留未知。** 已有证据能回答的问题直接复用；新增学习和验证用于解决关键缺口，不要求固定论文数、seed数或每轮新建Skill。阴性结果也可支持本轮取舍，具体方案的成败与更大命题分别判断。

记录只保留支持判断和接续所需的条件、结果、来源与下一步，沿用已有报告和笔记，按实质变化更新。学习掌握、Skill修改、当前对象检验分别说明进展；实现可运行、方法有效和机制成立分别判断。已安排而未执行的检验保留待办，原实验结案不自动完成后续验证。

## 4. 引用、版本与更正

Markdown正文链接相对于当前文件；结构化`evidence.path`以项目根目录为基准，或使用已有实体ID，并记录实际来源版本／SHA及必要定位。验证记录应能追到当时Idea版本、所属Study、Run和原始证据；事后补关联如实说明整理时点，不改写成事前登记。

协议或主张实质变化时保存新版本及变化原因，可用`supersedes`／`superseded_by`关联前后版本。更正结果时说明原记录、修正依据及影响范围，保留执行时的协议、Run、原始产物和冻结快照；文件迁移继续沿用原身份，记录位置变化。

## 5. 本地与服务器的保存分工

**完整实验数据与执行产物保存在所属服务器。** 本地保留知识Skill主份及其必要配套文件、阅读与研究笔记、纲要／Idea、设计与协议、研究报告、精简Study／Run信息及服务器定位／SHA回执；实验数据集、标签、完整预测、逐例明细、特征、权重、日志、图像、执行代码、压缩包和完整冻结快照均留服务器。

远端定位可集中保存在现有`study.json`、报告或交接中，确需独立清单时再使用`REMOTE_STORAGE.json`。定位记录写明主机、目录、对应Run、产物或清单的SHA、核验时点与结果；摘要引用该记录，避免在多处维护同一份长清单。未知、未完成及未回传状态明确保留，本地文件缺失不能单独证明服务器没有运行。

实验实现、数据处理、统计复核及完整性核验在服务器完成，不为本地复算下载完整Run。已有本地实验副本先核验服务器原件或归档的内容与SHA，再清理并保留回执；按需临时查看的图像用后移除，用户另行指定本地处理时按其指令。

## 6. 落盘与更新检查

Git元数据、工作台自身索引、AGENTS／README、必要工具配置及本指南引用的文件维护脚本属于基础文件。按用户要求，知识Skill的完整主份、来源、必要配套脚本和恢复清单保存在本地项目；环境依赖、生成缓存和实验整套产物仍按服务器留存分工，不以改后缀或放入Skill目录改变其身份。

完成本次修改时核对已改文件的ID、路径、版本、引用及状态是否相互对应，说明哪些文件已更新、哪些反馈或证据仍待补充。普通代码或文档编辑不额外建立Study、Run或交接文件，不为格式完整编造状态、来源或结果。

直接修改源文件并保留其他会话的改动，出现修订冲突时重新读取后合并。工作台数据库、`.research/`和`project/structure.json`不手工编辑，不擅自运行`sync/validate`；共享资料通过工作台界面／API保存，其独立主库和修订历史不能当作可丢弃的索引。

修改指南、规范或任务路由后，在本地运行`python project/check_active_plan.py`核对读取入口与链接。修改Skill主份后按[维护说明](../../../skills/README.md)更新派生清单，用[Skill检查脚本](../../../check_skills.py)核对文件、版本与加载副本。检查验证文件一致性与路由；知识质量、掌握程度、工作台索引和科学结论分别按实际依据判断。
