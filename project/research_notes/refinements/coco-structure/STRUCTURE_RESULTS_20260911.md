# COCO 结构诊断：实例差异在哪里仍然存在，预测在哪里损失

日期：2026-09-11。第一轮结果；官方预训练模型冻结，原 CCL 正式训练仍暂停。

**当前最值得追的是“已有空间信息如何被实例解码利用”，而不是继续假定“系数相似就是根因”。** 本轮发现严格框定位候选经过 NMS 时有损失；同时，已有较准框的 GT 仍有不少掩码失败。原型上的 GT 辅助读出优于模型实际系数，但图像坐标对照也很强，因此尚不能确定系数头是唯一瓶颈。

## 1. 实际完成的范围

- 远端 COCO val2017 的既有 300 张探索图片，3,635 个非 crowd GT，其中单实例 ICI>0.5 的高组 788 个、其余 2,847 个。图片按密集场景富集，并非全 COCO 的代表性抽样；这些图片此前已被探索。
- 1,174 个同类相邻 GT 对（框 IoU>0.05），其中至少一个实例高 ICI 的对有 877 个。任务分母保留漏检，未把多个 polygon 拆成多个 GT。
- 16 处表示：主干 4/6/10、neck 16/19/22、分类/框/系数分支各三个尺度，以及共享原型。得到 66,960 条探针记录；随机投影种子在同一对内平均。
- 冒烟与执行见证：val 4 图；额外 train 32 图、380 GT。train 见证排除此前适配训练的 1,200 图，仅验证执行，不构成新的方法训练或跨图泛化结果。首次 train 见证因已选图片没有落盘而停止；修正为实际可用 JPEG 池的哈希选择后完成，失败目录保留。
- 实测运行的是 one-to-many 分支加按类 NMS。所有 300 图均通过原始候选 source index、系数、框和原型的精确重放，缓存最大误差为 0。

模型为官方 `yolo26m-seg.pt`，权重 SHA256 `16b636f04e8fb6a325b3370f22dc5e5535ff473e384f4d041fd28d788f6ee9f5`。FP32，禁用 TF32；640 输入，conf=0.001、NMS IoU=0.7、输出上限300；COCOeval 每类每图 maxDets=100。图像、原标注及源码哈希见运行 protocol。主300图推理与探针用时162.07秒，另有统计与审查耗时。

## 2. 框与掩码都按 IoU=0.75 比较

这里的 R75 是官方 COCO 匹配下的 GT 微平均恢复率，**不是 AP，也不是固定 Precision 下的 Recall**。框与掩码各自执行官方匹配，匹配的预测身份可能不同。

| 指标 | 高 ICI，788 GT | 其余，2,847 GT |
|---|---:|---:|
| Box R75 | 72.21% | 74.11% |
| Mask R75 | 53.05% | 59.29% |
| 框匹配成功、掩码未匹配成功的 GT | 164（20.81%） | 486（17.07%） |
| 掩码成功但框不成功的 GT | 13（1.65%） | 64（2.25%） |

高组 164 个 GT 有合格的框匹配而没有合格的掩码匹配，说明有必要单独研究掩码解码。它并不等于“同一条预测的系数造成164次失败”，也不能仅把两个 R75 相减当作纯掩码模块的因果损失。

对于高拥挤同类相邻的877对，两实例同时 Box R75 成功为 **61.92%**，同时 Mask R75 成功为 **42.30%**。这里也采用相同 IoU；不是以宽松框阈值对比严格掩码阈值。

## 3. 候选筛选损失存在，但尚未证明是密集场景特有问题

下表检查每个 GT 是否还存在至少一个框 IoU≥0.75 的候选。它是逐 GT 的非独占候选可用率；同一个候选可能同时对多个 GT 合格，不能把它当成可实现的召回率上界。

| 阶段 | 高 ICI | 其余 |
|---|---:|---:|
| 原始候选有合格几何框，类别不限 | 83.38% | 85.46% |
| 加上候选 argmax 类别正确 | 82.23% | 82.16% |
| 加上分数过滤 | 79.82% | 79.98% |
| NMS 后 | 73.86% | 74.89% |
| 输出前300、空mask处理后 | 73.35% | 74.57% |
| 每类前100后 | 72.46% | 74.11% |

高组分数过滤到 NMS 的可用率下降 **5.96个百分点**，图像簇 bootstrap 的95%区间为 **[4.28,7.70]**；低组下降5.09个百分点。这个损失可能包括“留下了 IoU 较低但得分较高的同一实例候选”，不能直接解释成“另一头猪被压掉”。低组也有类似现象，尚未进行类别、尺度等组成控制。

如果改用框 IoU≥0.5，高组 NMS 阶段可用率只下降0.76个百分点。这说明较严格的定位质量与候选排序值得检查，不能笼统声称 NMS 导致大量完整实例消失。下一项诊断应追踪被压制候选与保留候选的 GT 归属和 mask IoU，而不是直接关闭 NMS 宣称方法改善。

## 4. 原型能区分实例，但实际系数没有充分利用这一点吗？

先固定同一对实例的自身独占和邻居独占 GT 像素，按空间块分成拟合与检验两部分。原型保持冻结，用32维线性读出器测试这两类像素能否分开。AUC衡量正负像素的排序，不衡量零阈值下的最终掩码正确率。

下面所有数值来自**同一批176个高拥挤同类相邻对**：需要有足够像素，且目标 A 有官方 bbox50 匹配；不要求 B 匹配。

| 自身与邻居像素的分数 | AUC |
|---|---:|
| 模型实际目标系数 `c_A^T p(x)` | 0.9341 |
| 仅二维坐标的 GT 辅助线性读出 | 0.9612 |
| 冻结32维原型的 GT 辅助线性读出 | 0.9929 |
| 打乱拟合像素标签后的原型读出 | 0.5213 |

原型读出相对实际系数的配对差为 **+0.0588 AUC**，95%图像簇区间 **[0.0439,0.0754]**。原型读出相对二维坐标为 +0.0317，区间[0.0214,0.0425]。这些区间是探索性点态区间，不是多重检验后的确认结果。

这说明：在本探针及这些合格实例上，冻结原型中仍有可由线性方向访问的目标/邻居差异，实际系数方向与该辅助方向的表现存在差距。**这支持继续检查系数选择及相邻实例的相对响应；不支持“特征已经完全混成一团”或“系数正交化必然有效”。**

但空间位置本身已非常容易区分两头猪。原型与二维坐标的容量也不同，棋盘空间块的感受野有交叠；原型与坐标的3个种子没有带来3次独立模型训练。打乱标签的均值0.5213也未恰好落在0.5，且相同长度标签的随机置换跨图复用，当前图像bootstrap没有覆盖重新抽取置换的随机性。这些因素要求下一轮使用更严格的空间、容量与标签对照，不能将0.9929写成最终实例分割能力。

逐层结果也没有显示“越深越不可分”的单调趋势。例如186个合格高对的 stride8 主干/neck/系数分支 AUC 分别约0.806/0.893/0.932，而原型约0.992。因为通道>32的层只做了32维随机投影，尚缺原维数读出；不能用这组跨层差值定位哪层损坏了信息。

## 5. 一个有具体结构含义的新线索：相对响应

限定为 A、B 均 bbox50 匹配的同一批167对：

| 像素分数 | 自身/邻居 AUC |
|---|---:|
| 单目标响应 `c_A^T p(x)` | 0.9399 |
| 两目标响应差 `(c_A-c_B)^T p(x)` | 0.9699 |
| GT 辅助原型读出 | 0.9933 |

响应差相对单目标分数的配对改善为 **+0.0300 AUC，95%区间[0.0186,0.0424]**。它不需要拟合新系数，但这次使用了 GT 选择邻居和评价像素，尚不是可部署方法。表内以A为正类，尚未同时报告交换A/B后的单目标对照；背景没有纳入这项二分类，输出两个互斥掩码还可能损失覆盖。

数学上，`z_A(x)-z_B(x)=(c_A-c_B)^T p(x)`。它直接判断同一像素更支持哪个实例，比两个系数的全局余弦更贴近实例归属。新的候选主张可以表述为：**共享原型中仍有可读出的实例差异，独立目标响应与相对实例归属之间可能存在尚未被利用的信息。** 这是待验证假说，并非本轮已建立的因果链。

## 6. 下一步的有界干预及停止条件

继续保持模型冻结，最多先追以下两条，而不同时增加多种训练损失：

1. **固定原型、框、类别和置信度，检查相对实例归属。** 邻居仅从预测中选择；先在预先固定的train开发图冻结选择规则和干预幅度，再比较原解码、同幅度随机邻居/方向、单目标阈值控制与响应差干预。正常裁切、共同支持域和外扩环分别报告自身覆盖、同类邻居错误、背景错误、Mask R75及相邻对恢复。若收益只来自缩小掩码或背景减少，停止“邻居分离”主线。
2. **用现有原始候选追踪 NMS 前后的替代关系。** 区分同一个GT的定位质量损失、两个不同GT的候选竞争、候选预算；先做 GT 辅助机会分析，再判断是否值得设计可部署的质量排序。不能把辅助替换的指标当成可实现方法。

逐层探针仍需补原维数/等容量空间对照、近接触区域、类别与尺度控制，以及更严格的空间划分。高低组比较目前没有完成这些控制。第一轮的作用是缩小干预范围，不能把 S003 全部标成完成。

旧 CCL 外扩优势仍可作为动机，但与这里的冻结官方模型探针属于不同实验。没有完成的干净 COCO CCL 配对权重，本轮不评价 CCL 效果，也不以这些 AUC 解释旧 CCL 的 AP 增益。
