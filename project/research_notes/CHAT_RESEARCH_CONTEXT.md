## A. 给新 Agent 的一段话

**双方目前赞成：**研究固定的 YOLO26m-Seg 原型—系数链路，优先查明「同一最终检测中，有限 Oracle 已找到的有用系数方向，为什么没有被无 GT 的 adapter 安全兑现」。不要未经证据便把 Mask75 失败归结为「32 维系数不够」，也不要因为负结果就不断增加 loss、teacher、门控、rank、训练预算。

实际研究至少有四个不同环节：**给定 P 能否表达 → 训练监督能否找到有利变化 → 模型能否预测该变化 → 推理时能否安全应用**。Prototype 自身也是训练产生的，因此「当前 P 的质量不好」「有效秩低」「原型网格分辨率不足」「通道数量 32 本身不足」还不是一个能由固定权重实验轻易拆开的原因。

**当前不启动新训练。**截至本摘要核对，仓库唯一总控报告 S3 已结案、S4/20k 未批准，下一项应是同检测 Oracle—Adapter—Gate 的零训练机会兑现分析，**尚待单独冻结协议**。

## B. 对话确认的科研工作方式（研究偏好）

1. 一个明确、可证伪的科学命题，事先规划**完整证据链**，写清比较对象、数据及候选身份、主次指标、阶段依赖、停止条件、最大资源与交付。不接受每次实验未过之后漫无目标地试新模块。
2. 每个结果需从已保存的 Run 和评价合同得出**唯一有依据的下一决策**；阴性也必须给出正向的知识收获，而不是只说「还有很多可能」。
3. 当前方法研究固定官方训练完成的模型、框/类别/分数、检测输出、原 Prototype `P` 和原系数 `c0`，围绕无 GT 的后训练 `c'=c0+delta_c`。TAL 历史审计用于纠正证据口径，**不是本后训练研究的强制前置 Gate**。
4. 用户和助手认可：数学表示能力与训练学习问题在实践中不易严格分离；新的机制解释不能因为一个有限求解器失败就写成数学定理。
5. **COCOval2017 已多次参与选择**，因此开发期 AP 改善及其 bootstrap 区间不能自动声称为独立盲测确认。

## D. 核心争议：「32 维容量不足」到底有多可靠？

**已经确定的数学事实：**对一张图像冻结的 `P∈R^(HW×32)`，连续 mask logit `z=Pc` 只能位于 `P` 的至多32维列空间。**这只说明表达空间受限，并不证明任何一张失败的 GT mask 在该空间内无法达到 Mask75。**阈值化还能从连续组合产生大量二值模式。

**目前不能直接接受的主张：**「32 维不够导致大多数实例分割失败」。根据现有 S1 正向见证，这个笼统结论的把握低。相比之下，「可恢复的系数方向未被当前模型可靠预测／兑现」已有较强证据支撑。

**必须区分的竞争解释：**

- `H_capacity_or_P_quality`：现有 P 的表达/有效秩/分辨率/框支持不足，甚至 32 这个数量不足。**这一族仍未被严格识别为主要失败原因。**
- `H_objective`：BCE 等训练目标与原图二值 MaskIoU 不一致；优化目标下降却损伤正确前景，已有受限范围内直接记账。
- `H_prediction`：32D 下本来有满足 Mask75 的系数，但原始 `c0` 和无 GT adapter 预测不到有益方向；S1 有机会见证，目前缺其与 adapter 输出的逐条兑现联查。
- `H_selection`：adapter 已经把某检测修好，但应用 Gate 拒绝；或者全输出应用伤及原成功 GT。S3 说明选择能帮助安全，**尚不证明 Gate 拒绝是当前+0.3不足的主因**。

**不对称判定：**找到一个在固定P/框/decoder下达到Mask75的具体 `c`，可证「此实例32D已足够到达门槛」。有限 LBFGS/BCE 未找到只能记录「当前 oracle 未恢复」，不能当作「不存在任何达标系数」的证明。扩大函数类以后仍可能因正则 BCE 目标或求解结果，在最终 Mask75 上丢失旧成功实例；因此 Q-all 的新增28与丢失18不能直接解释成容量极限。

即使某个精确二值图案在P空间数学上不可表示，也**不等于**不存在另一个32D图案达到足够的 MaskIoU。若将来专门研究容量，需区分「固定 P 的限制」与「把 Prototype 个数从32变为64/128的训练容量对照」，后者要控制新训练出来的 P 和优化条件。

## E. 已讨论并赞成的唯一后继科学问题（**待冻结，不自动执行**）

**先不训练：**对 S1 哈希固定的 256 个 `(image_id, annotation_id, output_detection_id[, raw_id])`，复用原有 P/c0、预测框和真实 decoder，关联三种结果：

1. `O`：原 S1 **GT辅助**有限32D Oracle（只作为机会参考）。
2. `B`：同一最终检测不加 Gate、应用原 soft-IoU adapter 的 `delta_c` 后的 **MaskIoU和Mask75**。
3. `G`：仍是同一最终检测，按已冻原生面积≥9216的 Gate 决定是否使用该 `delta_c`，再测 **MaskIoU和Mask75**。原生输出 `A` 一并保留。

**只在 O 已恢复的 122 条里，按同一最终检测的二值 Mask75 定义划分：**

| 观测 | 具体证据意义 |
| --- | --- |
| `O通过，B通过，G通过` | 有用方向已预测并安全保留 |
| `O通过，B通过，G失败` | **Gate 将已有的同检测有效修复撤回** |
| `O通过，B失败` | **Adapter 没能兑现已知存在的32D修复解** |

**论文假说分叉（尚未设定阈值）：**
- Gate 撤回已生效修复占主要机会损失 → 优先研究安全效用选择器，而**不是扫面积阈值**；
- Oracle可修但Adapter没有产生有效修复占主要机会损失 → 优先研究有益系数方向的学习信号、特征与目标，而不是简单放宽 Gate；
- 证据不足、两者接近或身份无法核对 → 维持当前配置结案，不把猜想改称定论，不以这一步为无限诊断循环的借口。

## H. 2026-10-16 讨论补充：BCE 优化与二值 Mask 质量如何对齐？

> **记录性质：**用户要求将上一轮「可以有哪些思路」的讨论收录在这里。下述方法优先级是**助手依据已有证据提出的候选研究判断**，不是用户逐项确认的方法选择、不是新增实验的冻结协议，也不授权 Agent 直接换 loss 或开训。优先执行的仍是 [ACTIVE_PLAN](../ACTIVE_PLAN.md) 指向的「同检测 Oracle—Adapter—Gate 机会兑现核对」。

### H1. 这个问题至少有两处不同的错位

1. **连续损失 → 首次二值判定：**在「BCE下降、最终原图IoU下降」的固定 3950 个监督配对中，**2159/3950** 在原 proto 同 ROI 上的二值 IoU 就已下降；另有 **1507/3950** 的 proto 同 ROI 二值 IoU 已改善，但最终原图 IoU 下降，剩余 **284/3950** 在 proto 同 ROI 持平。这不是同一个原因。见[原型网格一致性审计](../../experiments/mask_readout_proto_consistency_20261014/REPORT.md)。
2. **首次二值判定 → 原生解码／原图评价：**上述 1507 对说明变换、支持范围和/或二值化后原生缩放的环节仍可能改变最终结果，但该统计**没有独立隔离**某一个插值或裁切算子；不能直接宣布是 decoder Bug。

对已固定的 2159 个第一类异常配对，[BCE像素贡献分解](../../experiments/mask_readout_bce_decomposition_20261014/REPORT.md)发现 **2051/2159** 的 BCE 降低主要来自二值标签未翻转的像素，**1998/2159** 的 IoU 下降主要由前景损失占优。一个典型机制是错误背景 logit 从很大的正值下降但仍大于0，BCE大幅改善、FP仍是FP；同时原本略大于0的正确前景越过0变为FN。实际固定 \`P\` 下，改变同一个 \`delta_c\` 会同时影响很多像素，容易出现前景保持和背景清除之间的权衡。

**理论界限：**BCE 本身是合法的逐像素分类概率损失，不应写成「BCE 从数学上与二值分类不一致」。这里的可观测矛盾来自**有限的联合表示、有限训练／正则预算、实例级IoU与像素级损失的不同权重，以及硬阈值／解码路径**；上述各项的相对因果贡献尚未全部识别。

### H2. 已经尝试过什么，不能换名字重跑

- [同 ROI soft-IoU 2k Pilot](../../experiments/mask_readout_soft_iou_pilot_20261014/REPORT.md)：目标增益点值 +0.006799（IoU单位0—1），但开发CI下界未过0；总体 IoU 下降、原成功损伤 \`53/1024\` 且单侧上界超过1%；**原配置关闭**。不能说「换成IoU Loss就能解决」。
- [原生输入尺度 BCE／邻居排斥 E4](../../experiments/mask_readout_aligned_repulsion_20261015/REPORT.md)：R/REP 两臂目标改善约 +0.009783/+0.009617，原成功损伤仍分别 \`57/1024\`、\`52/1024\`；排斥增量没有达标。**把BCE从proto搬到输入尺度，并未解决安全保护**；此处仍非最终原图二值Mask的可微监督。
- [S3 原面积选择](../../experiments/mask_gate_s3r_20261015/REPORT.md)：现有 checkpoint 配合固定 9216 门控在完整 5000 图获得 \`+0.141573\` Mask AP 点、\`90/22957\` 原成功损伤（0.392%），但未达 +0.3 AP 门槛。它说明**修正对象的选择本身重要**，没有证明 Gate 丢掉了大部分 oracle 可恢复机会。
- 已关闭的 E1 Gram 排斥、E2 球面更新与 E4 固定排斥**不得作为「下一轮改个权重再试」的默认入口**。任意新对照应说明相对于这些已测配置究竟多隔离了哪个机制。

### H3. 值得讨论的机制候选（**尚未实施，非并行启动清单**）

| 候选思路 | 对应的实质问题／假说 | 必须避免的误读 |
| --- | --- | --- |
| **第一候选：阈值 Margin + 正确像素保持** | 在**真实首次二值化前的 logit**上，推动当前错误像素越过0，并给原本正确、接近0的前景／背景留安全间隔；直接针对FP→FP无效降损与TP→FN误伤。 | 并不能保证hard MaskIoU增加；固定P的一个系数依旧影响全部像素。与旧通用soft-BCE保持项不是相同目标。 |
| **Lovász-Hinge 标准对照** | 排序型 Jaccard/IoU surrogate，相比前一轮 soft-IoU 有不同的误差加权方式；适合作为**先验参考**，非自创loss。 | 「soft-IoU失败」不等于「Lovász必然成功」；不能跳过同分母安全Gate。 |
| **前景／背景非对称目标** | Tversky类或前景漏检权重：专门检验已见的正确前景被损失主导。 | FN减少可伴随FP增加；不能看结果后扫描\`alpha/beta\`追阳性。 |
| **原生解码感知监督** | 对齐实际\`input_hw\`、\`ratio_pad\`、框支持及首次阈值前连续logit；必要时单独评估硬二值算子的可微代理。 | E4已测输入尺度BCE且未通过安全护栏；硬阈值后的STE／平滑代理梯度不是实际硬解码梯度，也不等于真实部署改变。 |
| **最小扰动／成功像素保护** | 训练GT允许标记当前已正确且不应越过阈值的像素；限制\`delta_c\`造成的非目标翻转，并量化FP修复和TP损失的冲突。 | 训练时可用GT，但**推理时不允许输入GT**；保护约束和修复约束可能在32D空间冲突。 |
| **分离方向预测和风险选择** | adapter负责\`delta_c\`、可观测条件的Gate负责是否用；比较门控前后真正的同检测修复。 | 目前不批准直接训练新Gate；应先确认瓶颈在\`adapter\`还是\`gate\`。 |

一个用于讨论的候选形式（参数、ROI、数值网格**尚未冻结**）：

\`\`\`text
s(u) = 2*y(u) - 1
z'(u) = DecodeToPreThreshold(P, c0 + delta_c)[u]

L_flip = mean_over_fixed_errors softplus((m - s(u)*z'(u))/tau)
L_keep = mean_over_fixed_baseline_correct softplus((m_keep - s(u)*z'(u))/tau)
L = L_flip + lambda*L_keep + mu*||delta_c||^2
\`\`\`

这里的\`fixed_errors\`、\`fixed_baseline_correct\`只能通过**训练标签**冻结生成；在推理时既不读取GT，也不依赖GT决定哪些像素或检测被修改。监督ROI内的像素平均与图／实例平均应各自声明，避免小目标受到背景像素数的无意稀释。边界\`m=0\`与正margin、\`tau\`、权重以及\`lambda/mu\`都需科学运行前选择和冻结，不能在看到AP后调优；该式不是已经实现、验证或定稿的损失。

### H4. 我们认为最有判别力的下一步次序

**步骤0（现行唯一待冻结问题，零训练）：**遵守第E节与[当前总控](../ACTIVE_PLAN.md)，在 S1 的256个固定最终检测上先区分\`O成功→B失败\`（已知32D解、adapter未兑现）与\`O成功→B成功→G失败\`（adapter已兑现、Gate撤销）。这里的 O/B/G 分母、检测身份与完整RLE必须保持一致。现有189个COCO任务GT修复不可直接替代。

**只有当步骤0的新有效证据主要指向学习／优化缺口**，才将下面作为**新的待立项方法假说**：

1. **零训练的等口径系数 Oracle 比较：**在同一S1固定身份、相同P/c0/框、原生decoder、GT可见的离线求解域，预先锁定同一空间网格、GT ROI、正则与求解预算，公平比较旧式像素BCE与 Margin+正确像素保护的有限求解见证；记录新增成功、丢失成功、全体实际hard MaskIoU、FP/FN与前景损伤。若只是拿旧proto-BCE Oracle和新输入尺度Margin作比较，网格也在变化，**不能把差值单独归因于loss**。
2. **若新目标有实质互补恢复见证且不会大量丢失原有效实例**，再新建严格冻结的2k无GT adapter 单变量训练协议，对照同网格同预算BCE；最终用正常decoder与旧G2/G3任务/损伤合同判定。Oracle 正向只证明优化目标下**存在被找到的系数解**，不证明无GT网络能够学习／泛化；原Pilot及S3阴性不得重判或覆盖。
3. **若离线对照没有正向证据或校验不充分**，保持该loss思路为猜想并终止本配置；不启动盲目的\`Lovász→Tversky→Boundary→STE\`串行试错。
