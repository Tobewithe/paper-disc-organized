# 工作台记录与目录约定

本约定由用户要求统一工作台记录和产物迁移而建立。它约束文件组织与来源记录，不替代各论文的科学问题、实验协议和判断标准。

## 组织层次

- paper-disc 是研究方向的工作空间，包含独立的研究问题、实验、共享资产以及多篇论文研究线。实验可以先于论文开展。
- 当前本机论文线入口为 `paper/manuscripts/neighbor_sensitive_p3/`；研究问题、发展计划和证据对应关系从该目录读取。
- 笔记本并行线是同方向的另一篇独立论文：预测修正收益的选择性掩码读出校准，当前稿件入口为 `paper/manuscripts/mask_boundary_calibration/README.md`，源实验报告仍为 `experiments/mask_boundary_route_20260914/REPORT.md`。它保留独立的问题、论证和研究计划。
- Study、Run、Artifact 和 Note 独立保存科研记录。实验 Study 与论文是可选的多对多引用关系：一个实验可以没有论文引用，也可以被一篇或多篇论文引用；论文不独占实验。共享数据、代码和文献也只保留一份主来源。
- 诊断分析属于实验，和方法、消融、复现实验使用同一组织方式；以 study.json 的 kind 区分类型，不按类型拆分新建实验的顶层目录。
- 论文引用哪些实验由 `project/research_lines.json` 各条线的 `study_ids` 记录，同一 ID 可以出现在多条线中。没有论文关联是有效状态，不要求补填或创建占位论文。具体证据及其版本、范围另由论文证据表明确引用。
- 主机、磁盘目录和进程是位置与执行信息，不决定科研归属。

## 新增文件

| 内容 | 当前约定 |
|---|---|
| 每篇论文的主入口 | `paper/manuscripts/<论文线>/`，README 连接发展计划、证据表、正文和研究单元 |
| 一项新实验（含诊断、方法、消融、复现） | `experiments/<稳定目录名>/`，study.json 保存稳定 ID、类型及入口；论文关联可为零个或多个；各次执行放入独立的 runs/<Run ID>/ |
| 已有诊断实验 | 本副本已统一到 `experiments/<稳定目录名>/`；在其中的 `runs/<运行名或 Run ID>/` 追加执行，不再使用 diagnostics 顶层链接 |
| 共用资产和代码 | `assets/`、`shared/`；保存来源及具体使用版本 |
| 跨实验的决定和未知项 | `project/research_notes/` 中关联研究问题、实验或证据；面向某篇论文的综合判断可放其计划/证据表，论文关联不必填 |
| 跨任务盘点与迁移 | `_maintenance/workbench_alignment/`，任务分别提交自己的清单，协调任务汇总决定 |

新实验的目录名描述研究问题或设计，不要求携带论文名称。多个论文引用同一实验时复用原目录和 ID；既有实验新增 seed、重试或独立评估时增加 Run。未关联论文的实验通过项目范围 context/search 或网页“全部实验”读取。

现有目录兼容读取，不为改名而重建 ID。已运行内容、历史报告和旧引用保持版本可追溯。支持/反对关系由明确的记录与证据建立，不由目录名称推断。

## 写入方式

元数据与 Markdown 通过 `researchctl record` 使用当前 SHA256 修订号保存；新文件用 `new`，冲突后重新读取合并。普通代码改动按原工作方式保存。`project/structure.json` 由索引生成，停止使用 `project/refresh_active_studies.py` 等旧逻辑手工改写总目录；该旧入口将转接到新同步服务。

新运行接入 `runner.py`，由实际执行端保存命令、工作目录、解释器/环境、输入、快照、状态、日志和产物。已在运行的任务不为补格式而中断。历史缺口保持未知，不能从文件存在反推运行成功。

源文件已有问题、结论、限制或计划时，直接引用对应段落，避免复制出多个可能分叉的结论版本。实验执行与科学审查按实验自身保存的协议、版本和评价范围读取；论文引用时记录适用范围和限制，不改写原实验事实。一篇论文的计划不会自动成为共享实验或另一篇论文的约束。

## 迁移

各任务返回本地/远端目录、主副本、写入状态、引用和风险。协调任务按清单决定“保留原位并登记”“复制归档后核对”“移动并保留兼容入口”或“待运行结束再处理”。需要移动时先固定源和目标、核对文件与引用、保存迁移日志；不能因整理目录覆盖已有产物或混合不同运行结果。

新产物使用真实的规范目录。根目录兼容链接已撤除；历史来源与可恢复清单保存在 `_maintenance/physical_layout_20260915/`。被运行使用或无法确认状态的目录保持原位，并在迁移决策中写明原因。工作台持续发现新文件，不要求用户补表或审批科研节点。

## 本机磁盘层级（2026-09-15 更新）

```text
experiments/<实验>/
  study.json
  README.md / REPORT.md
  scripts/                      实验专用脚本
  runs/<运行名或 Run ID>/
    run.json                    本次实际执行记录
    stdout.log / stderr.log
    snapshots/                  已冻结的代码与配置
    ...                         本次结果、图表与产物
```

该层级是实际存储位置。论文通过 Study/Run ID 引用证据，不复制出论文专属实验。已有 Run 的内部文件名和布局保留原文，新记录按规范增加。

已复制归位的历史来源仍保留，其索引只采用登记的当前副本；Run ID、文件身份和旧版本可追溯。历史未知执行字段仍为未知。根目录不再创建 runs、diagnostics、Ultralytics 等链接。
